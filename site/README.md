# qxide.dev (`site/`)

Website for `qxide.dev` in the `qxide` repository.

**Status:** Live site for the `.qx` language and the `qxide` CLI (v0.6.0).

## Stack

- **Framework & build:** Vite 8 + React 19 + TypeScript
- **Design system & styling:** Astryx (`@astryxdesign/core`, `theme-neutral` `0.7.16`, pre-built CSS, no build plugin) and `@stylexjs/stylex`
- **Runtime:** Node 22+

## Commands

Run all commands inside `site/`:

- `npm install` — Install dependencies
- `npm run dev` — Start the Vite dev server (`http://localhost:5173`)
- `npm run build` — Run `build:wasm`, then `tsc --noEmit`, then `vite build` (output directory: `dist/`)
- `npm run build:wasm` — Build `crates/qxide-wasm` with `cargo` for `wasm32-unknown-unknown` (cargo profile `wasm`), copy it to `src/playground/generated/qxide.wasm`, and print its size; `npm run dev` and `npm run build` run it first
- `npm run test:parity` — Build the wasm module and the release `qxide` binary and check that every `examples/qx` program and a set of error cases give byte-identical stdout, stderr, and exit codes in both
- `npm run preview` — Serve `dist/` locally
- `npm run astryx -- <cmd>` — Run the Astryx CLI (e.g., `component Button`, `template --list`, `doctor --built dist`)

## Playground engine

The `/playground` page runs the `qxide` `.qx` interpreter compiled to WebAssembly in a Web Worker. Building it needs Rust (`cargo`) plus the `wasm32-unknown-unknown` target, installed once with `rustup target add wasm32-unknown-unknown`. The generated module is git-ignored; because the Pages project is deployed by direct upload, the machine that runs `npm run build` needs that toolchain, and a Git-connected Cloudflare build image would need it too. The module is about 260 KB (about 100 KB gzip), far below the 25 MiB per-file limit of Cloudflare Pages. Browser limits (20 state-vector qubits, 100,000 shots, 30 s per run) are defined in `crates/qxide-wasm/src/lib.rs` and `src/playground/client.ts`.

## Deploy to Cloudflare Pages

Static site plus one Pages Function (`functions/_middleware.ts`); no secrets needed. The middleware answers `https://qxide.dev/<path>` with a 301 to `https://www.qxide.dev/<path>` (query kept). It only acts when the host is exactly `qxide.dev`, and it skips `/install.sh` and `/install.ps1`, which fall through to `public/_redirects` (302 to the latest GitHub release). `qxide.pages.dev` and preview URLs are untouched.

- **Root directory:** `site`
- **Build command:** `npm run build`
- **Build output directory:** `dist`
- **Node version:** Set the `NODE_VERSION` environment variable to `22` (or newer)

The Git-connected build deploys `functions/` automatically. For a manual deploy, run this inside `site/`:

```sh
npm run build
npx wrangler pages deploy dist
```

`wrangler pages deploy dist` looks for `functions/` in the current directory (not inside `dist/`), so it must be run from `site/`; the folder is then bundled and uploaded together with `dist`. Both the apex and `www` hostnames must be custom domains of the Pages project for the redirect to be reachable.

To check the redirect locally, serve the build and override the `Host` header:

```sh
npx wrangler pages dev dist --port 8788
curl -sI -H "Host: qxide.dev" "http://localhost:8788/learn?x=1"            # 301 -> https://www.qxide.dev/learn?x=1
curl -sI -H "Host: qxide.dev" "http://localhost:8788/install.sh"           # 302 -> GitHub release installer
curl -sI -H "Host: qxide.pages.dev" "http://localhost:8788/learn"          # 200, untouched
```
