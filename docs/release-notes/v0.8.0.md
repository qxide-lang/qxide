# qxide v0.8.0

`qxide v0.8.0` builds on `v0.7.0` by adding a typed IR engine (`--engine ir`), an optional Cranelift JIT (`jit` feature, `--engine jit`), and IBM Quantum submission (`qxide run --backend ibm:<device>`, with `--dry-run`; tested only against a local fake server), while keeping `ast` as the default engine. It also adds the `String` type and `std` standard library, desktop apps and Qxide Studio, and editor support through the `qxide lsp` language server and a VS Code extension. Runtime and registry changes introduce a random default seed, execution budgets (`Q0413`–`Q0418`), registry package owners, and security hardening of the package client and registry template. For Rust library users, the public library API is unchanged since `0.7.0`; `lsp-server` joins the default `cli` feature's dependencies and the new optional `jit` feature pulls in Cranelift 0.138, so `default-features = false` still builds the library with no dependencies.

## Breaking changes

- **New `.qx` type name (`String`)**: `String` is now a `.qx` type name and can no longer be used as a variable or function name.
- **Reserved package name `std`**: `std` is reserved for the standard library and rejected by `qxide new`, `qxide.toml` validation, and the registry validator; `qxide new std` names the package `std-app`.
- **String literals as values (`Q0204` / `Q0214`)**: String literals are now values, so `int s = "hi";` reports a type mismatch (`Q0204`) instead of `Q0214`, and `Q0214` now reports `{}` placeholders outside `println`'s format string.
- **Execution budgets (`Q0413`–`Q0418`)**: Programs exceeding the new execution budgets now stop with errors instead of continuing or running out of memory: step limits (`Q0413`: 2^30 for the `qxide` command, 2^26 in the browser playground, 2^31 per desktop app call; `String` text costs 8 steps per byte), circuit operation limits (`Q0414`: 2^24 / 2^20 / 2^22), output size limits (`Q0415`: 256 MiB / 1 MiB / 32 MiB), measured-bit `if` nesting depth across function calls (`Q0416`: 64 levels, 128 in desktop apps), estimated simulation work (`Q0417`: about three minutes for `qxide`, a few seconds in the playground), and error report caps (`Q0418`: 50 errors with 120-character echoed source lines, or 100 errors / 240 characters in desktop apps).
- **Relative path dependencies only**: `path` dependencies in `qxide.toml` and `path+` sources in `qxide.lock` must now be relative. Values that start with `/` or `\` or contain `:` are rejected; relative paths, including `..`, keep working.

## New features

- **Typed IR engine (`--engine ir`) and Cranelift JIT (`--engine jit`)**: Added `--engine ast|ir` (defaulting to `QXIDE_ENGINE` or `ast`) to `qxide run`, `qxide qasm`, and `qxide repl`, lowering checked programs to a typed IR (`docs/design/qx-ir.md`) with matching output, OpenQASM, seeded measurements, diagnostics, and limit behaviour. Enabling the optional `jit` Cargo feature (off by default; Cranelift 0.138; builds without it reject `jit` with exit code 2) compiles build-time classical functions using only `int`, `double`, and `boolean` values to native code on first call and runs everything else in the typed IR interpreter (`docs/design/qx-jit.md`); the browser playground and desktop app runtime omit the JIT. Added a benchmark suite in `bench/qx/` (`cargo test --release --bin qxide bench_suite -- --ignored --nocapture`, documented in `docs/perf/QX_BENCHMARKS.md`).
- **Quantum computer submission (`qxide run --backend ibm:<device>`)**: Added QPU submission to IBM Quantum via the Qiskit Runtime REST API, lowering elaborated circuits to target basis gates and coupled physical qubits and formatting returned measurements like `--shots`. Reads `QXIDE_IBM_API_KEY` (or the OS credential store, read-only) and `QXIDE_IBM_INSTANCE` via system `curl` stdin config so secrets never appear in process arguments; real runs require terminal confirmation (or `--yes`) and cap QPU time with `--max-seconds` (default 120), while `--dry-run` (with optional `--device-config`) inspects requests and ISA circuits offline. Tested only against a local fake server (`docs/design/qx-qpu.md`); CI also validates OpenQASM 3 output and offline IBM device ISA circuits.
- **`String` type and standard library (`std`)**: Added immutable build-time `String` values supporting `+` concatenation with numbers and booleans, `==`, `!=`, `len(s)`, printing, parameters, returns, `final`, and `var`. Added `std.log`, `std.time`, `std.fs`, `std.http`, `std.app`, and `std.qxide` (`import std.fs;`, `import std.fs.read_text;`, `import std.fs.*;`; error codes `Q0701`–`Q0708`), evaluated once during elaboration under host permissions: `qxide run` allows `std.log`, `std.time`, and `std.fs` with `--allow fs` (under `data/` next to `qxide.toml`, or `./data`), `qxide qasm` refuses file and window effects, and the REPL and browser playground allow only `std.log`. In desktop apps, `std.http` provides `http.get(url)` returning a UTF-8 `String` (up to 16 MiB, 30-second timeout, `https://` on port 443 without user info, no redirects, via system `curl`, requiring the `http` permission and exact lowercase hosts in `[app] http_hosts`; `Q0707`/`Q0708`; disallowed in dependency packages).
- **Desktop apps and Qxide Studio**: Added `qxide app new <NAME>`, `qxide app dev`, `qxide app build` (bundling `.qx` sources, locked packages, and `ui/` onto the prebuilt `qxide-app` runtime in `target/app/` without compiling), app error codes `Q0711`–`Q0715`, `qxide check` verification of `[app] permissions`, and `examples/apps/bell-app` (`docs/design/qx-app.md`). The `crates/qxide-app-runtime` webview runtime (`wry`/`tao`) enforces a strict Content-Security-Policy, restricts calls to the app's own origin and `[app] commands`, and runs calls on cancellable worker threads; it is built separately (`cargo build --release --manifest-path crates/qxide-app-runtime/Cargo.toml`) and is not yet in release archives or PyPI wheels. Added Qxide Studio (`apps/studio`), a minimal `.qx` desktop IDE using `std.qxide` (`check`, `run`, `qasm`, `format` returning JSON under the `qxide` permission) with highlighting, error markers, Run/Stop/Check/Format, QASM view, distribution chart, Problems list, `examples/qx` programs, and autosave.
- **Language server (`qxide lsp`) and VS Code extension**: Added `qxide lsp` (stdio LSP server with optional `--stdio`; `docs/design/lsp.md`), providing `qxide check` diagnostics (UTF-16 columns, cross-module errors, live unsaved edits), `qxide fmt` formatting, hover (`qxide explain` entries and declarations), document symbols, cross-module go to definition, and completions (keywords, types, built-ins, `PI`, functions, locals, `BitReg` methods). Added the `editors/vscode/` extension (version `0.1.0`, publisher `qxide-lang`, requiring VS Code 1.91+ and `qxide` 0.8.0+) with TextMate highlighting, `qxide.path`, `qxide.trace.server`, and `Qxide: Restart Language Server`, packaged via `vsce` as `qxide-vscode-<version>.vsix` and published by `.github/workflows/vscode.yml` to GitHub Releases, Visual Studio Marketplace (`VSCE_PAT` or `VSCE_TRUSTED_PUBLISHING`), and Open VSX (`OVSX_PAT`), skipping targets with missing credentials or already-published versions (`docs/vscode-extension.md`).
- **Registry package owners**: Registry ownership is now recorded in `owners/<prefix>/<name>` (one JSON line per GitHub account with `id` and `login`). Registry CI requires pull requests modifying a package's index file, archives, or owner file to be opened by a listed base-branch owner (new packages must list only the pull request author); owners may yank versions (setting `yanked` back to false stays with registry maintainers) and invite new owners via `"pending": true` for acceptance in their own pull request. `qxide publish` now writes the owner file for a package's first version using `gh api user` (with `qxide` 0.7.0, it must be added by hand).

## Changes

- **Random default seed**: Running `qxide run` or `qxide repl` without `--seed` now uses OS entropy (via `std` only) instead of defaulting to `0`, printing `seed: S (pass --seed S to reproduce)` to `stderr` only when output depends on simulated measurements (once in `qxide repl` on the first measured-bit output). Explicit `--seed S` stays deterministic with no `stderr` line, `qxide bell` still uses seed `0`, and scripts relying on implicit seed `0` must pass `--seed 0`. In the browser playground, the Seed field is now empty by default, draws a random `u64` via `crypto.getRandomValues`, shows the seed used, and stores it in Copy link.
- **Checker performance**: `qxide check` now computes which functions may run inside an `if` on a measured bit (`Q0314`) in near-linear time, reducing a file with 32,000 chained functions from 42 s to 0.08 s.

## Fixes

- **Interpreter stack**: `run`, `check`, and `qasm` now run on a 256 MiB thread stack (up from 64 MiB) and the interpreter uses smaller stack frames, so the deepest programs the nesting limits allow no longer overflow the stack in unoptimized (debug) builds.
- **Package client hardening**: Package archives are unpacked with stricter header and size checks, archive locations from the index or the registry configuration must be `https` URLs or relative paths inside the registry (`Q0609`), installed packages are checked against the locked archive on every run, `curl`, `gh`, and `git` are looked up on `PATH` only, and control characters in package messages, `qxide search` rows, and diagnostics are shown escaped.
- **Registry template hardening**: The registry template's CI validates the merge result of each pull request with the scripts of the base branch, rejects deleted index files, malformed or oversized input, look-alike and reserved package names, and manifests whose dependencies differ from the index. Registries created from the template need its updated workflow and scripts.

## Rust library

- **Public API**: The public Rust library API is unchanged since `0.7.0`.
- **Feature dependencies**: `lsp-server` joins the default `cli` feature's dependencies and the new optional `jit` feature (off by default) pulls in Cranelift 0.138, so `default-features = false` still builds the library with no dependencies.

## Install

All installation methods below install the same `qxide` CLI binary.

Prebuilt binaries from GitHub Releases via the `qxide.dev` install script:

```sh
# Linux / macOS
curl --proto '=https' --tlsv1.2 -LsSf https://qxide.dev/install.sh | sh
```

```powershell
# Windows (PowerShell)
powershell -ExecutionPolicy Bypass -c "irm https://qxide.dev/install.ps1 | iex"
```

From PyPI (bundles the same CLI binary):

```sh
pip install qxide
```

The `jit` engine is not in the prebuilt binaries; build it with `cargo install qxide --features jit` once 0.8.0 is on crates.io, or from a checkout with `cargo install --path . --features jit`.

The VS Code extension is attached to the GitHub release as `qxide-vscode-0.1.0.vsix`: `code --install-extension qxide-vscode-0.1.0.vsix`.
