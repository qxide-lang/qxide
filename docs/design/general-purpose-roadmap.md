# Qxide 범용 언어 갭 분석과 로드맵

## 1. 목적과 범위

2026-11-22 사용자 요청에 따라 Qxide를 Rust, C, Java처럼 다양한 영역에서 사용할 수 있는 범용 언어로 확장하기 위한 갭 분석과 단계별 로드맵을 정리한다.

다음 제약은 고정된 전제로 유지한다.

- Java/C 스타일 문법: 이름 앞에 타입을 표기한다(`int x = 1;`, `Qubit q = qubit();`, 함수 이름 앞 반환 타입).
- 컴파일러의 Rust 스타일 안전성 검사 및 Rust 수준 성능 목표.
- 영문 컴파일러 진단 메시지.
- 큐비트 규칙: 측정하거나 폐기하지 않은 큐비트는 오류이며, 소유권 이동은 `consume`으로만 일어난다.
- `var`, `(int) x` 캐스트, CLI 명령(`qxide run`, `qxide check`, `qxide qasm`).
- 정체성: 고전과 양자를 아우르는 단일 언어. 고전 기능 추가가 기존 양자 기능을 깨뜨려서는 안 된다.
- 장기 목표: 우주 시뮬레이션 같은 대규모 계산 수행.

아래 모든 항목은 커밋 `3580518` (v0.8.0) 기준 코드로 확인했으며, 각 항목의 근거는 파일 경로로 명시한다.

## 2. 현재 실행 모델

현재 실행 모델이 언어 전반의 제약과 확장 방향을 결정하므로 갭 분석에 앞서 이를 정리한다.

- **Staged 실행 모델**: `.qx` 프로그램은 단계적으로 실행된다(`docs/design/qx-language.md` §5). 고전 코드(`int`, `double`, `boolean`, `String`)는 빌드 타임에 elaborator 내부에서 `main`을 실행하며 단 한 번 수행되어 하나의 `qxide::Circuit`을 기록한다. `Bit`와 `BitReg`는 시뮬레이션 단계에서 채워지는 shot-time 값이다.
- **버퍼링된 출력**: `println`은 stdout에 즉시 쓰지 않고 출력 템플릿에 덧붙인다(`src/lang/machine.rs` `Machine::print`). 이 템플릿은 elaboration과 시뮬레이션이 모두 끝난 뒤 shot당 한 번 렌더링된다. 따라서 장시간 고전 계산 중에는 종료 전까지 출력이 표시되지 않으며 스트리밍 출력이 불가능하다.
- **리소스 제한**: `src/lang/mod.rs`의 `Limits::CLI`는 인터프리터 스텝 2^30, 회로 연산 2^24, 출력 256 MiB 등의 상한을 적용한다(`docs/design/qx-language.md` §18). 이를 상향하는 CLI 플래그는 없다. 신뢰할 수 없는 파일로부터 보호하는 보안 장치이지만, 약 10^9 스텝 규모의 정당한 대규모 계산도 함께 가로막는다.
- **세 가지 elaborator**: `src/lang/engine.rs`는 동일한 결과를 내는 세 엔진을 제공한다.
  - `ast`: 트리 순회 인터프리터(기본값).
  - `ir`: typed-IR 인터프리터(`src/lang/ir/`).
  - `jit`: IR + Cranelift 네이티브 코드(Cargo feature `jit`, 기본 비활성, `src/lang/jit/`).
  - `cargo test`에서는 `dual` 엔진이 기본값으로 동작하며 모든 엔진을 실행해 결과를 비교한다.
- **JIT 지원 범위**: `src/lang/jit/mod.rs`의 `supported` 조건에 따라, 모든 값이 `int`/`double`/`boolean`이고 동일 조건의 함수만 호출하는 함수만 JIT 컴파일된다. 문자열, `std` 호출, 양자 연산은 지원하지 않는다.

`docs/perf/QX_BENCHMARKS.md`에 기록된 실측치(최소 elaboration 시간, ms)는 다음과 같다.

| 벤치마크 | `ast` (ms) | `ir` (ms) | `jit` (ms) |
| --- | ---: | ---: | ---: |
| `arith` | 813.2 | 542.9 | 83.7 |
| `recursion` | 179.1 | 56.9 | 5.4 |

### 3.6 쓰임새별 평가

| 쓰임새 | 지금 가능한가 | 막는 갭 |
| --- | --- | --- |
| CLI 도구 | 불가 | 커맨드라인 인자, stdin, 종료 코드, 스트리밍 출력 부재 |

| 웹 (WASM) | 플레이그라운드만 가능 | 브라우저 플레이그라운드 실행만 지원하며 `.qx`의 WASM 컴파일 불가 |
| 과학 계산 / 시뮬레이션 | 부분 가능 | 순수 숫자 함수는 JIT 가능하나 배열, 수학 함수, `while`, 병렬성 부재 및 스텝 제한 |
| 임베디드 | 장기 과제 | AOT 컴파일 및 런타임 할당 비의존 구조 필요 |

## 4. 설계 결정

아래 항목은 권장안이며 사용자가 변경할 수 있다. 추후 되돌리기 어려운 결정은 `[되돌리기 어려움]`으로 표시한다. 각 결정의 구현 현황은 6절을 참조한다.

- **D1 루프와 복합 대입**: `while cond { ... }`, `break;`, `continue;`를 기존 `if`/`for`와 동일한 괄호 없는 헤더 스타일로 도입한다(`(cond)`는 식이므로 괄호 사용도 허용된다). 변수에 대해 복합 대입 `+=`, `-=`, `*=`, `/=`, `%=`를 추가한다. `++`/`--`는 문(statement)과 식(expression) 간 모호성 때문에 당장 넣지 않으며 추후 추가할 수 있다. `loop`와 `do-while`은 추가하지 않는다.
- **D2 오류 처리 `[되돌리기 어려움]`**: 예외(exception)가 아니라 `Result` 스타일 값과 명시적 전파를 채택한다. 예외는 살아 있는 큐비트를 보유한 프레임을 되감기(unwind)하므로 선형 큐비트 검사기가 모든 throw 경로를 추적해야 한다. 반면 명시적 조기 반환은 이미 검사되고 있으며(살아 있는 큐비트가 있을 때 `return` 시 `Q0302`), Rust 스타일의 명시적 오류 모델이면서도 Java/C 사용자에게 읽기 쉽다. 1f에서는 모든 파일에서 `import` 없이 사용할 수 있는 프렐류드 제네릭 열거형 `Result<T, E>`(`Ok(T value)`/`Err(E error)`)와 `Option<T>`(`None`/`Some(T value)`), 그리고 후위 전파 연산자 `?`를 구현했다. `?`는 `Err`/`None`을 함수의 반환 타입으로 다시 감싸 조기 반환하되 오류 타입이 정확히 일치해야 하며(자동 변환 없음), `return`과 동일한 큐비트 규칙(`Q0302`, `Q0308`)을 따르고 잘못된 사용은 `Q0231`로 진단된다. `String.try_parse_int()`/`try_parse_double()`도 `Result`를 반환한다(세부 사항은 `qx-language.md` 19.7절 참조).
- **D3 복합 데이터 범위**: 1단계에서는 빌드 타임 고전 값만 허용한다. 배열과 구조체 안에 `Qubit`/`Bit`를 넣지 않으며 `QReg`/`BitReg`가 양자 컬렉션 역할을 유지한다. 이로써 기존 큐비트 검사기를 변경하지 않는다.
- **D4 순수 수학 및 문자열 함수 배치**: 수학 함수는 `std` 모듈(`import std.math;` 후 `math.sqrt(x)`)에 두고, 문자열 함수는 `std` 모듈이 아니라 `String` 값의 메서드(`s.trim()`, `s.substring(0, 3)`)로 제공하며, 둘 다 새 전역 이름을 추가하지 않는다. 사용자 함수는 내장 함수 이름을 재사용할 수 없으므로(`src/lang/check.rs` `signatures`, `Q0217`) 새 전역 내장 함수를 추가하면 기존 프로그램이 깨진다. 이 함수들은 순수 함수로 권한이 필요 없으며 모든 호스트에서 허용된다.
- **D5 배열 `[되돌리기 어려움]`**: Java 문법을 따른다(`int[] a = new int[n];`, `new int[]{1, 2, 3}`, 선언 초기화 `int[] a = {1, 2, 3};`, 원소 읽기/쓰기 `a[i]`, `a[i] = v;`, 길이 `len(a)`). 권장안은 Java와 같은 참조 의미론(reference semantics)이며, 대안은 C/Rust와 같은 값 의미론(value semantics)이다. `new`는 키워드가 아닌 문맥적 단어(타입 이름이 뒤따를 때만 배열을 생성)이므로 `new`를 식별자로 사용하는 기존 프로그램도 계속 동작한다.
- **D6 구조체 `[되돌리기 어려움]`**: 이미 예약어인 C 키워드 `struct`로 선언하고(`struct Point { double x; double y; }`), Java 스타일의 `new Point(1.0, 2.0)`으로 생성하며, `p.x`, `p.x = 2.0;`으로 필드에 접근한다. `null`은 도입하지 않는다. 구조체는 배열과 마찬가지로 참조 의미론(Java 의미론)을 따르며 `new`는 계속 문맥적 단어로 유지된다. 이번 버전에서는 구조체가 직접 또는 배열·열거형을 통해 자기 자신을 포함할 수 없다(호출당 메모리 상한을 유지하기 위한 제한이며, 리스트·트리는 재귀 열거형(D8)으로 작성한다).
- **D7 신뢰할 수 있는 로컬 코드의 리소스 제한 `[보안 관련 결정]`**: `Limits::CLI` 기본값은 유지한다. 2026-11-23 결정에 따라 실행 예산만 높이는 명령줄 전용 opt-in 플래그 `--trusted`(`qxide run`, `qxide qasm`)를 추가했다(7절, `qx-language.md` 19.13절).
- **D8 열거형과 `match` `[되돌리기 어려움]`**: 페이로드를 갖는 열거형(Rust 스타일 태그드 유니언, Java식 문법)을 `enum Shape { Circle(double r), Rect(double w, double h), Empty }`로 선언하고 `Shape.Circle(2.0)`·`Shape.Empty`로 생성한다. `enum`과 `match`는 이미 예약어였으므로 키워드로 승격해도 기존 프로그램이 깨지지 않는다. 열거형 값은 구조체·배열과 달리 불변(immutable)이며 고전 값만 담는다(D3). `null`이 없으므로 첫 번째 배리언트가 기본값(배열 원소, 구조체 필드)이 되며, 따라서 첫 번째 배리언트는 자기 열거형 타입을 포함할 수 없다. 나머지 배리언트는 직접 재귀를 허용해 리스트·트리를 표현할 수 있으나, 배열이나 구조체를 경유한 재귀는 가변 참조로 자기 자신을 가리키는 순환 참조(해제되지 않아 데스크톱 앱과 REPL의 호출당 메모리 상한을 무력화함)를 만들 수 있으므로 거부한다. `match`는 식이 아닌 문(statement)이며 모든 경우를 망라(exhaustive)해야 하고, 각 분기는 블록으로 작성하며 배리언트 바인딩·`int`/`String`/`boolean` 리터럴·`_` 패턴을 지원한다(큐비트 검사기는 각 분기를 `if`/`else` 분기와 동일하게 검사한다). 열거형의 `==` 비교·출력 지원 및 식 형태 `match` 도입 여부는 사용자 결정 사항으로 둔다.

### Stage 1 — 언어 핵심과 순수 라이브러리

이 브랜치에서 순차적으로 구현을 시작한다.

- **1a `while`/`break`/`continue` + 복합 대입**
  - 내용: `while`, `break`, `continue`와 복합 대입 연산자(`+=`, `-=`, `*=`, `/=`, `%=`) 추가.
  - 완료 기준: 세 엔진(`ast`, `ir`, `jit`) 모두 지원. 검사기가 루프 탈출 시 큐비트 규칙을 강제(`break`/`continue`를 통한 큐비트 누수 금지, `for`와 동일하게 루프 본문에서 외부 큐비트 소비 금지 `Q0305`, 측정된 `Bit` 조건의 `if`를 `break`/`continue`로 벗어나는 것 금지). 포매터, LSP, VS Code 문법이 새 키워드를 인식.
  - 테스트 기준: 파서/검사기 단위 테스트, dual-engine 실행 테스트, 스텝 예산 동등성 검증, 예제 프로그램.
- **1b `std.math` 및 문자열 함수 (순수 함수, 모든 호스트)**
  - 내용: 순수 수학 함수는 표준 모듈 `std.math`로, 문자열 조작 함수는 `String` 값의 메서드로 구현.
  - 완료 기준: 모든 엔진에서 동일한 결과와 스텝 과금으로 동작. 권한 없이 모든 호스트에서 사용 가능.
  - 테스트 기준: NaN, 음수 `sqrt`, 범위 밖 substring의 진단 오류 등 경계 사례를 포함한 dual-engine 테스트.
- **1c 고전 타입 배열**
  - 내용: D3 및 D5에 따른 고전 타입 배열 구현.
  - 완료 기준: 배열 할당 시 스텝 예산을 차감(`new double[huge]` 등에서 OOM 중단 방지), 범위 밖 인덱스는 진단 오류로 처리, 모든 엔진 결과 일치.
  - 테스트 기준: dual-engine 테스트, 리소스 제한 테스트.
- **1d 구조체 (`struct`)**
  - 내용: D3 및 D6에 따른 고전 필드 구조체 선언, 생성, 필드 접근 구현.
  - 완료 기준: 모든 엔진에서 동일 동작, 타입 검사 및 진단 지원.
  - 테스트 기준: 파서/검사기 단위 테스트, dual-engine 테스트.
- **1e 열거형(`enum`) + `match`**
  - 내용: `enum` 선언 및 `match` 패턴 매칭 구현.
  - 완료 기준: 모든 엔진에서 동일 동작, 정적 검사 지원.
  - 테스트 기준: 파서/검사기 단위 테스트, dual-engine 테스트.
- **1f `Result<T, E>` 오류 처리 (D2)**
  - 내용: D2에 따른 일반 제네릭 열거형 `Result<T, E>`(1g 필요, `Ok(T value)`/`Err(E error)` 배리언트)와 `match` + 조기 `return`의 문법 설탕인 `?` 전파 연산자 구현.
  - 완료 기준: 모든 엔진에서 동일 동작, 오류 전파 경로에서 선형 큐비트 규칙 준수(살아 있는 큐비트가 있을 때 조기 반환하는 `?`는 `return`과 동일하게 `Q0302` 오류).
  - 테스트 기준: 파서/검사기(큐비트 안전성 포함) 단위 테스트, dual-engine 테스트.
- **1g 제네릭**
  - 내용: 제네릭 구조체·열거형·함수(`struct Pair<A, B>`, `enum Option<T>`, `T max<T>(T a, T b)`)를 검사 시점에 단형화(monomorphization)하여 각 인스턴스화가 구체 타입·함수가 되도록 구현(세 엔진과 JIT는 구체 코드만 실행). 타입 인자는 호출 인자에서 추론하거나 타입에 직접 표기하며(`Option<int>.None`), `Name<`은 `Name`이 선언된 제네릭 타입일 때만 타입으로 파싱해 `a < b`가 비교 연산으로 유지되도록 한다.
  - 완료 기준: 모든 엔진에서 동일한 결과 반환, 인스턴스화 오류는 사용 위치를 가리킴.
  - 테스트 기준: 파서/검사기 단위 테스트, dual-engine 테스트, 인스턴스화 횟수 상한 테스트.
- **1h 메서드와 인터페이스(`interface`)**
  - 내용: 구조체·열거형 메서드(수신자 `this`), Java 스타일 `interface` 선언, 제네릭 함수 타입 매개변수당 단일 인터페이스 제약(bound, 단형화를 통한 정적 디스패치), 값으로 쓰이는 인터페이스 타입(실행 시점 타입 기반 동적 디스패치) 구현. `interface`/`implements`/`extends`/`this`는 문맥적으로 처리해 기존 식별자 이름이 계속 동작하도록 한다.
  - 완료 기준: 제네릭 코드의 제약 메서드 호출과 인터페이스 값의 동적 디스패치가 모든 엔진에서 동일한 결과와 스텝 과금으로 동작하며, 큐비트 규칙과 측정 비트 `if` 규칙이 메서드 호출에도 적용되고 인터페이스를 통한 순환 참조가 허용되지 않음.
  - 테스트 기준: 파서/검사기 단위 테스트(구현 적합성, 제약, 재귀), 스텝 한도 스윕을 포함한 dual-engine 테스트, 모듈·REPL·LSP·포매터 테스트.

구현 순서는 1e → 1g → 1f → 1h로 진행한다(`Result`가 제네릭 열거형이며, 인터페이스는 앞선 단계에서 필요하지 않기 때문이다).

### Stage 2 — 표준 라이브러리 기초

- **2a 프로세스 입출력**
  - 내용: `main` 커맨드라인 인자(`String[] args`), `int main()` 종료 코드, `std.io`(`write`/`writeLine`/`readLine`/`readAll`), `std.env.get`, `std.time.monotonicMillis` 추가.
  - 완료 기준: `.qx`로 작성한 단어 수 세기 CLI 도구(`examples/cli/wc.qx`)가 표준 입력을 읽고 집계 결과를 즉시 출력하며 오류 시 0이 아닌 종료 코드로 종료한다.
  - 테스트 기준: CLI 통합 테스트(인자, 종료 코드, stdin, 환경 변수, 출력 순서), 호스트별 권한 테스트, 스크립트된 호스트를 사용한 dual-engine 테스트.
- **2b 기초 데이터 도구**
  - 내용: `String` 메서드(`split(sep)` — 빈 조각 유지·빈 구분자는 `Q0706`인 Rust 의미론, `splitWhitespace()`, `lines()`, `chars()`, `sep.join(parts)`), `int` 비트·시프트 연산자(`&`, `|`, `^`, `~`, `<<`, `>>`, `>>>`) 및 복합 대입(비교보다 높은 Rust 우선순위, `0..=63` 범위 밖 시프트는 런타임 오류 `Q0420`)과 `std.math`의 `wrappingAdd`/`wrappingSub`/`wrappingMul`, 모든 엔진과 호스트에서 동일하게 동작하는 시드 기반 순수 결정적 내장 PRNG 타입 `Random`(`new Random(seed)`, `nextInt(bound)`, `nextDouble()`, `nextBoolean()`, SplitMix64), 런타임에 네이티브로 구현되어 `import` 없이 모든 파일에서 사용할 수 있는 고전 전용 내장 제네릭 컬렉션 `List<T>`/`Map<K, V>`(삽입 순서 유지, `int`/`String`/`boolean` 키, 프로그램이 선언한 동명 타입 우선), 배열·`List` 순회용 `for x in xs` 루프, 표준 오류 출력 `std.io.write_err`/`writeErrLine` 추가.
  - 완료 기준: 텍스트를 토큰화하고 `Map`으로 단어 빈도를 집계하는 프로그램을 작성할 수 있으며, 모든 엔진에서 동일한 결과와 스텝 과금으로 동작한다.
  - 테스트 기준: dual-engine 실행 테스트, `examples/qx/collections.qx`의 `ast`/`ir` 스텝 한도 스윕, 비트 연산자 JIT 네이티브 코드 테스트, PRNG 재현성 테스트, 오류 테스트, `-f` 단어 빈도 옵션을 사용한 `examples/cli/wc.qx` CLI 테스트.
- **2c 파일과 데이터 형식**
  - 내용: 경로 처리 모듈(`std.path`), `std.fs` 확장(명시적 권한 아래 커맨드라인으로 지정한 파일 읽기, 디렉터리 목록 조회), JSON 파싱·직렬화 추가.
  - 완료 기준: `qxide run wc.qx --allow fs -- file.txt` 형태의 CLI 도구가 인자로 전달된 파일을 읽을 수 있고, JSON 파싱·직렬화가 왕복(round-trip)으로 일치한다.
  - 테스트 기준: CLI 통합 테스트, 권한 테스트, JSON 적합성 테스트 사례.

### Stage 3 — 실행 방식

- **3a `qxide build` 번들 실행 파일**
  - 내용: 실행 중인 `qxide` 바이너리 사본 끝에 검사 완료된 프로그램(소스, 패키지 정보, 실행 옵션, 32바이트 트레일러)을 덧붙여 단일 실행 파일을 생성하는 `qxide build` 구현(네이티브 컴파일이 아닌 인터프리터 번들 방식, `docs/design/qx-build.md`).
  - 완료 기준: `qxide build app.qx -o app.exe`로 생성한 실행 파일이 `qxide` CLI, 원본 소스 파일, 패키지 캐시 없이 실행된다.
  - 테스트 기준: CLI 통합 테스트(원본 소스를 삭제한 상태에서 다른 디렉터리에서 실행, 인자/표준 입력/종료 코드, 고정 `--seed`/`--shots`, 덮어쓰기 규칙, 손상된 파일 거부), 경로 의존성이 있는 패키지 빌드·실행 테스트, 페이로드 단위 테스트. Windows 로컬에서만 실행했으며 Linux/macOS CI는 추후 검증 대상이다.
- **3b Cranelift AOT 네이티브 컴파일**
  - 내용: 고전 코드를 Cranelift(`cranelift-object`)로 사전 컴파일하고 시스템 링커와 양자용 런타임 라이브러리를 링크해 네이티브 실행 파일을 생성한다(미착수).
  - 완료 기준: 사전 컴파일된 고전 코드와 양자 런타임이 링크된 네이티브 실행 파일이 생성·실행된다.
  - 테스트 기준: Windows/Linux/macOS CI에서 AOT 빌드·링크·실행 테스트 및 기존 엔진과의 결과 동등성 검증.
- **3c JIT 커버리지 확대 및 lowering 캐싱**
  - 내용: 배열·수학·문자열·구조체에 대한 JIT 컴파일 지원 확대와 lowering 결과 캐싱(미착수).
  - 완료 기준: 확장된 고전 기능이 JIT에서 네이티브로 실행되며 `ast`/`ir`과 동일한 결과와 스텝 과금을 유지한다.
  - 테스트 기준: dual-engine 동등성 테스트, 경계·오류 테스트 및 실측 벤치마크 비교.

### Stage 4 — 상호 운용

- **4a 최소 C FFI (`extern`)**
  - 내용: 최상위 `extern "lib" double cos(double x);` 선언. `int`(C `int64_t`)·`double` 매개변수 최대 6개, `int`·`double`·`void` 반환. cargo 기능 `ffi`(기본 꺼짐)와 `--allow ffi` 허가가 모두 있어야 하며, 진입 파일에서만 선언할 수 있다. 플레이그라운드·Studio·REPL·데스크톱 앱에서는 쓸 수 없다. 새 크레이트 의존성 없이 플랫폼 로더(`LoadLibraryExW`/`dlopen`)를 직접 쓴다.
  - 완료 기준: `.qx` 프로그램이 공유 라이브러리의 C 함수를 호출할 수 있다. `qxide build`로 만든 실행 파일도 빌드할 때 받은 허가로 호출할 수 있다.
  - 테스트 기준: 시스템 C 라이브러리(Windows `ucrtbase`, Linux `libm.so.6`·`libc.so.6`, macOS `libSystem.B.dylib`)의 함수를 두 인터프리터와 번들에서 호출하는 테스트. 호스트별·의존성 거부 테스트, 라이브러리·기호 누락 오류 테스트, 타입 검사 테스트. 직접 빌드한 C 라이브러리 테스트는 CI 작업으로 남긴다.
- **4b 공개 Rust 임베딩 API**: `lang`의 검사·실행 API를 안정된 공개 인터페이스로 정리한다.
- **4c Python 바인딩**: 4b 위에서 `.qx` 프로그램을 Python에서 검사·실행한다.

### Stage 5 — 도구

- 내용: `qxide test`(테스트 함수), `qxide doc`, 사용자용 벤치마크 커맨드, 추후 디버거(DAP).
- 완료 기준: 각 CLI 도구 명령이 `.qx` 프로젝트에서 동작한다(DAP는 후속).
- 테스트 기준: CLI 통합 테스트 및 공통 테스트 기준 충족.

### Stage 6 — 대규모 계산

- 내용: 공유 데이터 소유권 모델을 갖춘 데이터 병렬 루프/스레드, SIMD, 고전 GPU 커널, 신뢰할 수 있는 코드의 리소스 제한 상향(D7).
- 완료 기준: N-body 시뮬레이션 예제가 멀티 코어에서 실측 속도 향상을 보이며 확장된다.
- 테스트 기준: 병렬 실행 정확성 테스트 및 멀티 코어 실측 벤치마크.

## 7. 사용자 결정 항목 (결정됨 2026-11-23)

- **D1 (루프와 복합 대입)** — 결정됨(2026-11-23): 구현된 대로 괄호 없는 `while`, `break`/`continue`, 복합 대입(`+=`, `-=`, `*=`, `/=`, `%=` 및 2b의 비트 복합 대입)을 채택하며 `loop`와 `do-while`은 추가하지 않는다.
- **`++`/`--` 연산자** — 결정됨(2026-11-23): 문과 식의 모호성으로 인해 도입을 보류하고 당장 추가하지 않는다.
- **D2 (오류 처리)** — 결정됨(2026-11-23): 예외를 도입하지 않고 `Result<T, E>`와 후위 `?`를 통한 명시적 전파 방식을 유지한다.
- **D5 (배열 의미론)** — 결정됨(2026-11-23): Java 스타일의 참조 의미론을 유지한다. 배열에 참조 의미론과 C/Rust 스타일의 값 의미론 중 무엇을 택할지가 쟁점이었다.
- **배열 길이 접근** — 결정됨(2026-11-23): 현재 동작을 유지해 `len(a)`만 지원하며, Java 스타일의 `a.length`는 추가하지 않는다.
- **D6 (구조체 의미론)** — 결정됨(2026-11-23): 구조체(및 배열)에 Java 스타일의 참조 의미론을 유지하고 `new`는 문맥적 단어로 유지한다. 값 의미론(C/Rust) 전환 여부를 검토했던 항목이다.
- **D7 (리소스 제한 상향 플래그)** — 결정됨(2026-11-23): `Limits::CLI` 기본값은 그대로 두고, 신뢰하는 로컬 코드용 opt-in 플래그 `--trusted`를 `qxide run`과 `qxide qasm`에 추가했다. 실행 예산(스텝 `2^30`→`2^36`, 회로 연산 `2^24`→`2^26`, 시뮬레이션 작업 `2^36`→`2^40`, 출력 `256 MiB`→`1 GiB`)만 높이고, 중첩·조건 깊이와 진단 한도는 `STACK_SIZE`에 맞춘 CLI 값을 유지한다. 명령줄에서만 켤 수 있으며 소스 파일, `qxide.toml`, `qxide build` 번들로는 켤 수 없다(`check`와 `build`는 이 플래그를 거부한다). `qx-language.md` 19.13절 참조.
- **메서드 이름 규칙** — 결정됨(2026-11-23): 0.8.0의 이름(`as_int` -> `asInt`, `to_binary` -> `toBinary`)을 포함한 내장 메서드와 `std` 함수 이름 51개를 Java식 camelCase(`indexOf`, `toUpperCase`, `parseInt`, `length()`, `substring`)로 변경하고, 기존 snake_case 이름은 `Q0801` 경고를 내는 폐기 예정 별칭으로 한 릴리스 동안 유지한다. 전체 대응표는 `docs/design/qx-language.md` 19.12절과 `qxide explain Q0801`에 있다.
- **배열·필드 저장 함수와 측정 비트 `if`** — 결정됨(2026-11-23): 현재의 보수적 규칙(`Q0314`)을 유지한다. 저장 대상이 지역 값인지 분석해 측정 비트 조건 `if` 안의 호출 제한을 완화할지가 쟁점이었다.
- **플랫폼별 부동소수점 결과** — 결정됨(2026-11-23): `libm` 의존성을 추가하지 않고 플랫폼 수학 라이브러리를 사용하는 현재 동작을 유지하며, 플랫폼 간 마지막 자리 차이를 허용한다. 순수 Rust 구현으로 모든 플랫폼의 결과를 일치시킬지가 쟁점이었다.
- **구조체 모듈 범위** — 결정됨(2026-11-23): 구조체 이름을 프로그램 전체에서 고유하게 두고 모듈별 한정 이름을 두지 않는 현재 동작을 유지한다. 함수처럼 모듈별 한정 이름과 `public`/`import`를 지원할지가 쟁점이었다.
- **자기 참조 구조체** — 결정됨(2026-11-23): 자기 참조 구조체를 거부하는 현재 동작을 유지하며, 관련 자료구조에는 재귀 열거형을 사용한다. 가변 참조 구조체에 `Option<Node>` 같은 자기 참조를 허용할지가 쟁점이었다.
- **JIT 범위** — 결정됨(2026-11-23): `std.math`, 문자열 메서드, 배열, 구조체를 사용하는 함수는 IR 인터프리터로 실행하는 현재 동작을 유지하고, JIT 확장은 후속 로드맵 항목(Stage 3c)으로 남겨 둔다. 이를 바로 다음 작업으로 추진할지가 쟁점이었다.
- **D8 (열거형)** — 결정됨(2026-11-23): 불변 열거형과 첫 번째 배리언트를 기본값으로 삼는 규칙을 유지한다. 다른 기본값 규칙으로 변경할지가 쟁점이었다.
- **열거형 비교·출력과 식 `match`** — 결정됨(2026-11-23): 열거형에 `==` 비교와 `println` 출력을 추가하지 않고 `match`도 문(statement)으로만 유지하는 현재 동작을 유지한다.
- **제네릭(1g)** — 결정됨(2026-11-23): 단형화(monomorphization)를 유지하고 호출 위치의 명시적 타입 인자 표기는 추가하지 않으며, 보수적 재귀 검사도 그대로 유지한다. 타입 소거·박싱 전환, 명시적 타입 인자 문법 도입, 재귀 검사 완화 여부가 쟁점이었다.
- **`Result`/`Option` 프렐류드(1f)** — 결정됨(2026-11-23): `Result`와 `Option`을 프렐류드로 유지하고, `?`의 동일 오류 타입 요구(자동 변환 미지원)와 `map`·`and_then` 같은 추가 메서드 미도입 방침을 유지한다. 프렐류드 메서드 이름은 `Result`의 `isOk`·`isErr`·`orElse`와 `Option`의 `isPresent`·`isEmpty`·`orElse`로 변경되었고 기존 이름은 폐기 예정 별칭으로 남는다. `import std.result;` 이동, 오류 자동 변환, 추가 메서드 도입 여부가 쟁점이었다.
- **메서드 문법(1h)** — 결정됨(2026-11-23): 필드는 `this.x`로만 접근하고 정적 메서드, 오버로딩, 자체 타입 매개변수를 갖는 메서드를 허용하지 않는 현재 동작을 유지한다.
- **인터페이스 의미론(1h)** — 결정됨(2026-11-23): 다운캐스트, 인터페이스 값에 대한 `match`, 인터페이스 상속 및 인터페이스 간 변환, 배열 공변성을 모두 지원하지 않는 현재 동작을 유지한다.
- **제약 문법(1h)** — 결정됨(2026-11-23): 제네릭 함수에서만 타입 매개변수당 단일 제약을 지원하는 현재 규칙을 유지한다. 복수 제약과 구조체·열거형의 타입 매개변수 제약 추가 여부가 쟁점이었다.
- **메서드 호출과 측정 비트 `if`(1h)** — 결정됨(2026-11-23): 이름 기준으로 판정하는 현재의 보수적 규칙을 유지한다. 스캔 단계에 타입 정보를 도입해 수신자 타입별로 판정할지가 쟁점이었다.
- **인터페이스와 재귀(1h)** — 결정됨(2026-11-23): 인터페이스 타입 필드를 거쳐 자기 자신에 도달하는 구조체 순환을 `Q0227`로 계속 거부한다. 순환 참조 수집이나 약한 참조를 도입해 이런 순환을 허용할지가 쟁점이었다.
- **비트 연산자 우선순위(2b)** — 결정됨(2026-11-23): `x & 1 == 0`을 `(x & 1) == 0`으로 해석하는 Rust 우선순위를 유지한다. Java/C 우선순위로 전환할지가 쟁점이었다.
- **시프트 범위 검사(2b)** — 결정됨(2026-11-23): `0..=63` 범위를 벗어난 시프트 양에 대해 런타임 오류 `Q0420`을 발생시키는 동작을 유지한다. Java식 마스킹으로 전환할지가 쟁점이었다.
- **`List`/`Map`/`Random` 내장 이름(2b)** — 결정됨(2026-11-23): 모든 파일에 알려진 내장 타입 이름으로 유지하되, 프로그램이 같은 이름의 타입을 선언하면 사용자 타입이 우선하도록 한다. `import std.collections` 요구나 예약어 고정 여부가 쟁점이었다.
- **컬렉션 메모리 스텝 과금(2b)** — 결정됨(2026-11-23): 바이트당 스텝 과금을 유지하며, 더 큰 한도가 필요한 프로그램은 기본 `2^30` 대신 `2^36` 스텝 예산을 부여하는 `qxide run`/`qxide qasm`의 새 선택적 `--trusted` 플래그(D7)를 사용할 수 있다. 원소당 과금 인하와 신뢰 코드 한도 상향 사이에서 결정한 항목이다.
- **컬렉션 변이 메서드와 측정 비트 `if`(2b)** — 결정됨(2026-11-23): 이름 기준의 보수적 규칙을 유지하되 변경된 camelCase 이름(`add`, `put`, `nextInt` 등)과 폐기 예정 별칭 모두에 적용한다. 분석에 타입 정보를 반영해 수신자 타입별로 판정할지가 쟁점이었다.
- **`for-each` 순회 중 `List` 변경(2b)** — 결정됨(2026-11-23): 순회 중 동시 변경을 감지하지 않는 현재 동작을 유지한다. 순회 중 변경을 오류로 처리할지가 쟁점이었다.
- **FFI 기본값과 범위(4a)** — 결정됨(2026-11-23): `ffi`는 기본 꺼진 cargo 기능으로 유지하며 배포 바이너리에 포함하지 않는다. 라이브러리 경로 허용 목록 같은 `--allow ffi` 외의 확인은 배포 빌드에 포함하기로 할 때 다시 검토한다.
- **FFI 구현 방식(4a)** — 결정됨(2026-11-23): 새 의존성 없이 레지스터로 전달되는 `int`/`double` 인수 6개까지 지원하는 현재 방식을 유지하며 `libffi`는 도입하지 않는다.
- **FFI 라이브러리 검색(4a)** — 결정됨(2026-11-23): 현재 플랫폼별 검색 동작(Windows는 애플리케이션·시스템 디렉터리만, Linux·macOS는 `dlopen` 기본 순서)을 유지한다.

### 2c에서 권장안으로 진행한 항목 (사용자 확인 필요, 2026-11-23)

2c 단계에서 되돌리기 쉬운 선택 사항을 권장안으로 진행했으며, 사용자 확인을 위해 아래에 기록한다.

- **명령줄 인자 파일 접근 범위(보안 관련)** — 권장안으로 진행: `--allow fs`를 사용하면 프로그램 인자와 정확히 일치하는 경로(및 폴더를 가리키는 인자 하위의 경로)만 현재 디렉터리 기준으로 읽기 전용으로 읽을 수 있으며, 그 외 경로는 데이터 폴더에 남는다. 추후 지정된 출력 파일의 쓰기 접근이나 별도의 `--allow-read=<dir>` 플래그 등으로 범위를 넓힐 수 있으나 릴리스 이후에는 축소하지 않아야 한다.
- **`examples/cli/wc.qx`** — 권장안으로 진행: `examples/cli/wc.qx`가 `std.fs`를 `import`하므로 표준 입력만 사용할 때도 항상 `--allow fs`가 필요하다. 파일 입력용 예제를 별도로 두는 대안이 남아 있다.
- **`Json` 표현** — 권장안으로 진행: `List`/`Map`처럼 모든 파일에서 사용할 수 있는 불변 내장 타입 `Json`으로 제공하되(프로그램이 같은 이름의 타입을 선언하면 사용자 타입이 우선), 기존 값으로만 구성해 순환을 허용하지 않으며 최대 중첩 깊이는 256으로 제한한다. 가변 JSON 트리를 제공하거나 `import std.json`을 통해서만 타입을 노출하는 대안이 남아 있다.
- **JSON 숫자** — 권장안으로 진행: 소수부나 지수부 없이 쓰이고 64비트에 들어가는 정수는 `int`로 유지하고 그 외는 `double`로 처리하며, 왕복 시 종류가 유지되도록 `double`은 항상 소수부나 지수부를 포함해 출력하고 객체의 중복 이름은 첫 번째 위치와 마지막 값을 유지한다. 모든 숫자를 `double`로 처리하거나 중복 이름을 거부하는 대안이 남아 있다.
- **종류 불일치 처리** — 권장안으로 진행: 다른 종류의 값에 `asInt()` 및 유사 메서드를 호출하면 `Option`을 반환하지 않고 런타임 오류 `Q0421`을 발생시키며, `get(name)`은 `Option<Json>`을 반환한다. 모든 접근자가 `Option`을 반환하도록 하는 대안이 남아 있다.
- **`std.path` 의미론** — 권장안으로 진행: 텍스트 기반으로만 동작하며 모든 플랫폼에서 동일하게 처리하고(`/`와 `\`를 모두 구분자로 인식하며 `join`/`normalize` 결과는 `/`를 사용), `parent`는 상위 경로가 없을 때 `Option<String>` 대신 빈 문자열을 반환한다. 플랫폼 기본 구분자를 사용하거나 `Option`을 반환하는 대안이 남아 있다.
- **`fs.exists`·`fs.isDirectory`·`fs.list`** — 권장안으로 진행: `fs.exists`는 그대로 파일만 뜻하고 폴더는 새 `fs.isDirectory`로 확인하며, `fs.list`는 이름을 바이트 순서로 정렬해 최대 1,048,576개까지 반환한다. `exists`가 폴더에 대해서도 참을 반환하도록 동작을 변경하는 대안이 남아 있다.
