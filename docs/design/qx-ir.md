# `.qx` 언어의 타입 있는 IR 설계 초안

상태: 설계 초안이며 아직 구현된 코드는 없다. 2026-11-20 메인테이너 결정에 따라 IR 구현은 큐비트 매개변수, `var`, 캐스트, `PI` 기능의 구현과 테스트가 모두 완료된 뒤에 착수한다. 이 문서는 [qx-language.md](qx-language.md#126-인터프리터에서-ir-네이티브-코드-생성까지의-로드맵) 12.6절 로드맵의 1단계를 구체화하며, 아직 측정된 수치가 없으므로 성능에 관한 주장은 포함하지 않는다.

## 목표와 비목표

- **목표 — AST 인터프리터 대체와 동작 동등성**: 기존 AST 트리 순회 인터프리터를 타입 있는 IR 하강(lowering)과 IR 인터프리터로 대체하되, 프로그램 출력, 진단 메시지와 오류 코드(런타임 `Q04xx`의 위치 포함), 바이트 단위로 동일한 OpenQASM 3 출력을 그대로 재현한다.
- **목표 — 세 가지 값 단계의 명시화**: 빌드 시점 고전 값, 샷 시점 고전 값, 양자 핸들의 세 단계를 IR 타입 체계에 명시적으로 드러낸다.
- **목표 — 후속 백엔드 기반 마련**: 추후 Cranelift 백엔드가 빌드 시점 고전 함수를 그대로 받아 네이티브 코드로 컴파일할 수 있는 구조를 제공한다.
- **비목표**: 이 단계에서는 최적화 패스, 네이티브 코드 생성, QIR 변환, 신규 언어 기능 추가, 기존 검사기 변경, 공개 `qxide` 라이브러리 API 변경을 다루지 않는다.

## 파이프라인

아래 그림은 검사기를 거친 AST가 IR로 하강해 실행되는 전체 파이프라인을 보여 준다.

```text
.qx source
  -> lexer -> parser -> AST
  -> checker (types, linear qubits, if-on-Bit rules)   // unchanged
  -> lowering -> typed IR (src/lang/ir.rs)             // new
  -> IR interpreter -> qxide::Circuit + output template
  -> simulate (run) / to_qasm (qasm)
later: build-time classical functions -> Cranelift JIT
```

타입 및 선형성 오류의 단일 출처는 기존 검사기로 유지하며, 하강 단계는 이미 검사를 통과한 AST를 입력으로 가정한다. IR 인터프리터도 현재 인터프리터와 마찬가지로 `main`을 한 번 실행해 `qxide::Circuit`과 출력 템플릿을 구성하며, `src/lang/mod.rs`의 시뮬레이션 실행과 표 출력은 변경하지 않는다. IR 관련 코드는 모두 바이너리 전용 모듈인 `src/lang/` 안에 둔다.

## 타입과 값 단계

모든 IR 값은 아래 표의 타입 중 하나를 가지며, 단계 열은 해당 값이 결정되는 시점을 나타낸다.

| IR | `.qx` | 단계 |
| --- | --- | --- |
| `i64` | `int` | 빌드 시점(회로 구성 중) |
| `f64` | `double` | 빌드 시점(회로 구성 중) |
| `bool` | `boolean` | 빌드 시점(회로 구성 중) |
| `bit` | `Bit` | 샷 시점(시뮬레이션 샷별, OpenQASM 3 고전 비트) |
| `bits` | `BitReg` | 샷 시점(시뮬레이션 샷별, OpenQASM 3 고전 비트) |
| `qubit` | `Qubit` | 양자 핸들(회로 내 큐비트 슬롯) |
| `qreg` | `QReg` | 양자 핸들(회로 내 큐비트 슬롯) |
| `unit` | `void` | - |

## 모듈, 함수, 기본 블록

IR 모듈은 함수 목록으로 구성되며, `.qx` 프로그램의 제어 흐름과 부수 효과를 명시적인 명령어 집합으로 표현한다.

- **매개변수 전달 모드**: 각 함수 매개변수는 `.qx` 시그니처에 따라 `copy`(고전 타입), `borrow`(대여 양자 타입), `consume`(소유권 이동 양자 타입) 중 하나의 전달 모드를 가진다.
- **기본 블록과 종결자**: 함수 본문은 기본 블록으로 이루어진 제어 흐름 그래프이며, 모든 기본 블록은 `jump`, `br`, `ret` 중 하나의 종결자 명령어로 끝난다.
- **가상 레지스터와 스택 슬롯**: 명령어 결과는 타입이 붙은 가상 레지스터(`%x`)에 저장한다. 변경 가능한 `.qx` 지역 변수는 SSA phi 노드 대신 타입이 있는 스택 슬롯(`slot`, `load`, `store`)으로 표현하는데, 추후 네이티브 백엔드를 추가할 때 `cranelift-frontend`가 변수로부터 SSA를 직접 구성할 수 있기 때문이다.
- **양자 연산과 출력**: 양자 연산은 부수 효과를 가진 명령어(`qalloc`, `qalloc.reg`, `qelem`, `h`·`cx`·`rx` 등의 게이트 명령어, `measure`, `measure.reg`, `discard`)로 표현하며, `print` 명령어는 `println`의 포맷 조각을 그대로 유지한다.

아래 예제는 `examples/qx/functions.qx`를 IR로 하강한 형태다.

```text
fn bellPair(borrow %a: qubit, borrow %b: qubit) -> unit {
bb0:
    h %a
    cx %a, %b
    ret
}

fn measureAll(consume %r: qreg) -> unit {
bb0:
    %m = measure.reg %r
    print "{}", %m
    ret
}

fn main() -> unit {
bb0:
    %r = qalloc.reg 2
    %r0 = qelem %r, 0
    %r1 = qelem %r, 1
    call bellPair(%r0, %r1)
    call measureAll(%r)
    ret
}
```

빌드 시점 범위를 순회하는 `for` 반복문은 아래 예제처럼 헤더·본문·종료 기본 블록으로 하강된다. 정수 산술 명령어는 검사 산술 의미론(오버플로 `Q0401`, 0으로 나누기 `Q0402`)을 유지하고, `double` 산술은 IEEE 754를 따르며, 캐스트는 Java 규칙을 그대로 유지한다.

```text
// for i in 0..n { total = total + i; }
fn sum(copy %n: i64) -> i64 {
    slot $total: i64
    slot $i: i64
bb0:
    store $total, 0
    store $i, 0
    jump bb1
bb1:
    %i = load $i
    %c = lt.i64 %i, %n
    br %c, bb2, bb3
bb2:
    %t = load $total
    %t2 = add.i64 %t, %i      // checked: overflow -> Q0401
    store $total, %t2
    %i2 = add.i64 %i, 1
    store $i, %i2
    jump bb1
bb3:
    %r = load $total
    ret %r
}
```

## 측정 결과에 대한 `if`

`Bit`에 대한 `if`는 본문을 조건부 연산으로 회로에 기록해야 하므로 빌드 시점 제어 흐름 분기로 낮출 수 없다. 따라서 선택적 `else` 영역을 갖는 구조화된 영역 명령어 `if.bit`로 표현하며, IR 인터프리터가 이를 `Circuit::if_one`/`if_zero`로 낮춘다. 영역 안에는 `call` 명령어가 나타날 수 있으나, 검사기가 조건부 실행 가능으로 분류한 함수(`consume` 매개변수, 양자 반환, 큐비트 할당·측정·폐기·출력이 추이적으로 없는 함수)에 대한 호출만 허용된다. IR 인터프리터는 영역을 기록하는 동안 이러한 호출을 실행하며, IR 검증기(verifier)도 이 조건을 검증해야 한다. 반면 바깥 함수의 `ret`, 큐비트 할당, 측정은 여전히 영역 안에 나타나지 않는다. 아래 발췌는 `examples/qx/teleport.qx`의 조건부 보정 부분을 IR로 표현한 예다.

```text
%m1 = measure %alice
if.bit %m1 {
    x %bob
}
```

## 함수 호출과 추후 네이티브 코드 생성

IR 인터프리터는 현재 인터프리터와 동일한 방식으로 호출 프레임과 호출 깊이 제한(`Q0405`)을 관리하며 `call`을 실행하고, 실행 시점에 결정되는 인덱스를 가진 양자 인자가 서로 겹치지 않는지 런타임에 검사한다(`Q0303`). 추후 Cranelift 단계에서는 하강 시점에 함수를 다음과 같이 분류한다.

- **순수 빌드 시점 고전 함수**: `int`, `double`, `boolean` 매개변수와 반환값만 다루고 큐비트 연산·`println`·측정을 포함하지 않는 함수로, JIT 컴파일 후보가 된다.
- **회로 구성·출력 함수**: 큐비트를 다루거나 출력을 수행하는 함수는 회로를 구성해야 하므로 IR 인터프리터에서 계속 실행한다.
- **선행 조건**: 이 분류는 하강 시점에 결정되는 정적 속성이며, 실제 백엔드 작업은 로드맵 2단계의 벤치마크를 먼저 구축한 뒤 착수한다.

## 진단 메시지와 소스 위치

런타임에 실패할 수 있는 모든 IR 명령어는 원래 `.qx` 표현식의 소스 `Span`을 보관하므로, 런타임 오류(`Q0401`~`Q0410`)는 현재와 동일한 행과 열 위치에서 보고된다. 하강 단계 자체는 사용자 대상 오류를 발생시키지 않아야 하며, 이 단계에서 발생하는 실패는 모두 내부 오류로 취급한다.

## 검증

- **IR 검증기**: 디버그 빌드와 테스트에서 피연산자 타입 일치, 모든 기본 블록의 종결자 보유 여부, 그리고 선형 큐비트 사용 규칙(소유한 큐비트는 정확히 한 번 소비되고 대여한 큐비트는 소비되지 않음)을 단언(assertion)으로 재검증한다.
- **이중 실행 동등성 검사**: 전환 기간 동안 모든 기존 테스트와 예제를 AST 인터프리터와 IR 인터프리터 양쪽으로 실행해 프로그램 출력, 진단 메시지, OpenQASM 3 출력을 바이트 단위로 비교한다.
- **스냅샷 테스트**: 위 예제와 같은 형식의 텍스트 IR 덤프를 스냅샷 테스트에 사용하며, 이를 숨겨진 CLI 명령으로 노출할지는 아직 미결이다.

## 구현 단계

1. IR 자료구조, 텍스트 덤프 출력기, IR 검증기를 구현한다.
2. 고전 부분집합(함수, 스택 슬롯, `for`, `boolean` 조건의 `if`, 산술 연산, 캐스트, `PI`)의 하강과 IR 인터프리터를 구현한다.
3. 양자 명령어와 `if.bit` 영역 명령어를 추가한다.
4. `copy`/`borrow`/`consume` 전달 모드를 지원하는 함수 호출과 런타임 별칭 검사를 구현한다.
5. 모든 테스트와 예제에 대해 이중 실행 동등성을 검증한 뒤 CLI를 IR 인터프리터로 전환하고 기존 AST 인터프리터를 제거한다.
6. Cranelift 백엔드 작업에 앞서 벤치마크 모음(로드맵 2단계)을 구축한다.

## 미결 사항

- `for` 반복문 경계를 계속 빌드 시점 값으로만 제한할지 여부
- `Bit` 값에 대한 샷 시점 고전 산술을 지금 IR에 추가할지, 추후 OpenQASM 3 고전 기능과 함께 도입할지 여부
- IR 텍스트 덤프를 숨겨진 CLI 명령으로 노출할지 테스트 전용으로만 둘지 여부
- 레지스터가 크기 지정 타입(`QReg<3>`)으로 확장될 때 `QReg` 원소 핸들(`qelem`)을 어떻게 표현할지 여부
- Cranelift 도입 시 JIT 컴파일된 함수를 어느 계층에 캐시할지 여부
