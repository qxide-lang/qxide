# .qx 언어 설계 초안 (ROADMAP 1단계)

> **상태**: 초안/제안. 문법과 의미론은 10절의 메인테이너 결정을 기다리는 초안 상태이며, 3~5절의 MVP는 `qx-lang` 브랜치에 구현 완료되었다(2026-11-20, 미병합·미배포). 구현 결과와 설계 대비 수정 사항은 11절에 기록한다.

## 1. 배경 및 목표

현재 `qxide`는 큐비트 소유권을 Rust 타입으로 표현하는 크레이트다. `Qubit`은 `Clone`과 `Copy`를 구현하지 않으며, `measure(q: Qubit) -> Bit`는 큐비트를 소비하고, `cx(&mut a, &mut b)`는 동일한 큐비트의 중복 전달을 금지한다. 라이브러리에는 OpenQASM 3 내보내기, `Backend::Auto`로 선택되는 상태벡터/안정화자(stabilizer) 시뮬레이터, 선택적 GPU 프로토타입, 범위 기반 역연산(uncomputation) `with_ancilla`, 런타임 얽힘 그룹 추적 `may_be_entangled`가 구현되어 있다.

ROADMAP 1단계 과제는 전용 `.qx` 문법의 도입이다. `.qx` 언어의 목표는 일반 고전 연산과 양자 연산을 Rust와 유사한 단일 `.qx` 파일에 함께 작성하는 것이다. 프로젝트의 장기 목표에는 우주·천체물리 시뮬레이션과 같은 대규모 연산이 포함되어 있으므로, 첫 버전은 인터프리터로 구현하더라도 고전 연산을 빠르게 실행할 수 있는 컴파일 경로를 설계 단계에서 열어 둔다.

이 문서는 언어의 목표, 문법 초안, 선형 큐비트 기반 타입 시스템, 실행 모델, 구현 전략 비교, 단계별 로드맵, 미결정 사항을 다룬다.

**MVP 범위**
- `fn main` 및 고전 보조 함수
- `let`/`let mut`, `i64`, `bool`
- `if`/`else`, `for i in a..b`
- 큐비트 및 큐비트 레지스터 할당
- 게이트 `h`, `x`, `z`, `s`, `sdg`, `t`, `tdg`, `cx`, `ccx`, `reset`
- `measure`, `discard`, `println`
- CLI 명령 `qxide run`, `qxide check`, `qxide qasm`

**MVP 비목표**
- 부동소수점 타입과 회전 게이트
- 큐비트를 인자로 받는 사용자 정의 함수
- `with_ancilla` 문법
- `while`/`loop` 반복문
- 구조체·모듈·패키지(`Qx.toml`)
- 네이티브 코드 생성
- 실제 양자 하드웨어 제출

## 2. 설계 원칙 및 제약

1. **기준 의미론은 `qxide` 라이브러리다.** 모든 `.qx` 구문은 기존 공개 `qxide::Circuit` API 호출로 낮춰지며(lowering), 시뮬레이터와 OpenQASM 3 출력 및 런타임 검사를 재구현하지 않고 그대로 재사용한다. MVP는 크레이트의 공개 API를 변경하지 않으며, 언어 구현은 `src/main.rs`에서만 사용하는 바이너리 전용 모듈 `src/lang/`에 둔다.
2. **물리 법칙을 타입 규칙으로 강제한다.** 라이브러리에서 `rustc`의 대여 검사기(borrow checker)가 수행하던 복제 금지(no-cloning)와 측정 시 큐비트 소비 규칙을 `.qx` 검사기가 실행 전에 정적으로 검증한다.
3. **라이브러리보다 의도적으로 더 엄격한 선형 규칙을 적용한다.** Rust 라이브러리는 `Qubit`이 암묵적으로 드롭될 수 있는 아핀(affine) 모델이지만, `.qx`는 스코프 종료 전에 모든 큐비트가 `measure` 또는 명시적 `discard`로 소비되어야 하는 선형(linear) 모델을 택한다. 전용 검사기를 두면 `Drop` 기반 런타임 가드 없이도 Rust가 정적으로 강제할 수 없는 규칙을 검사할 수 있다.
4. **`qxide check`를 통과한 모든 프로그램은 OpenQASM 3로 내보낼 수 있어야 한다.** 라이브러리의 `if_one`/`if_zero` 피드포워드 모델로 표현할 수 없는 구문은 시뮬레이터에서 별도 동작으로 처리하지 않고 정적 검사 단계에서 거부한다.
5. **어떤 `.qx` 입력도 Rust 패닉에 도달해서는 안 된다.** 라이브러리가 `panic!`으로 보고하는 오용(분기 내부 측정, 중복 큐비트 전달 등)은 검사기가 사전에 차단하거나 런타임 진단으로 보고한다. 시뮬레이션 역시 `simulate_with`를 호출해 `SimError`를 진단 메시지로 변환한다.
6. **새 외부 의존성을 추가하지 않는다.** 렉서와 파서는 파서 생성기 없이 직접 작성한다. 이를 통해 크레이트의 기본 무의존성 상태를 유지하고, 줄·열 위치 정보를 포함한 진단 메시지를 완전히 제어한다.

## 3. 문법 초안

아래 네 개의 예제 프로그램은 벨 쌍(Bell pair), 레지스터와 `for` 루프를 사용한 5-큐비트 GHZ 상태, 측정된 비트가 `if m1 { ... }`로 후속 게이트를 제어하는 양자 텔레포테이션, 빌드 시점 루프를 포함하는 순수 고전 보조 함수를 보여 준다.

문법은 `examples/bell.rs`에서 수신자 `c.`와 `&mut`를 제거한 형태를 의도적으로 따른다. 게이트는 `h(a)`, `cx(a, b)`와 같은 자유 함수로 호출하며, 할당은 `qubit()`과 `qreg(n)`을 사용한다. `measure`는 `Qubit`에 대해 `Bit`를, `QReg`에 대해 `BitReg`를 반환한다. 주석은 `//` 한 줄 주석을 지원하며, 함수 정의, `let`, `let mut`, `if`/`else`, 끝값이 배타적인 `for i in a..b`, `return`, 함수 마지막 표현식 반환은 Rust 규칙을 따른다. 다만 MVP에서 `if`는 문(statement)으로만 사용할 수 있으며 `if` 표현식은 지원하지 않는다. 아래 코드 블록의 `rust` 태그는 구문 강조만을 위한 것이다.

```rust
// examples/qx/bell.qx
fn main() {
    let a = qubit();
    let b = qubit();
    h(a);
    cx(a, b);
    let ma = measure(a);
    let mb = measure(b);
    println("a={} b={}", ma, mb);
}
```

```rust
// examples/qx/ghz.qx
fn main() {
    let n = 5;
    let r = qreg(n);
    h(r[0]);
    for i in 1..n {
        cx(r[0], r[i]);
    }
    let m = measure(r);
    println("{}", m);
}
```

```rust
// examples/qx/teleport.qx: measurement results steer later gates
fn main() {
    let msg = qubit();
    let alice = qubit();
    let bob = qubit();
    x(msg);
    h(alice);
    cx(alice, bob);
    cx(msg, alice);
    h(msg);
    let m0 = measure(msg);
    let m1 = measure(alice);
    if m1 {
        x(bob);
    }
    if m0 {
        z(bob);
    }
    let out = measure(bob);
    println("bob={}", out);
}
```

```rust
// Classical helper functions and build-time control flow
fn parity(n: i64) -> bool {
    n % 2 == 1
}

fn main() {
    let mut total = 0;
    for i in 0..10 {
        if parity(i) {
            total = total + i;
        }
    }
    println("total={}", total);
}
```

다음은 MVP 문법의 EBNF 정의다. 연산자 우선순위는 낮은 순서에서 높은 순서로 `||`, `&&`, 비교 연산자(비결합), `+ -`, `* / %`, 단항 `- !`, 인덱싱 순이다. 범위 연산자 `..`는 `for` 헤더에서만 허용된다. 문자열 리터럴(`\n`, `\t`, `\\`, `\"` 이스케이프와 리터럴 중괄호용 `{{`/`}}` 지원)은 `println`의 첫 번째 인자로만 사용할 수 있다. 향후 확장을 위해 예약된 키워드 `while`, `loop`, `break`, `continue`, `struct`, `enum`, `impl`, `use`, `mod`, `const`, `match`, `with_ancilla`, `apply`는 사용 시 오류로 거부한다.

```ebnf
program    = { fn_decl } ;
fn_decl    = "fn" IDENT "(" [ param { "," param } ] ")" [ "->" type ] block ;
param      = IDENT ":" type ;
type       = "i64" | "bool" | "Bit" | "BitReg" | "Qubit" | "QReg" ;
block      = "{" { stmt } [ expr ] "}" ;          (* trailing expr = function result *)
stmt       = "let" [ "mut" ] IDENT [ ":" type ] "=" expr ";"
           | IDENT "=" expr ";"
           | "if" expr block [ "else" ( block | if_stmt ) ]
           | "for" IDENT "in" expr ".." expr block
           | "return" [ expr ] ";"
           | expr ";" ;
expr       = or ;
or         = and { "||" and } ;
and        = cmp { "&&" cmp } ;
cmp        = sum [ ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) sum ] ;
sum        = term { ( "+" | "-" ) term } ;
term       = unary { ( "*" | "/" | "%" ) unary } ;
unary      = ( "-" | "!" ) unary | postfix ;
postfix    = primary { "[" expr "]" } ;
primary    = INT | "true" | "false" | STRING | IDENT [ "(" [ expr { "," expr } ] ")" ] | "(" expr ")" ;
```

아래 표는 MVP에서 제공하는 내장 함수와 각 함수가 `qxide` 라이브러리에서 대응하는 대상을 정리한 것이다.

| 내장 함수 | 시그니처 / 소유권 | qxide 라이브러리 대응 |
| --- | --- | --- |
| `qubit()` | `() -> Qubit` | `Circuit::qubit` |
| `qreg(n)` | `(i64) -> QReg` | `Circuit::qubit` × n |
| `h` `x` `z` `s` `sdg` `t` `tdg` | `(Qubit)`, 큐비트 대여(유지) | `Circuit::h` … |
| `cx(c, t)` | `(Qubit, Qubit)`, 큐비트 대여(유지) | `Circuit::cx` |
| `ccx(c1, c2, t)` | `(Qubit, Qubit, Qubit)`, 큐비트 대여(유지) | `Circuit::ccx` |
| `reset(q)` | `(Qubit)`, 큐비트 대여(유지) | `Circuit::reset` |
| `measure(q)` / `measure(r)` | `(Qubit) -> Bit` / `(QReg) -> BitReg`, 인자 소비(이동) | `Circuit::measure` |
| `discard(q)` / `discard(r)` | `(Qubit)` / `(QReg)`, 인자 소비(이동) | 연산 미방출, 슬롯 포기(부분 대각합) |
| `len(r)` | `(QReg) -> i64` / `(BitReg) -> i64` | 빌드(전개) 시 평가, 연산 미방출 |
| `println(fmt, ...)` | `{}` 자리표시자가 포함된 문자열 리터럴과 `i64`/`bool`/`Bit`/`BitReg` 인자 | 출력 템플릿에 기록, 샷마다 1회 렌더링 |

## 4. 타입 시스템

MVP의 6개 타입은 복사 가능 여부와 값 확정 시점에 따라 세 범주로 나뉜다. 아래 표는 각 타입의 성격과 의미를 정리한 것이다.

| 타입 | 복사 가능 여부 | 값 확정 시점 | 의미 |
| --- | --- | --- | --- |
| `i64`, `bool` | 가능 | 빌드 시점(인터프리터 전개 중) | 일반 고전 정수(64비트, 오버플로 시 오류)와 불리언 |
| `Bit`, `BitReg` | 가능 | 샷 실행 시점(시뮬레이션 이후) | 측정 결과 슬롯 핸들 및 그 레지스터(라이브러리의 `Bit`/`BitReg`에 대응) |
| `Qubit`, `QReg` | 불가 — 선형(정확히 한 번 소비해야 함) | 빌드 시점(인터프리터 전개 중) | 소유된 큐비트 및 큐비트 레지스터 |

### 선형 큐비트 규칙

1. **복사 금지**: `let q2 = q;`는 `q`를 이동(move)시키며, 이후 `q`를 다시 사용하면 `Q0301` 오류가 발생한다. 복제 연산은 존재하지 않는다.
2. **소비 규칙**: `measure`와 `discard`는 `Qubit` 또는 `QReg` 전체를 소비하며, 게이트와 `reset`은 대여만 수행한다. 이미 소비된 변수를 사용하면 `Q0301` 오류가 발생하며, 진단 메시지는 해당 변수가 소비된 위치를 함께 가리킨다.
3. **선형성**: 블록이 끝나거나 `return`으로 함수를 빠져나갈 때 아직 살아 있는 `Qubit`/`QReg`가 남아 있으면 `Q0302` 오류로 거부한다. 라이브러리에서는 조용히 드롭되는 경우라도 `.qx`에서는 명시적인 `measure`나 `discard`가 필요하다. 살아 있는 큐비트와 같은 이름의 새 `let` 바인딩으로 섀도잉(shadowing)하는 것도 누수를 유발하므로 `Q0310` 오류로 금지한다.
4. **피연산자 중복 금지**: `cx`/`ccx`에 동일한 큐비트를 두 번 전달하는 경우, 정적으로 판별 가능하면(같은 변수이거나 같은 레지스터의 동일한 리터럴 인덱스) 검사 단계에서 `Q0303` 오류를 보고한다. 정적으로 알 수 없는 경우(예: 실행 시 `i == j`인 `cx(r[i], r[j])`)에는 런타임에서 동일한 코드로 오류를 보고한다.
5. **제어 흐름 일치**: `bool` 조건의 `if`에서는 양쪽 분기가 끝났을 때 외부 큐비트의 소비 상태가 모두 일치해야 하며, 다르면 `Q0304` 오류가 발생한다. `for` 루프 본문은 루프 바깥에서 선언된 큐비트를 소비할 수 없다(`Q0305`).
6. **레지스터 단위 이동 및 재할당 금지**: MVP에서 `QReg`는 전체 단위로만 이동한다. `measure(r[i])`, `discard(r[i])`, `let q = r[i];`는 `Q0306` 오류로 거부하며, 개별 원소는 게이트 호출의 대여 인자로만 사용할 수 있다. 또한 양자 변수에는 `=`로 재할당할 수 없다(`Q0307`).
7. **연산 문맥 제한**: 양자 값을 산술 연산이나 비교 연산에 사용하면 타입 불일치(`Q0204`)로, `println`으로 출력하면 `Q0212`로 보고되며, 매개변수나 반환값이 `Qubit`/`QReg`인 함수는 MVP에서 지원하지 않아 `Q0219`로 거부된다. 또한 `h(qubit())`처럼 큐비트 변수나 레지스터 원소가 아닌 게이트 피연산자는 `Q0311`로 보고된다.

아래 네 개의 코드 예제는 이러한 오류 코드가 발생하는 대표적인 사례를 보여 준다.

```rust
fn main() {
    let q = qubit();
    let m = measure(q);
    h(q);          // error[Q0301]: q was already measured
}
```

```rust
fn main() {
    let a = qubit();
    cx(a, a);      // error[Q0303]: the same qubit is passed twice
    discard(a);
}
```

```rust
fn main() {
    let q = qubit();
    h(q);
}                  // error[Q0302]: q is never measured or discarded
```

```rust
fn main() {
    let q = qubit();
    for i in 0..3 {
        let m = measure(q);   // error[Q0305]: q is consumed inside a loop
    }
}
```

### 고전 값과 측정 결과 (`bool` 대 `Bit`)

`bool`과 `Bit`의 구분은 이 언어의 핵심 설계 결정이다. `i64`와 `bool` 값은 인터프리터가 프로그램을 전개하는 빌드 시점에 이미 확정되지만, `Bit`와 `BitReg` 값은 라이브러리의 `Bit`/`Shot::get`과 마찬가지로 시뮬레이션 이후 각 샷마다 결정된다.

이에 따라 `bool` 조건의 `if`는 빌드 시점에 분기가 결정되어 선택된 쪽의 게이트만 방출하고, `for` 루프 역시 빌드 시점에 전개된다. 반면 `Bit` 조건의 `if`(`Bit` 변수 또는 `BitReg`의 원소 `m[i]`)는 `Circuit::if_one`으로, `else` 절은 `Circuit::if_zero`로 낮춰지며, OpenQASM 3의 `if (c[i] == true) { ... }`에 대응한다. `Bit`는 산술 연산, `for` 범위, `bool` 조건, 인덱스, 비교 연산처럼 빌드 시점 값이 필요한 위치에 사용할 수 없으며, 시도할 경우 전용 오류 코드 `Q0218`(빌드 시점 값이 필요한 위치에 측정 결과 사용)이 발생한다.

`Bit` 조건 `if`의 본문은 조건부 게이트 블록으로 낮춰져야 하므로 사용 가능한 구문이 제한된다.
- **허용**: 게이트 호출, `reset`, 중첩 `if`, `for`, 고전 값에 대한 `let` 바인딩
- **금지 (`Q0308`)**: `measure`, `discard`, `qubit()`/`qreg()`, `println`, 사용자 함수 호출, `return`, 양자 값에 대한 `let` 바인딩
- **외부 변수 대입 금지 (`Q0309`)**: 본문 바깥에서 선언된 변수에 대입하면 샷 결과와 무관하게 빌드 시점에 실행되므로 허용하지 않는다.

이 제약의 근거는 라이브러리의 의미론과 일치한다. 라이브러리 자체가 분기 내부의 측정을 선택되지 않은 경로의 미정의 비트로 간주해 패닉을 발생시키며, 빌드 시점의 부수 효과 역시 샷별 결과에 의존할 수 없다. 회로 중간 측정 후 후속 게이트를 적용하는 패턴과 `if`를 통한 고전 피드포워드는 그대로 지원된다. OpenQASM 3가 지원하는 샷 시점의 비트 단위 고전 연산은 이후 단계에서 추가할 예정이며, 세부 방향은 8절에서 다룬다.

```rust
fn main() {
    let a = qubit();
    let t = qubit();
    h(a);
    let m = measure(a);
    if m {
        x(t);                 // ok: lowered to `if (c[0] == true) { x q[1]; }`
        let m2 = measure(t);  // error[Q0308]: no measure inside an `if` on a Bit
    }
}
```

## 5. 실행 모델

검사기는 실행에 앞서 전체 프로그램을 먼저 검증하므로, 타입 오류나 소유권 오류가 있는 프로그램은 부분 출력을 생성하지 않는다.

전개(elaboration) 단계는 단일 `qxide::Circuit`을 대상으로 `main`을 정확히 한 번 실행하는 트리 워킹 인터프리터다. 큐비트 변수는 풀(pool)에 저장된 실제 `qxide::Qubit` 값을 보유하므로 모든 게이트 호출은 `Circuit::h`, `Circuit::cx` 등 라이브러리 메서드의 직접 호출로 이어지고, `Bit` 조건의 `if`는 `Circuit::if_one`/`if_zero`로, `measure`는 라이브러리의 `Bit` 반환으로 매핑된다. 고전 평가는 검사된 `i64` 산술을 사용하므로 오버플로, 0으로 나누기, 범위 초과 인덱스는 소스 위치가 포함된 런타임 오류로 보고된다. 재귀 호출은 허용하되 호출 깊이에 상한을 둔다.

전개 결과는 하나의 회로와 출력 템플릿으로 구성된다. 출력 템플릿은 빌드 순서대로 기록된 `println` 호출의 목록이며, 각 `{}` 자리표시자는 이미 확정된 텍스트(`i64`/`bool`)이거나 `Bit`/`BitReg` 참조다. 이처럼 고전 코드가 양자 프로그램을 구성하는 방식을 단계적(staged) 모델이라 하며, 현재 Rust 코드로 `qxide` 라이브러리를 사용하는 방식과 동일하다.

```text
.qx source ─lexer→ tokens ─parser→ AST ─checker→ checked AST
    ─elaborate (tree-walking interpreter, runs main once)→ qxide::Circuit + output template
        ├─ qxide run   → Circuit::simulate_with(Backend::Auto, seed + k) per shot → render template
        └─ qxide qasm  → Circuit::to_qasm()  (OpenQASM 3)
```

실행, 검증, OpenQASM 3 내보내기는 세 가지 CLI 하위 명령으로 제공된다.

- `qxide run <file.qx> [--shots N] [--seed S]`: 회로를 `N`회(기본값 1) 시뮬레이션하며, `k`번째 샷은 `Circuit::simulate_with(Backend::Auto, S + k)`(기본값 `S = 0`)로 실행한다. 따라서 클리포드(Clifford) 연산만으로 구성된 프로그램은 안정화자 백엔드를, 그 외에는 상태벡터 백엔드를 사용한다. 각 샷의 비트로 출력 템플릿을 렌더링해 `N = 1`이면 결과를 그대로 출력하고, `N > 1`이면 동일한 출력을 묶어 고유 출력과 횟수를 함께 표시한다. 출력 템플릿이 `Bit`를 전혀 참조하지 않으면 출력이 샷에 의존하지 않으므로 시뮬레이션을 생략한다. 메모리 한도 초과 등의 `SimError`는 패닉 대신 진단 메시지로 보고한다.
- `qxide qasm <file.qx>`: `Circuit::to_qasm()`이 생성한 OpenQASM 3 코드를 출력하며 `println`은 무시한다.
- `qxide check <file.qx>`: 렉서, 파서, 검사기만 실행하고 진단 메시지를 출력한다. 인덱스 범위 초과와 같은 런타임 오류는 `run`이나 `qasm` 실행 시에만 검출된다.

`BitReg`는 인덱스 순서(`r[0]`부터)로 0과 1의 문자열을 출력한다. 이는 Qiskit의 표시 순서와 반대이며, 10절의 미결정 사항에 기록한다. 한편 `measure`가 즉시 `bool`을 반환하는 실시간 단계별 시뮬레이터 대안은 기각했다. 이 방식은 측정 결과에 임의의 고전 코드를 적용할 수 있지만, 측정 의존 프로그램의 고전 흐름이 단일 샷에 고정되어 OpenQASM 3 내보내기를 잃게 되고, 현재 크레이트에 없는 단계별 시뮬레이터 API가 필요하다. 다만 향후 선택적 실행 모드로 다시 검토할 여지는 남겨 둔다.

## 6. 구현 전략 비교

### 안 A: 직접 작성한 프런트엔드와 트리 워킹 인터프리터

렉서, 재귀 하강 파서, 검사기, 그리고 `qxide` 라이브러리를 직접 호출하는 트리 워킹 인터프리터를 직접 구현하는 방식이다.
- **장점**: 외부 의존성이 없고 `run`/`check`/`qasm` 동작까지 가장 빠르게 도달할 수 있다. 줄·열 정보와 오류 코드를 포함한 진단을 완전히 제어할 수 있고, 기존 시뮬레이터와 OpenQASM 3 출력을 그대로 재사용하며, 문법 초안 단계에서 변경 비용이 낮다.
- **단점**: 고전 코드가 인터프리터로 실행되어 네이티브 Rust에 비해 크게 느리므로(실측 수치는 아직 없음) 장기적인 대규모 시뮬레이션 목표에 제약이 된다. 또한 언어의 모든 의미론을 직접 구현해야 한다.

### 안 B: Rust 소스 변환(트랜스파일) 후 `rustc` 컴파일

`.qx` 코드를 `qxide` 크레이트를 사용하는 Rust 소스로 변환한 뒤 `rustc`로 컴파일해 실행하는 방식이다.
- **장점**: 고전 연산이 네이티브 속도로 실행되며, `rustc`의 소유권 검사기로 큐비트 규칙을 그대로 활용할 수 있고, 라이브러리와 1:1로 대응한다.
- **단점**: 사용자 환경에 Rust 툴체인이 필요하고 실행마다 컴파일 지연이 발생한다. `rustc` 오류는 생성된 코드를 가리키므로 양질의 `.qx` 진단을 제공하려면 어차피 자체 검사기가 필요하며, 라이브러리가 아핀 모델인 탓에 선형성 검사도 별도로 구현해야 한다. PyPI나 단일 설치 바이너리로 배포하기도 어렵다.

### 안 C: 자체 타입 중간 표현(IR) 기반 컴파일러

자체 타입 IR로 낮춘 뒤 초기에는 IR 인터프리터로 실행하고, 이후 Cranelift·LLVM 등의 네이티브 코드 생성기와 OpenQASM 3·QIR 같은 양자 타깃을 붙이는 방식이다.
- **장점**: 장기적으로 성능과 최적화 여지가 가장 크고, 고전 영역과 양자 영역의 분리가 명확하다. `entanglement-tracking.md`의 대안 F인 정적 얽힘 분석을 배치하기에도 자연스럽다.
- **단점**: 초기 설계와 구현 비용이 가장 크며, 문법이 확정되지 않은 단계에서는 시기상조다.

### 권장안

현재 단계에서는 **안 A를 채택하되, 향후 안 C로 확장할 수 있는 구조**로 구현한다. 렉서, 파서, AST, 검사기를 인터프리터와 분리해 두면, 이후 프런트엔드를 건드리지 않고 검사된 AST를 IR로 낮추는 단계(`checked AST -> IR`)로 트리 워커를 교체할 수 있다. CPU 비중이 큰 고전 코드에 대해 필요성이 입증되면 안 B를 선택적 백엔드로 추가하는 것도 배제하지 않는다.

- 문법이 아직 초안 단계이므로 변경 비용을 낮게 유지해야 한다.
- 당장 필요한 가치는 명확한 진단 메시지를 갖춘 `check`/`run`/`qasm`의 동작이다.
- 새 의존성을 추가하지 않는 제약과 부합한다.
- MVP의 고전 연산 규모는 회로를 구성하는 수준으로 작으며, 장기적인 대규모 시뮬레이션 목표는 인터프리터 최적화보다 로드맵의 IR 및 네이티브 코드 생성 단계에서 해결하는 편이 타당하다.

## 7. 진단 메시지

모든 진단 메시지는 안정적인 오류 코드, 설명 문구, 주 소스 위치(줄·열 기준, 열은 문자 수로 계산하며 CRLF 줄바꿈을 허용)와 해당 소스 줄 및 캐럿(`^`) 표시, 그리고 필요 시 관련 위치를 가리키는 부가 주석(예: 큐비트가 측정된 위치)으로 구성된다. 메시지는 라이브러리의 패닉 및 `SimError` 문구와 일관되게 한국어로 작성하되, 테스트는 문구 자체 대신 오류 코드와 소스 위치를 검증한다. 검사기는 첫 오류에서 중단하지 않고 발견할 수 있는 오류를 모두 보고한다. 종료 코드는 성공 `0`, 프로그램 오류(진단 발생) `1`, CLI 사용법 오류 `2`를 사용한다.

| 코드 범위 | 분류 |
| --- | --- |
| `Q01xx` | 렉싱 및 파싱 오류 |
| `Q02xx` | 이름 해석 및 타입 오류 |
| `Q03xx` | 큐비트 소유권 및 `Bit` 조건 `if` 제약 오류 |
| `Q04xx` | 전개 또는 시뮬레이션 중 런타임 오류(오버플로, 0으로 나누기, 인덱스 범위 초과, 런타임 중복 큐비트, 재귀 한도 초과, `SimError`) |

## 8. MVP 이후 확장 계획

아래 두 코드 스케치는 아직 구현되지 않았으며 향후 문법 방향만 고정하기 위한 것이다. `with_ancilla anc { compute } apply { body }`는 `Circuit::with_ancilla`/`with_ancillas`로 낮춰지며, 라이브러리와 동일한 규칙(compute 블록에는 `x`/`cx`/`ccx`만 허용, apply 블록에서는 보조 큐비트와 compute 블록이 건드린 모든 큐비트를 제어 큐비트 또는 대각 위상 용도로만 사용)을 대여 검사기와 런타임 잠금 대신 `.qx` 검사기가 정적으로 검증한다. 큐비트를 받는 사용자 함수는 명시적인 `&mut Qubit`(대여)와 `Qubit`(이동) 매개변수 및 `Qubit` 반환 타입으로 표현한다.

```rust
// Sketch only (not implemented): scoped uncomputation, lowered to Circuit::with_ancilla
fn main() {
    let a = qubit();
    let b = qubit();
    let t = qubit();
    h(a);
    h(b);
    with_ancilla anc {
        ccx(a, b, anc);       // compute: only x / cx / ccx, reads a and b
    } apply {
        cx(anc, t);           // apply: anc, a and b are control-only here
    }
    let r = measure(t);
    discard(a);
    discard(b);
}
```

```rust
// Sketch only (not implemented): qubit-taking functions
fn bell_pair(a: &mut Qubit, b: &mut Qubit) {
    h(a);
    cx(a, b);
}

fn fresh_plus() -> Qubit {
    let q = qubit();
    h(q);
    q
}
```

- `f64` 타입과 회전 게이트 `rx`, `ry`, `rz`(라이브러리에서 이미 지원)
- 위 스케치와 같은 큐비트 매개변수·반환값 지원 사용자 함수
- `with_ancilla` 블록 문법
- 빌드 시점 `while`/`loop`/`break` 제어 흐름
- `Bit` 값에 대한 샷 시점 고전 연산(OpenQASM 3 고전 타입)과 `BitReg`에 대한 `m == 3` 형태의 조건식
- 구조체·모듈 및 `Qx.toml` 패키지 관리(ROADMAP 2단계)
- 검사기 내 정적 얽힘 추적(`entanglement-tracking.md`의 대안 F)
- 대규모 고전 연산을 위한 IR 및 네이티브 코드 생성(6절의 안 C)
- OpenQASM 3의 하드웨어 서비스 제출(ROADMAP 2단계)
- VS Code 구문 강조 확장(ROADMAP 1단계)

   - 얽힘 그룹 기반 시뮬레이션 분할, 양자 하드웨어 제출, `Qx.toml` 패키지 지원

## 10. 미결정 사항

1. **선형 대 아핀 모델**: 스코프 종료 시 소비되지 않은 큐비트를 오류로 처리할 것인가(MVP 기본값: 오류 `Q0302`, 명시적 `discard` 제공), 경고로 낮출 것인가, 아니면 라이브러리처럼 허용할 것인가?
2. **게이트 호출 문법**: `&mut` 없이 `h(q)`로 호출하는 형태를 유지할 것인가(MVP 기본값), 아니면 Rust처럼 `h(&mut q)`를 요구할 것인가? 큐비트를 받는 사용자 함수에도 같은 기준을 적용할지 결정해야 한다.
3. **타입 명명 규칙**: `i64`/`bool`과 대문자 라이브러리 이름 `Qubit`/`QReg`/`Bit`/`BitReg`를 함께 쓸 것인가(MVP 기본값), 아니면 `int`/`qubit`/`bit`처럼 소문자로 통일할 것인가?
4. **할당 문법**: `qubit()`/`qreg(n)` 함수 호출 형태를 유지할 것인가(MVP 기본값), 아니면 `let q: Qubit;` 같은 선언 구문이나 `QReg<3>` 같은 크기 포함 레지스터 타입을 도입할 것인가?
5. **`measure` 오버로딩**: `measure`가 `Qubit`과 `QReg`를 모두 받도록 오버로딩할 것인가(MVP 기본값), 아니면 라이브러리처럼 `measure_reg`를 별도로 둘 것인가?
6. **`with_ancilla` 블록 문법**: 초안의 `with_ancilla anc { ... } apply { ... }` 형태를 쓸 것인가, 아니면 Q#과 유사한 `within { } apply { }` 또는 다른 구문을 채택할 것인가?
7. **CLI 명령 이름**: `qxide run`/`check`/`qasm` 체계를 유지할 것인가(MVP 기본값), 아니면 ROADMAP에 적힌 `qxide build hello.qx` 형태와 어떻게 통합할 것인가?
8. **`BitReg` 출력 순서**: 인덱스 순서(`r[0]` 우선)로 출력할 것인가(MVP 기본값), Qiskit 방식의 최상위 비트 우선 순서를 따를 것인가, 아니면 `Shot::value`처럼 정수로 출력할 것인가?
9. **진단 메시지 언어**: 라이브러리 메시지에 맞춰 한국어를 기본으로 둘 것인가(MVP 기본값), 영어를 사용할 것인가, 아니면 두 언어를 모두 지원할 것인가?
10. **프런트엔드 공개 여부**: Python 바인딩 등에서 활용할 수 있도록 프런트엔드를 공개 `qxide::lang` 모듈로 노출할 것인가, 아니면 CLI 전용 비공개 모듈로 유지할 것인가(MVP 기본값)?
11. **출력 비의존 시 시뮬레이션 생략**: `println`이 어떤 `Bit`도 출력하지 않을 때 시뮬레이션을 건너뛰는 동작을 유지할 것인가(MVP 기본값), 아니면 `SimError`를 드러내기 위해 항상 시뮬레이션을 실행할 것인가?

## 11. 구현 결과 및 설계 수정 사항 (MVP)

6장의 권고(안 A)에 따라 `qx-lang` 브랜치(커밋 `a052f2b`)에서 MVP를 구현했다. 구현 코드는 `src/lang/`(`lexer.rs`, `parser.rs`, `ast.rs`, `check.rs`, `interp.rs`, `diag.rs`, `msg.rs`)에 위치하며 `src/main.rs`의 바이너리 전용 모듈로 구성되어 라이브러리 공개 API에는 변경이 없고 의존성도 추가되지 않았다. 이 장에서는 구현된 범위, 3~7장의 설계와 달라진 부분, 전체 오류 코드 목록, 그리고 검증 내역을 기록한다.

### 구현 범위

- **언어**: 1장의 MVP 범위에 명시된 기능을 모두 구현했다. `fn main`과 고전 보조 함수(매개변수와 반환 타입으로 `i64`, `bool`, `Bit`, `BitReg` 지원, 재귀 허용), `let`/`let mut`/대입, `if`/`else if`/`else`, `for i in a..b`, `return`, 함수 결과로서의 말미 표현식, `qubit()`, `qreg(n)`, 게이트 `h`, `x`, `z`, `s`, `sdg`, `t`, `tdg`, `cx`, `ccx`, `reset`, 그리고 `measure`, `discard`, `len`, `println`을 지원한다.
- **CLI**: `qxide run <FILE> [--shots N] [--seed S]`, `qxide check <FILE>`, `qxide qasm <FILE>`을 제공한다. 진단은 표준 오류(stderr)로 출력하며, 종료 코드는 성공 시 0, 프로그램 오류(파일을 읽을 수 없는 경우 포함) 시 1, 명령줄 사용법 오류 시 2를 반환한다.
- **예제**: `examples/qx/bell.qx`, `ghz.qx`, `teleport.qx`를 추가했다.
- **다중 샷 출력**: `--shots N`에서 N > 1이면 `run`은 서로 다른 출력마다 `== count/N ==` 형식의 헤더 아래에 내용을 출력하며, 빈도 내림차순과 텍스트순으로 정렬한다. 출력 예시는 아래 오류 코드 표 다음에 제시한다.
- **안전 한도**: 비정상 입력이 크래시 대신 진단으로 처리되도록 한도를 두었다. 파서 중첩 깊이 128(`Q0106`), 함수 호출 깊이 200(`Q0405`), 누적 할당 큐비트 수 최대 2^20개(`Q0409`)로 제한하며, 인터프리터는 64 MiB 스택을 가진 스레드에서 실행한다.
- **`discard` 동작**: `discard`는 연산을 방출하지 않으며 슬롯을 라이브러리의 재사용 풀에 반환하지 않는다(라이브러리는 `measure`로 해제된 슬롯만 재사용한다).
- **진단 언어**: 명령줄 사용법 오류 등의 CLI 메시지는 기존 `qxide bell` 명령과 동일하게 영어로 출력하고, 언어 진단은 한국어로 출력한다(미결 사항 9).

### 설계 수정 사항

1. **빌드 시점 값 자리에 `Bit`/`BitReg` 사용 (`Q0218`)**: 산술 연산, 비교, `for` 범위, 인덱스, `bool` 위치처럼 빌드 시점에 결정되어야 하는 자리에 `Bit`/`BitReg`를 사용하면 4장 초안의 일반 타입 불일치(`Q0204`) 대신 전용 코드 `Q0218`을 보고한다. 오류 메시지는 측정 결과가 샷마다 결정된다는 점을 안내하며, 4장의 내용도 이에 맞게 수정했다.
2. **렉서·파서의 첫 구문 오류 중단**: 모든 오류를 한꺼번에 보고하는 단계는 검사기뿐이다. 파서에 아직 오류 복구 기능이 없으므로 렉서와 파서는 첫 번째 구문 오류(`Q01xx`)에서 중단한다.
3. **양자 값 오용에 대한 세분화된 오류 코드**: 양자 값이 허용되지 않는 위치에 사용된 일부 사례는 `Q0204` 대신 전용 코드를 부여한다. 큐비트를 출력하면 `Q0212`, `Qubit`/`QReg`를 매개변수나 반환 타입으로 쓰는 함수는 `Q0219`를 보고하며, 4장의 규칙 7도 이에 맞게 수정했다.
4. **게이트 피연산자 제한 (`Q0311`)**: 게이트 피연산자는 큐비트 변수나 레지스터 원소여야 하므로 새 코드 `Q0311`을 추가했다. `h(qubit())`는 새로 만든 큐비트가 유실되므로 거부하지만, `measure(qubit())`와 `discard(qreg(3))`는 임시 값을 바로 소비하므로 허용한다.
5. **`Bit` 조건 `if` 내부 `return`의 연쇄 오류 억제**: `Bit` 조건의 `if` 블록 안에 `return`이 있으면 `Q0308`만 보고한다. 하나의 실수가 후속 오류를 만들지 않도록 해당 `return`에 대해서는 큐비트 누수 분석을 건너뛴다.
6. **`bool` 조건 `if`의 발산 분기와 `for` 본문 처리**: `bool` 조건 `if`에서 항상 `return`으로 끝나는 분기는 Rust의 발산 규칙처럼 다른 분기와 큐비트 소비 상태를 맞출 필요가 없어, 예를 들어 `if c { discard(q); return; } discard(q);`는 허용된다. 반면 `for` 본문에서 바깥 큐비트를 소비하는 경우는 루프가 0회 실행될 수도 있으므로 여전히 거부되며, 해당 큐비트는 누수(`Q0302`)로도 함께 보고된다.
7. **런타임 중복 피연산자 코드 재사용 및 미할당 코드**: i == j인 `cx(r[i], r[j])` 같은 런타임 중복 피연산자 오류는 별도 코드를 쓰지 않고 `Q0303`을 재사용한다. 이에 따라 계획했던 별도 런타임 코드는 사용하지 않으며 `Q0208`, `Q0216`, `Q0404`는 미할당 상태로 남겼다.

### 검증

- **로컬 툴체인 검증 (Windows 11)**: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`가 모두 통과했다.
- **신규 테스트**: 바이너리 내부 단위 테스트 19건(`src/lang/`의 렉서, 파서, 진단 렌더링, 검사기, 인터프리터 대상; 메시지 문구가 아니라 오류 코드와 행:열 위치만 검증)과 `tests/cli.rs`의 CLI 테스트 6건(CLI 테스트 총 9건)을 추가했다.
- **주요 확인 항목**: 4장의 모든 오류 예제가 명시된 위치에서 해당 오류 코드를 반환하는지 확인했다. Bell과 GHZ 측정 결과가 항상 상관관계를 유지하며 Bell 예제가 200샷에서 두 결과를 모두 출력하는지, |1> 텔레포테이션이 항상 `bob=1`을 출력하는지 검증했다. `qxide qasm examples/qx/bell.qx` 출력이 Rust API로 구성한 동일 회로의 `to_qasm()` 결과와 일치하며, `bool` 조건 `if`는 선택된 분기만 방출하고 `Bit` 조건 `if`/`else`는 `if (c[i] == true)` / `if (c[i] == false)`로 내려가는 것을 확인했다. 30큐비트 비-Clifford 프로그램은 패닉 대신 `Q0406`을 반환하면서 `qasm` 출력은 정상 동작하며, CRLF 줄바꿈 소스에서도 열 번호가 정확히 보고된다.
- **OpenQASM 3 상호운용성**: 세 예제 파일과 중첩 `Bit` 조건, `else`, `ccx`, `for` 루프를 포함한 추가 샘플에서 생성한 OpenQASM 3 출력을 `ci/check_qasm.py`를 통해 Qiskit 2.6.2(CI 기준 버전)의 `qiskit.qasm3.loads`로 파싱해 성공을 확인했다. CI의 `qasm-interop` 작업도 `examples/qx/*.qx`를 내보내 파싱하도록 확장했다.
- **미검증 항목**: `gpu` 피처 테스트(`cargo test --features gpu`는 이번 변경에서 미실행; CI와 동일한 `cargo clippy --all-targets --features gpu -- -D warnings`는 실행해 통과함), GitHub CI 실행(원격 푸시 전), 인터프리터 성능(별도 측정 없음)은 검증하지 않았다.
