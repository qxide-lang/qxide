# .qx 언어 설계 초안 (ROADMAP 1단계)

> **상태**: MVP는 `main`에 병합되었고, 0.5.0 문법 개정(Java 스타일 선언, 12절)도 `main`에 구현되어 있으나 아직 배포되지 않았다(버전 0.5.0 준비 완료, 2026-11-20). 결정 사항은 10절과 12절에 기록하며, 11절은 0.4 시점 MVP 구현의 이력 기록이다.

## 1. 배경 및 목표

현재 `qxide`는 큐비트 소유권을 Rust 타입으로 표현하는 크레이트다. `Qubit`은 `Clone`과 `Copy`를 구현하지 않으며, `measure(q: Qubit) -> Bit`는 큐비트를 소비하고, `cx(&mut a, &mut b)`는 동일한 큐비트의 중복 전달을 금지한다. 라이브러리에는 OpenQASM 3 내보내기, `Backend::Auto`로 선택되는 상태벡터/안정화자(stabilizer) 시뮬레이터, 선택적 GPU 프로토타입, 범위 기반 역연산(uncomputation) `with_ancilla`, 런타임 얽힘 그룹 추적 `may_be_entangled`가 구현되어 있다.

ROADMAP 1단계 과제는 전용 `.qx` 문법의 도입이다. `.qx` 언어의 목표는 일반 고전 연산과 양자 연산을 Rust와 유사한 단일 `.qx` 파일에 함께 작성하는 것이다. 프로젝트의 장기 목표에는 우주·천체물리 시뮬레이션과 같은 대규모 연산이 포함되어 있으므로, 첫 버전은 인터프리터로 구현하더라도 고전 연산을 빠르게 실행할 수 있는 컴파일 경로를 설계 단계에서 열어 둔다.

이 문서는 언어의 목표, 문법 초안, 선형 큐비트 기반 타입 시스템, 실행 모델, 구현 전략 비교, 단계별 로드맵, 미결정 사항을 다룬다.

**MVP 범위**
- `void main` 및 고전 보조 함수
- Java 스타일 타입 선언(`int x = 1;`, `final`)과 타입 `int`, `double`, `boolean`(0.5.0부터 적용, 12절 참고)
- `if`/`else`, `for i in a..b`
- 큐비트 및 큐비트 레지스터 할당
- 게이트 `h`, `x`, `z`, `s`, `sdg`, `t`, `tdg`, `cx`, `ccx`, `reset`
- `measure`, `discard`, `println`
- CLI 명령 `qxide run`, `qxide check`, `qxide qasm`

**MVP 비목표**
- 부동소수점 타입과 회전 게이트
- 큐비트를 인자로 받는 사용자 정의 함수
- `with_ancilla` 문법
- `while`/`loop` 반복문
- 구조체·모듈·패키지(`qxide.toml`)
- 네이티브 코드 생성
- 실제 양자 하드웨어 제출

## 2. 설계 원칙 및 제약

1. **기준 의미론은 `qxide` 라이브러리다.** 모든 `.qx` 구문은 기존 공개 `qxide::Circuit` API 호출로 낮춰지며(lowering), 시뮬레이터와 OpenQASM 3 출력 및 런타임 검사를 재구현하지 않고 그대로 재사용한다. MVP는 크레이트의 공개 API를 변경하지 않으며, 언어 구현은 `src/main.rs`에서만 사용하는 바이너리 전용 모듈 `src/lang/`에 둔다.
2. **물리 법칙을 타입 규칙으로 강제한다.** 라이브러리에서 `rustc`의 대여 검사기(borrow checker)가 수행하던 복제 금지(no-cloning)와 측정 시 큐비트 소비 규칙을 `.qx` 검사기가 실행 전에 정적으로 검증한다.
3. **라이브러리보다 의도적으로 더 엄격한 선형 규칙을 적용한다.** Rust 라이브러리는 `Qubit`이 암묵적으로 드롭될 수 있는 아핀(affine) 모델이지만, `.qx`는 스코프 종료 전에 모든 큐비트가 `measure` 또는 명시적 `discard`로 소비되어야 하는 선형(linear) 모델을 택한다. 전용 검사기를 두면 `Drop` 기반 런타임 가드 없이도 Rust가 정적으로 강제할 수 없는 규칙을 검사할 수 있다.
4. **`qxide check`를 통과한 모든 프로그램은 OpenQASM 3로 내보낼 수 있어야 한다.** 라이브러리의 `if_one`/`if_zero` 피드포워드 모델로 표현할 수 없는 구문은 시뮬레이터에서 별도 동작으로 처리하지 않고 정적 검사 단계에서 거부한다.
5. **어떤 `.qx` 입력도 Rust 패닉에 도달해서는 안 된다.** 라이브러리가 `panic!`으로 보고하는 오용(분기 내부 측정, 중복 큐비트 전달 등)은 검사기가 사전에 차단하거나 런타임 진단으로 보고한다. 시뮬레이션 역시 `simulate_with`를 호출해 `SimError`를 진단 메시지로 변환한다. 다만 이 목표는 패닉과 크래시 방지에 한정되며 실행 시간 상한은 두지 않는다. 예컨대 `for i in 0..9223372036854775807 { ... }`이나 샷 수가 많은 대규모 시뮬레이션처럼 정상적으로 매우 오래 실행되는 프로그램은 사용자가 직접 중단해야 하며, 시간이나 스텝 예산 도입은 추후 과제로 남겨 둔다.
6. **새 외부 의존성을 추가하지 않는다.** 렉서와 파서는 파서 생성기 없이 직접 작성한다. 이를 통해 크레이트의 기본 무의존성 상태를 유지하고, 줄·열 위치 정보를 포함한 진단 메시지를 완전히 제어한다.

## 3. 문법 초안

아래 네 개의 예제 프로그램은 벨 쌍(Bell pair), 레지스터와 `for` 루프를 사용한 5-큐비트 GHZ 상태, 측정된 비트가 `if m1 { ... }`로 후속 게이트를 제어하는 양자 텔레포테이션, 빌드 시점 루프를 포함하는 순수 고전 보조 함수를 보여 준다.

게이트는 `&mut` 없이 `h(a)`, `cx(a, b)`와 같은 자유 함수로 호출하며, 할당은 `qubit()`과 `qreg(n)`을 사용한다. `measure`는 `Qubit`에 대해 `Bit`를, `QReg`에 대해 `BitReg`를 반환한다. 0.5.0부터 변수 선언은 이름 앞에 타입을 두는 Java 스타일(`Qubit a = qubit();`, `Bit m = measure(a);`, `int n = 5;`, 상수에는 `final`)을 따르며, 함수는 반환 타입을 앞에 쓰고(`void main()`, `boolean parity(int n)`) 값 반환은 `return`으로만 수행한다(마지막 표현식 반환은 지원하지 않는다). 제어 흐름은 기존 형태를 유지해 괄호 없는 `if`/`else`, 끝값이 배타적인 `for i in a..b`, `//` 한 줄 주석을 지원하며, `if`는 문(statement)으로만 사용할 수 있다. 0.5.0의 문법 변경 사항과 마이그레이션은 12절에 기록한다. 아래 코드 블록의 `rust` 태그는 구문 강조만을 위한 것이다.

```rust
// examples/qx/bell.qx
void main() {
    Qubit a = qubit();
    Qubit b = qubit();
    h(a);
    cx(a, b);
    Bit ma = measure(a);
    Bit mb = measure(b);
    println("a={} b={}", ma, mb);
}
```

```rust
// examples/qx/ghz.qx
void main() {
    int n = 5;
    QReg r = qreg(n);
    h(r[0]);
    for i in 1..n {
        cx(r[0], r[i]);
    }
    BitReg m = measure(r);
    println("{}  {} = {}", m, m.to_binary(), m.as_int());
}
```

```rust
// examples/qx/teleport.qx: measurement results steer later gates
void main() {
    Qubit msg = qubit();
    Qubit alice = qubit();
    Qubit bob = qubit();
    x(msg);
    h(alice);
    cx(alice, bob);
    cx(msg, alice);
    h(msg);
    Bit m0 = measure(msg);
    Bit m1 = measure(alice);
    if m1 {
        x(bob);
    }
    if m0 {
        z(bob);
    }
    Bit out = measure(bob);
    println("bob={}", out);
}
```

```rust
// Classical helper functions and build-time control flow
boolean parity(int n) {
    return n % 2 == 1;
}

void main() {
    int total = 0;
    for i in 0..10 {
        if parity(i) {
            total = total + i;
        }
    }
    println("total={}", total);
}
```

다음은 MVP 문법의 EBNF 정의다. 연산자 우선순위는 낮은 순서에서 높은 순서로 `||`, `&&`, 비교 연산자(비결합), `+ -`, `* / %`, 단항 `- !` 및 캐스트 `(type) expr`, 인덱싱 순이다. 범위 연산자 `..`는 `for` 헤더에서만 허용된다. 문자열 리터럴(`\n`, `\t`, `\\`, `\"` 이스케이프와 리터럴 중괄호용 `{{`/`}}` 지원)은 `println`의 첫 번째 인자로만 사용할 수 있다. `var`, `consume`, `import`, `public`은 정식 키워드이며(패키지 시스템의 `import`와 `public` 문법은 `qx-packages.md` 참고), `PI`는 내장 `double` 상수 식별자다. 타입 이름(`int`, `double`, `boolean`, `void`, `Bit`, `BitReg`, `Qubit`, `QReg`)은 식별자로 사용할 수 없다(`Q0112`). 향후 확장을 위해 예약된 키워드 `while`, `loop`, `break`, `continue`, `struct`, `enum`, `impl`, `use`, `mod`, `const`, `match`, `with_ancilla`, `apply`는 사용 시 오류로 거부한다.

```ebnf
program    = { import } { fn_decl } ;                          (* imports: qx-packages.md *)
import     = "import" IDENT { "." IDENT } ( "." IDENT | "." "*" ) ";" ;
fn_decl    = [ "public" ] type IDENT "(" [ param { "," param } ] ")" block ;   (* type may be "void" *)
param      = [ "consume" ] type IDENT ;                      (* "consume" only on Qubit / QReg *)
type       = "int" | "double" | "boolean" | "void" | "Bit" | "BitReg" | "Qubit" | "QReg" ;
block      = "{" { stmt } "}" ;
stmt       = [ "final" ] ( type | "var" ) IDENT "=" expr ";"   (* "var": int / double / boolean only *)
           | IDENT "=" expr ";"
           | if_stmt
           | "for" IDENT "in" expr ".." expr block
           | "return" [ expr ] ";"
           | expr ";" ;
if_stmt    = "if" expr block [ "else" ( block | if_stmt ) ] ;
expr       = or ;
or         = and { "||" and } ;
and        = cmp { "&&" cmp } ;
cmp        = sum [ ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) sum ] ;
sum        = term { ( "+" | "-" ) term } ;
term       = unary { ( "*" | "/" | "%" ) unary } ;
unary      = ( "-" | "!" ) unary | "(" type ")" unary | postfix ;   (* cast: int <-> double *)
postfix    = primary { "[" expr "]" | "." IDENT "(" ")" } ;   (* r.to_binary(), r.as_int() *)
primary    = INT | DOUBLE | "true" | "false" | STRING | IDENT [ "(" [ expr { "," expr } ] ")" ] | "(" expr ")" ;
(* IDENT is never a type name; the IDENT "PI" is the built-in double constant *)
```

아래 표는 MVP에서 제공하는 내장 함수와 각 함수가 `qxide` 라이브러리에서 대응하는 대상을 정리한 것이다.

| 내장 함수 | 시그니처 / 소유권 | qxide 라이브러리 대응 |
| --- | --- | --- |
| `qubit()` | `() -> Qubit` | `Circuit::qubit` |
| `qreg(n)` | `(int) -> QReg` | `Circuit::qubit` × n |
| `h` `x` `z` `s` `sdg` `t` `tdg` | `(Qubit)`, 큐비트 대여(유지) | `Circuit::h` … |
| `cx(c, t)` | `(Qubit, Qubit)`, 큐비트 대여(유지) | `Circuit::cx` |
| `ccx(c1, c2, t)` | `(Qubit, Qubit, Qubit)`, 큐비트 대여(유지) | `Circuit::ccx` |
| `reset(q)` | `(Qubit)`, 큐비트 대여(유지) | `Circuit::reset` |
| `rx(q, θ)` `ry` `rz` | `(Qubit, double)`, 큐비트 대여, 각도는 `double`(`int`는 확장 변환) | `Circuit::rx` … |
| `measure(q)` / `measure(r)` | `(Qubit) -> Bit` / `(QReg) -> BitReg`, 인자 소비(이동) | `Circuit::measure` |
| `discard(q)` / `discard(r)` | `(Qubit)` / `(QReg)`, 인자 소비(이동) | 연산 미방출, 슬롯 포기(부분 대각합) |
| `len(r)` | `(QReg) -> int` / `(BitReg) -> int` | 빌드(전개) 시 평가, 연산 미방출 |
| `r.to_binary()` / `r.as_int()` | `BitReg` 메서드, 출력 전용(변수 저장 불가) | 샷마다 렌더링, 연산 방출 없음 |
| `println(fmt, ...)` | `{}` 자리표시자가 포함된 문자열 리터럴과 `int`/`double`/`boolean`/`Bit`/`BitReg`/`to_binary()`/`as_int()` 인자 | 출력 템플릿에 기록, 샷마다 1회 렌더링 |
| `PI` | `double` 상수(재선언·대입 불가) | `std::f64::consts::PI` 값(빌드 시점 평가, 회로 연산 방출 없음) |

## 4. 타입 시스템

MVP의 6개 타입은 복사 가능 여부와 값 확정 시점에 따라 세 범주로 나뉜다. 아래 표는 각 타입의 성격과 의미를 정리한 것이다.

| 타입 | 복사 가능 여부 | 값 확정 시점 | 의미 |
| --- | --- | --- | --- |
| `int`, `double`, `boolean` | 가능 | 빌드 시점(인터프리터 전개 중) | 64비트 부호 있는 정수(오버플로 시 오류), 64비트 IEEE 754 부동소수점, 불리언 |
| `Bit`, `BitReg` | 가능 | 샷 실행 시점(시뮬레이션 이후) | 측정 결과 슬롯 핸들 및 그 레지스터(라이브러리의 `Bit`/`BitReg`에 대응) |
| `Qubit`, `QReg` | 불가 — 선형(정확히 한 번 소비해야 함) | 빌드 시점(인터프리터 전개 중) | 소유된 큐비트 및 큐비트 레지스터 |

### 선형 큐비트 규칙

1. **복사 금지**: `Qubit q2 = q;`는 `q`를 이동(move)시키며, 이후 `q`를 다시 사용하면 `Q0301` 오류가 발생한다. 복제 연산은 존재하지 않는다.
2. **소비 규칙**: `measure`와 `discard`는 `Qubit` 또는 `QReg` 전체를 소비하며, 게이트와 `reset`은 대여만 수행한다. 이미 소비된 변수를 사용하면 `Q0301` 오류가 발생하며, 진단 메시지는 해당 변수가 소비된 위치를 함께 가리킨다.
3. **선형성**: 블록이 끝나거나 `return`으로 함수를 빠져나갈 때 아직 살아 있는 `Qubit`/`QReg`가 남아 있으면 `Q0302` 오류로 거부한다. 라이브러리에서는 조용히 드롭되는 경우라도 `.qx`에서는 명시적인 `measure`나 `discard`가 필요하다. 살아 있는 큐비트와 같은 이름의 새 `let` 바인딩으로 섀도잉(shadowing)하는 것도 누수를 유발하므로 `Q0310` 오류로 금지한다.
4. **피연산자 중복 금지**: `cx`/`ccx`에 동일한 큐비트를 두 번 전달하는 경우, 정적으로 판별 가능하면(같은 변수이거나 같은 레지스터의 동일한 리터럴 인덱스) 검사 단계에서 `Q0303` 오류를 보고한다. 정적으로 알 수 없는 경우(예: 실행 시 `i == j`인 `cx(r[i], r[j])`)에는 런타임에서 동일한 코드로 오류를 보고한다.
5. **제어 흐름 일치**: `boolean` 조건의 `if`에서는 양쪽 분기가 끝났을 때 외부 큐비트의 소비 상태가 모두 일치해야 하며, 다르면 `Q0304` 오류가 발생한다. `for` 루프 본문은 루프 바깥에서 선언된 큐비트를 소비할 수 없다(`Q0305`).
6. **레지스터 단위 이동 및 재할당 금지**: MVP에서 `QReg`는 전체 단위로만 이동한다. `measure(r[i])`, `discard(r[i])`, `Qubit q = r[i];`는 `Q0306` 오류로 거부하며, 개별 원소는 게이트 호출의 대여 인자로만 사용할 수 있다. 또한 양자 변수에는 `=`로 재할당할 수 없다(`Q0307`).
7. **연산 문맥 제한**: 양자 값을 산술 연산이나 비교 연산에 사용하면 타입 불일치(`Q0204`)로, `println`으로 출력하면 `Q0212`로 보고된다. `Qubit`/`QReg` 매개변수는 기본 대여·`consume` 소유권 이동으로(13.1절 참고), `Qubit`/`QReg`를 반환하는 함수는 소유권 반환으로 지원되며(14.1절 참고) `Q0219`는 폐기되었다. 또한 `h(qubit())`처럼 큐비트 변수나 레지스터 원소가 아닌 게이트 피연산자나 대여 매개변수 인자는 `Q0311`로 보고된다.

아래 네 개의 코드 예제는 이러한 오류 코드가 발생하는 대표적인 사례를 보여 준다.

```rust
void main() {
    Qubit q = qubit();
    Bit m = measure(q);
    h(q);          // error[Q0301]: use of consumed qubit `q`
}
```

```rust
void main() {
    Qubit a = qubit();
    cx(a, a);      // error[Q0303]: same qubit passed to `cx` more than once
    discard(a);
}
```

```rust
void main() {
    Qubit q = qubit();
    h(q);
}                  // error[Q0302]: qubit `q` is never measured or discarded
```

```rust
void main() {
    Qubit q = qubit();
    for i in 0..3 {
        Bit m = measure(q);   // error[Q0305]: qubit `q` is consumed inside a loop
    }
}
```

### 고전 값과 측정 결과 (`boolean` 대 `Bit`)

`boolean`과 `Bit`의 구분은 이 언어의 핵심 설계 결정이다. `int`와 `boolean` 값은 인터프리터가 프로그램을 전개하는 빌드 시점에 이미 확정되지만, `Bit`와 `BitReg` 값은 라이브러리의 `Bit`/`Shot::get`과 마찬가지로 시뮬레이션 이후 각 샷마다 결정된다.

이에 따라 `boolean` 조건의 `if`는 빌드 시점에 분기가 결정되어 선택된 쪽의 게이트만 방출하고, `for` 루프 역시 빌드 시점에 전개된다. 반면 `Bit` 조건의 `if`(`Bit` 변수 또는 `BitReg`의 원소 `m[i]`)는 `Circuit::if_one`으로, `else` 절은 `Circuit::if_zero`로 낮춰지며, OpenQASM 3의 `if (c[i] == true) { ... }`에 대응한다. `Bit`는 산술 연산, `for` 범위, `boolean` 조건, 인덱스, 비교 연산처럼 빌드 시점 값이 필요한 위치에 사용할 수 없으며, 시도할 경우 전용 오류 코드 `Q0218`(빌드 시점 값이 필요한 위치에 측정 결과 사용)이 발생한다.

`Bit` 조건 `if`의 본문은 조건부 게이트 블록으로 낮춰져야 하므로 사용 가능한 구문이 제한된다.
- **허용**: 게이트 호출, `reset`, 대여 큐비트에 게이트와 `reset`만 적용하는 사용자 함수 호출(14.2절 참고), 중첩 `if`, `for`, 고전 변수 선언(예: `int k = 3;`)
- **금지 (`Q0308`)**: `measure`, `discard`, `qubit()`/`qreg()`, `println`, `return`, 양자 변수 선언(`Qubit`, `QReg`). 조건부 블록에서 실행할 수 없는 사용자 함수를 호출하면 `Q0314`로 보고된다(14.2절 참고).
- **외부 변수 대입 금지 (`Q0309`)**: 본문 바깥에서 선언된 변수에 대입하면 샷 결과와 무관하게 빌드 시점에 실행되므로 허용하지 않는다.

이 제약의 근거는 라이브러리의 의미론과 일치한다. 라이브러리 자체가 분기 내부의 측정을 선택되지 않은 경로의 미정의 비트로 간주해 패닉을 발생시키며, 빌드 시점의 부수 효과 역시 샷별 결과에 의존할 수 없다. 회로 중간 측정 후 후속 게이트를 적용하는 패턴과 `if`를 통한 고전 피드포워드는 그대로 지원된다. OpenQASM 3가 지원하는 샷 시점의 비트 단위 고전 연산은 이후 단계에서 추가할 예정이며, 세부 방향은 8절에서 다룬다.

```rust
void main() {
    Qubit a = qubit();
    Qubit t = qubit();
    h(a);
    Bit m = measure(a);
    if m {
        x(t);                 // ok: lowered to `if (c[0] == true) { x q[1]; }`
        Bit m2 = measure(t);  // error[Q0308]: cannot use `measure` inside an `if` on a measurement result
    }
}
```

## 5. 실행 모델

검사기는 실행에 앞서 전체 프로그램을 먼저 검증하므로, 타입 오류나 소유권 오류가 있는 프로그램은 부분 출력을 생성하지 않는다.

전개(elaboration) 단계는 단일 `qxide::Circuit`을 대상으로 `main`을 정확히 한 번 실행하는 트리 워킹 인터프리터다. 큐비트 변수는 풀(pool)에 저장된 실제 `qxide::Qubit` 값을 보유하므로 모든 게이트 호출은 `Circuit::h`, `Circuit::cx` 등 라이브러리 메서드의 직접 호출로 이어지고, `Bit` 조건의 `if`는 `Circuit::if_one`/`if_zero`로, `measure`는 라이브러리의 `Bit` 반환으로 매핑된다. 고전 평가는 검사된 `int` 산술을 사용하므로 오버플로, 0으로 나누기, 범위 초과 인덱스는 소스 위치가 포함된 런타임 오류로 보고된다. 재귀 호출은 허용하되 호출 깊이에 상한을 둔다.

전개 결과는 하나의 회로와 출력 템플릿으로 구성된다. 출력 템플릿은 빌드 순서대로 기록된 `println` 호출의 목록이며, 각 `{}` 자리표시자는 이미 확정된 텍스트(`int`/`boolean`)이거나 `Bit`/`BitReg` 참조다. 이처럼 고전 코드가 양자 프로그램을 구성하는 방식을 단계적(staged) 모델이라 하며, 현재 Rust 코드로 `qxide` 라이브러리를 사용하는 방식과 동일하다.

```text
.qx source ─lexer→ tokens ─parser→ AST ─checker→ checked AST
    ─elaborate (tree-walking interpreter, runs main once)→ qxide::Circuit + output template
        ├─ qxide run   → Circuit::simulate_with(Backend::Auto, seed + k) per shot → render template
        └─ qxide qasm  → Circuit::to_qasm()  (OpenQASM 3)
```

실행, 검증, OpenQASM 3 내보내기는 세 가지 CLI 하위 명령으로 제공된다.

- `qxide run <file.qx> [--shots N] [--seed S]`: 프로그램을 N회 시뮬레이션한다(기본값 1). 각 샷 k는 `Circuit::simulate_shots`를 통해 `Circuit::simulate_with(Backend::Auto, qxide::shot_seed(S, k))`로 실행되므로(기본값 `S = 0`), 클리퍼드(Clifford) 전용 프로그램은 안정화기(stabilizer) 백엔드를, 그 외에는 상태 벡터 백엔드를 사용한다. 이처럼 시드를 파생하면 인접한 시드로 실행하더라도 샷을 공유하지 않는다(0.6.0까지는 `S + k`를 사용했다). N = 1이면 해당 샷의 `println` 출력을 그대로 출력한다. N > 1이면(0.5.0부터) 서로 다른 측정 기록(측정된 모든 비트를 측정 순서대로, 즉 고전 레지스터 `c[0]`부터 나열한 값)마다 한 행씩 `[0, 1, 1]  0b110 = 6  ×503` 형식의 표를 횟수 순으로 정렬해 출력하고, 각 행 아래에 해당 결과에 대한 `println` 출력을 공백 두 칸 들여쓰기로 이어 붙인다(`println` 출력은 측정된 비트에만 의존한다). N = 1이면서 `Bit` 출력이 없거나 측정 자체가 없는 등 샷 결과에 따라 관찰 가능한 출력이 달라지지 않으면 시뮬레이션을 건너뛴다. 메모리 한도 초과 같은 `SimError`는 진단 메시지로 변환한다.
- `qxide qasm <file.qx>`: `Circuit::to_qasm()` 결과를 출력하고 `println`은 무시한다.
- `qxide check <file.qx>`: 렉서, 파서, 검사기만 실행한다. 범위 초과 인덱스 같은 실행 시점 오류는 `run` 또는 `qasm`에서만 발견된다.

`BitReg` 출력 규칙은 12.4절에 정의한다(기본값은 `r[0]`이 먼저 오는 배열 `[0, 1, 1]`, `to_binary()`는 최상위 비트 우선, `as_int()`는 `r[0]`을 최하위 비트로 해석하며 순서 변경 옵션은 두지 않는다). `measure`가 즉시 `boolean`을 반환하는 단계별 실시간 시뮬레이터 대안은 측정에 의존하는 고전 제어 흐름이 단일 샷에 고정되어 OpenQASM 3 내보내기가 불가능해지고, 크레이트에 단계별 시뮬레이터 API도 없어 기각했다. 향후 선택적 모드로 다시 도입할 수 있다.

## 6. 구현 전략 비교

### 안 A: 직접 작성한 프런트엔드와 트리 워킹 인터프리터

렉서, 재귀 하강 파서, 검사기, 그리고 `qxide` 라이브러리를 직접 호출하는 트리 워킹 인터프리터를 직접 구현하는 방식이다.
- **장점**: 외부 의존성이 없고 `run`/`check`/`qasm` 동작까지 가장 빠르게 도달할 수 있다. 줄·열 정보와 오류 코드를 포함한 진단을 완전히 제어할 수 있고, 기존 시뮬레이터와 OpenQASM 3 출력을 그대로 재사용하며, 문법 초안 단계에서 변경 비용이 낮다.
- **단점**: 고전 코드가 인터프리터로 실행되어 네이티브 Rust에 비해 크게 느리므로(실측 수치는 아직 없음) 장기적인 대규모 시뮬레이션 목표에 제약이 된다. 또한 언어의 모든 의미론을 직접 구현해야 한다.

### 안 B: Rust 소스 변환(트랜스파일) 후 `rustc` 컴파일

`.qx` 코드를 `qxide` 크레이트를 사용하는 Rust 소스로 변환한 뒤 `rustc`로 컴파일해 실행하는 방식이다.
- **장점**: 고전 연산이 네이티브 속도로 실행되며, `rustc`의 소유권 검사기로 큐비트 규칙을 그대로 활용할 수 있고, 라이브러리와 1:1로 대응한다.
- **단점**: 사용자 환경에 Rust 툴체인이 필요하고 실행마다 컴파일 지연이 발생한다. `rustc` 오류는 생성된 코드를 가리키므로 양질의 `.qx` 진단을 제공하려면 어차피 자체 검사기가 필요하며, 라이브러리가 아핀 모델인 탓에 선형성 검사도 별도로 구현해야 한다. PyPI나 단일 설치 바이너리로 배포하기도 어렵다.

### 안 C: 자체 타입 중간 표현(IR) 기반 컴파일러

자체 타입 IR로 낮춘 뒤 초기에는 IR 인터프리터로 실행하고, 이후 Cranelift·LLVM 등의 네이티브 코드 생성기와 OpenQASM 3·QIR 같은 양자 타깃을 붙이는 방식이다.
- **장점**: 장기적으로 성능과 최적화 여지가 가장 크고, 고전 영역과 양자 영역의 분리가 명확하다. `entanglement-tracking.md`의 대안 F인 정적 얽힘 분석을 배치하기에도 자연스럽다.
- **단점**: 초기 설계와 구현 비용이 가장 크며, 문법이 확정되지 않은 단계에서는 시기상조다.

### 권장안

현재 단계에서는 **안 A를 채택하되, 향후 안 C로 확장할 수 있는 구조**로 구현한다. 렉서, 파서, AST, 검사기를 인터프리터와 분리해 두면, 이후 프런트엔드를 건드리지 않고 검사된 AST를 IR로 낮추는 단계(`checked AST -> IR`)로 트리 워커를 교체할 수 있다. CPU 비중이 큰 고전 코드에 대해 필요성이 입증되면 안 B를 선택적 백엔드로 추가하는 것도 배제하지 않는다.

- 문법이 아직 초안 단계이므로 변경 비용을 낮게 유지해야 한다.
- 당장 필요한 가치는 명확한 진단 메시지를 갖춘 `check`/`run`/`qasm`의 동작이다.
- 새 의존성을 추가하지 않는 제약과 부합한다.
- MVP의 고전 연산 규모는 회로를 구성하는 수준으로 작으며, 장기적인 대규모 시뮬레이션 목표는 인터프리터 최적화보다 로드맵의 IR 및 네이티브 코드 생성 단계에서 해결하는 편이 타당하다.

## 7. 진단 메시지

모든 진단 메시지는 안정적인 오류 코드, 설명 문구, 주 소스 위치(줄·열 기준, 열은 문자 수로 계산하며 CRLF 줄바꿈을 허용)와 해당 소스 줄 및 캐럿(`^`) 표시, 그리고 필요 시 관련 위치를 가리키는 `note:` 줄(예: 큐비트가 측정된 위치)로 구성되며, 다수의 오류 코드에는 구체적인 수정 제안을 담은 `help:` 줄이 함께 출력된다. 메인테이너 결정(10절)에 따라 메시지는 rustc 스타일(소문자 시작, 마침표 없음)의 영어로 작성한다. 라이브러리의 `SimError` 문구는 한국어이므로 메모리 부족으로 인한 시뮬레이션 오류는 `.qx` 계층에서 영어로 다시 작성하여 보고한다. 테스트는 오류 코드와 소스 위치를 검증하며, 렌더링된 진단에 한글이 포함되지 않는지 확인하는 테스트 하나를 포함한다. 검사기는 첫 오류에서 중단하지 않고 발견할 수 있는 오류를 모두 보고한다. 종료 코드는 성공 `0`, 프로그램 오류(진단 발생) `1`, CLI 사용법 오류 `2`를 사용한다. 아래 오류 코드 대역표에 이어 실제 진단 출력 예시를 제시한다.

| 코드 범위 | 분류 |
| --- | --- |
| `Q01xx` | 렉싱 및 파싱 오류 |
| `Q02xx` | 이름 해석 및 타입 오류 |
| `Q03xx` | 큐비트 소유권 및 `Bit` 조건 `if` 제약 오류 |
| `Q04xx` | 전개 또는 시뮬레이션 중 런타임 오류(오버플로, 0으로 나누기, 인덱스 범위 초과, 런타임 중복 큐비트, 재귀 한도 초과, `SimError`) |

```text
$ qxide check leak.qx
error[Q0302]: qubit `q` is never measured or discarded
 --> leak.qx:2:11
  |
2 |     Qubit q = qubit();
  |           ^
note: goes out of scope here
 --> leak.qx:4:1
  |
4 | }
  | ^
help: call `measure` or `discard` on it before the end of its scope
```

## 8. MVP 이후 확장 계획

아래 코드 스케치는 향후 문법 방향을 고정하기 위한 것으로, 아직 구현되지 않은 기능을 포함한다. `with_ancilla anc { compute } apply { body }`는 `Circuit::with_ancilla`/`with_ancillas`로 낮춰지며, 라이브러리와 동일한 규칙(compute 블록에는 `x`/`cx`/`ccx`만 허용, apply 블록에서는 보조 큐비트와 compute 블록이 건드린 모든 큐비트를 제어 큐비트 또는 대각 위상 용도로만 사용)을 대여 검사기와 런타임 잠금 대신 `.qx` 검사기가 정적으로 검증한다. 큐비트 매개변수(13.1절 참고)와 큐비트를 반환하는 사용자 함수(14.1절 참고)는 모두 구현되었으므로 해당 스케치는 제거하였다.

```rust
// Sketch only (not implemented): scoped uncomputation, lowered to Circuit::with_ancilla
void main() {
    Qubit a = qubit();
    Qubit b = qubit();
    Qubit t = qubit();
    h(a);
    h(b);
    with_ancilla anc {
        ccx(a, b, anc);       // compute: only x / cx / ccx, reads a and b
    } apply {
        cx(anc, t);           // apply: anc, a and b are control-only here
    }
    Bit r = measure(t);
    discard(a);
    discard(b);
}
```

- `with_ancilla` 블록 문법
- 빌드 시점 `while`/`loop`/`break` 제어 흐름
- `Bit` 값에 대한 샷 시점 고전 연산(OpenQASM 3 고전 타입)과 `BitReg`에 대한 `m == 3` 형태의 조건식
- 구조체·모듈 및 `qxide.toml` 패키지 관리(ROADMAP 2단계)
- 검사기 내 정적 얽힘 추적(`entanglement-tracking.md`의 대안 F)
- 대규모 고전 연산을 위한 IR 및 네이티브 코드 생성(6절의 안 C)

3. **타입 명명 규칙** — 결정(2026-11-20): 같은 날 Java 스타일 결정으로 대체되었다. 기본 타입은 Java 스타일 소문자(`int` = 64비트 정수, `double`, `boolean`), 양자 및 복합 타입은 PascalCase(`Qubit`, `Bit`, `QReg`, `BitReg`)를 사용하며 `long`은 생략한다(12.1절). 이전의 `i64`/`bool` 선택은 0.5.0에서 대체되었다.
4. **할당 문법** — 결정(2026-11-20): 이름 앞에 타입을 두는 Java 스타일 선언을 사용하며, 할당은 함수 호출 형태를 유지한다(`Qubit q = qubit();`, `QReg r = qreg(3);`). `var` 타입 추론은 2026-11-20에 고전 타입에 한해 채택·구현되었으며(13.2절 참고), `QReg<3>` 같은 크기 지정 레지스터 타입은 여전히 미결이다.
5. **`measure` 오버로딩** — 미결: `Qubit`과 `QReg` 모두에 오버로딩하는 현재 방식과 별도의 `measure_reg`를 분리하는 방식을 비교 검토한다.
6. **`with_ancilla` 블록 문법** — 미결: 초안의 `with_ancilla anc { ... } apply { ... }` 형태와 Q# 스타일의 `within { } apply { }` 또는 다른 구문을 비교 검토한다.
7. **CLI 명령 이름** — 결정(2026-11-20): `qxide run`/`check`/`qasm`을 유지하며, ROADMAP의 `qxide build` 항목은 `qxide qasm`으로 이름을 변경했다.
8. **`BitReg` 출력 순서** — 결정(2026-11-20): 순서 변경 옵션(`--bit-order` 등)은 두지 않는다. 기본 출력은 `r[0]`이 먼저 오는 배열 `[0, 1, 1]`이며, `to_binary()`는 `0b` 접두사와 함께 최상위 비트부터 출력하고(`0b110`), `as_int()`는 `r[0]`을 최하위 비트로 해석하므로 항상 `to_binary()` 값과 일치한다(`= 6`). 다중 샷 표에서는 두 형식을 모두 표시한다. 자세한 내용은 12.4절에 기록한다.
9. **진단 메시지 언어** — 결정(2026-11-20): 영어를 사용한다. 모든 컴파일러 진단(오류, note, help)과 CLI 메시지를 영어로 출력한다(7절 및 11절 수정 사항 9 참고).
10. **프런트엔드 공개 여부** — 미결: Python 바인딩 등을 위해 `qxide::lang` 모듈을 공개할지, 현재처럼 CLI 내부 비공개로 유지할지 검토한다.
11. **출력 비의존 시 시뮬레이션 생략** — 미결: 출력되는 `Bit`가 없을 때 시뮬레이션을 생략하는 현재 동작과 `SimError`를 드러내기 위해 항상 시뮬레이션을 실행하는 동작을 비교 검토한다.

## 11. 구현 결과 및 설계 수정 사항 (MVP)

> 이 절은 0.4 시점 MVP 구현의 이력 기록으로, 이전 Rust 스타일 문법(`let`, `fn`, `i64`, `bool`)을 기준으로 작성되었다. 현재 문법과 코드 변경 사항은 12절을 참고한다.

6장의 권고(안 A)에 따라 `qx-lang` 브랜치의 커밋 `a052f2b`에서 MVP를 구현하고, 커밋 `d171fa6`에서 리뷰 수정 사항을 반영했다. 구현 코드는 `src/lang/`(`lexer.rs`, `parser.rs`, `ast.rs`, `check.rs`, `interp.rs`, `diag.rs`, `msg.rs`)에 위치하며 `src/main.rs`의 바이너리 전용 모듈로 구성되어 라이브러리 공개 API에는 변경이 없고 의존성도 추가되지 않았다. 이 장에서는 구현된 범위, 3~7장의 설계와 달라진 부분, 전체 오류 코드 목록, 그리고 검증 내역을 기록한다.

### 구현 범위

- **언어**: 1장의 MVP 범위에 명시된 기능을 모두 구현했다. `fn main`과 고전 보조 함수(매개변수와 반환 타입으로 `i64`, `bool`, `Bit`, `BitReg` 지원, 재귀 허용), `let`/`let mut`/대입, `if`/`else if`/`else`, `for i in a..b`, `return`, 함수 결과로서의 말미 표현식, `qubit()`, `qreg(n)`, 게이트 `h`, `x`, `z`, `s`, `sdg`, `t`, `tdg`, `cx`, `ccx`, `reset`, 그리고 `measure`, `discard`, `len`, `println`을 지원한다.
- **CLI**: `qxide run <FILE> [--shots N] [--seed S]`, `qxide check <FILE>`, `qxide qasm <FILE>`을 제공한다. 진단은 표준 오류(stderr)로 출력하며, 종료 코드는 성공 시 0, 프로그램 오류(파일을 읽을 수 없는 경우 포함) 시 1, 명령줄 사용법 오류 시 2를 반환한다.
- **예제**: `examples/qx/bell.qx`, `ghz.qx`, `teleport.qx`를 추가했다.
- **다중 샷 출력**: `--shots N`에서 N > 1이면 `run`은 서로 다른 출력마다 `== count/N ==` 형식의 헤더 아래에 내용을 출력하며, 빈도 내림차순과 텍스트순으로 정렬한다. 출력 예시는 아래 오류 코드 표 다음에 제시한다.
- **안전 한도**: 비정상 입력이 크래시 대신 진단으로 처리되도록 한도를 두었다. 파서 중첩 깊이 128(`Q0106`), 함수 호출 깊이 200(`Q0405`), 누적 할당 큐비트 수 최대 2^20개(`Q0409`)로 제한하며, 인터프리터는 64 MiB 스택을 가진 스레드에서 실행한다. 라이브러리의 스태빌라이저 백엔드 자체에는 메모리 제한이 없으므로(태블로에 약 2·(2n+1)·⌈n/64⌉·8바이트가 필요하다), `qxide run`은 물리 슬롯 수(`measure`로 해제된 슬롯을 재사용하는 라이브러리 동작을 인터프리터가 그대로 반영한다)를 바탕으로 태블로 크기를 추정해 `DEFAULT_MEMORY_LIMIT`(1 GiB)을 초과하면 시뮬레이션 전에 `Q0406`으로 거부한다(예: 200000큐비트 레지스터에는 18.6 GiB가 필요하다). `qxide qasm`은 이 제한의 영향을 받지 않는다. 입력 선두의 UTF-8 바이트 순서 표식(BOM)은 제거하며, 실행 시간에는 별도 한도를 두지 않는다(원칙 5 참고).
- **`discard` 동작**: `discard`는 연산을 방출하지 않으며 슬롯을 라이브러리의 재사용 풀에 반환하지 않는다(라이브러리는 `measure`로 해제된 슬롯만 재사용한다).
- **진단 언어**: 메인테이너 결정(10절 항목 9)에 따라 CLI 메시지와 모든 언어 진단(오류, `note:`, `help:`)을 영어로 출력한다(수정 사항 9 참고).

### 설계 수정 사항

1. **빌드 시점 값 자리에 `Bit`/`BitReg` 사용 (`Q0218`)**: 산술 연산, 비교, `for` 범위, 인덱스, `bool` 위치처럼 빌드 시점에 결정되어야 하는 자리에 `Bit`/`BitReg`를 사용하면 4장 초안의 일반 타입 불일치(`Q0204`) 대신 전용 코드 `Q0218`을 보고한다. 오류 메시지는 측정 결과가 샷마다 결정된다는 점을 안내하며, 4장의 내용도 이에 맞게 수정했다.
2. **렉서·파서의 첫 구문 오류 중단**: 모든 오류를 한꺼번에 보고하는 단계는 검사기뿐이다. 파서에 아직 오류 복구 기능이 없으므로 렉서와 파서는 첫 번째 구문 오류(`Q01xx`)에서 중단한다.
3. **양자 값 오용에 대한 세분화된 오류 코드**: 양자 값이 허용되지 않는 위치에 사용된 일부 사례는 `Q0204` 대신 전용 코드를 부여한다. 큐비트를 출력하면 `Q0212`, `Qubit`/`QReg`를 매개변수나 반환 타입으로 쓰는 함수는 `Q0219`를 보고하며, 4장의 규칙 7도 이에 맞게 수정했다.
4. **게이트 피연산자 제한 (`Q0311`)**: 게이트 피연산자는 큐비트 변수나 레지스터 원소여야 하므로 새 코드 `Q0311`을 추가했다. `h(qubit())`는 새로 만든 큐비트가 유실되므로 거부하지만, `measure(qubit())`와 `discard(qreg(3))`는 임시 값을 바로 소비하므로 허용한다.
5. **`Bit` 조건 `if` 내부 `return`의 연쇄 오류 억제**: `Bit` 조건의 `if` 블록 안에 `return`이 있으면 `Q0308`만 보고한다. 하나의 실수가 후속 오류를 만들지 않도록 해당 `return`에 대해서는 큐비트 누수 분석을 건너뛴다.
6. **`bool` 조건 `if`의 발산 분기와 `for` 본문 처리**: `bool` 조건 `if`에서 항상 `return`으로 끝나는 분기는 Rust의 발산 규칙처럼 다른 분기와 큐비트 소비 상태를 맞출 필요가 없어, 예를 들어 `if c { discard(q); return; } discard(q);`는 허용된다. 반면 `for` 본문에서 바깥 큐비트를 소비하는 경우는 루프가 0회 실행될 수도 있으므로 여전히 거부되며, 해당 큐비트는 누수(`Q0302`)로도 함께 보고된다.
7. **런타임 중복 피연산자 코드 재사용 및 미할당 코드**: i == j인 `cx(r[i], r[j])` 같은 런타임 중복 피연산자 오류는 별도 코드를 쓰지 않고 `Q0303`을 재사용한다. 이에 따라 계획했던 별도 런타임 코드는 사용하지 않으며 `Q0208`, `Q0216`, `Q0404`는 미할당 상태로 남겼다.
8. **미소비 임시 큐비트·레지스터 거부(`Q0312`)**: 리뷰에서 확인된 선형성 허점을 메우기 위해, 생성 후 변수에 바인딩되거나 소비되지 않는 큐비트·레지스터(문장으로 사용된 `qubit();`·`qreg(3);`, `len(qreg(3))`, `qreg(2)[0]`)가 첫 구현에서 조용히 버려지던 문제를 수정하고 이제 `Q0312`로 거부한다. 다만 임시 값을 직접 소비하는 `measure(qubit())`와 `discard(qreg(3))`는 계속 허용한다.
9. **진단 메시지 영어 전환 및 `help:` 줄 추가**: 2026-11-20 메인테이너 결정에 따라 모든 진단 메시지를 한국어에서 rustc 스타일 영어로 전환하고, 오류 코드별 수정 제안을 담은 `help:` 줄을 추가했다(예: `Q0302`는 `measure` 또는 `discard`를, 연쇄 비교 오류인 `Q0105`는 `&&` 사용을 제안한다). 라이브러리의 한국어 메모리 부족 `SimError` 문구는 영어로 다시 작성하여 `Q0406`으로 출력하며, 렌더링된 진단에 한글이 포함되지 않고 `help:` 줄이 표시되는지 확인하는 단위 테스트를 추가했다. 오류 코드와 소스 위치는 변경되지 않았다.

## 12. 0.5.0 문법 개정(Java 스타일 선언), 비트 출력, 포지셔닝 및 네이티브 코드 로드맵

2026-11-20에 메인테이너는 Java 스타일 표면 문법, 고정된 비트 출력 형식, 언어 포지셔닝, 네이티브 코드 로드맵을 결정했다. 이 절은 해당 결정 사항과 0.4 시점 문법에서의 마이그레이션 내용을 기록한다. 이 변경 사항은 버전 0.5.0에 포함되어 있으며, 작성 시점 기준으로 준비 완료되었으나 아직 배포되지 않았다.

### 12.1 Java 스타일 선언과 타입

- Java와 같이 변수 이름 앞에 타입을 쓴다(`int x = 1;`, `Qubit q = qubit();`, `Bit m = measure(q);`). 초기화식은 필수이며 `int x;` 같은 미초기화 선언은 허용하지 않는다.
- 함수는 반환 타입을 앞에 쓰고(`void main()`, `int add(int a, int b)`), 값 반환은 `return` 문으로만 수행한다(마지막 표현식 반환은 제거되었다).
- 지역 변수는 기본적으로 가변이며, `final`을 붙이면 불변이 된다. `final` 변수에 재할당하면 `Q0207` 오류가 발생한다.
- 기본 타입은 `int`(64비트 부호 있는 정수, 오버플로 시 `Q0401` 오류), `double`(64비트 IEEE 754 부동소수점, 0으로 나누면 오류가 아니라 Java와 같이 무한대 또는 NaN 반환), `boolean`이며, `void`는 함수 반환 타입으로만 사용할 수 있다. 양자 및 복합 타입은 PascalCase(`Qubit`, `QReg`, `Bit`, `BitReg`)를 사용한다.
- `int`는 대입, 인자, 반환값, 산술 연산에서 `double`로 암묵적 확장 변환된다. 반대 방향 변환은 Java식 명시적 캐스트 `(int) x`를 사용하며 0 방향으로 절사한다(13.3절 참고). 새로 추가된 `rx`, `ry`, `rz` 게이트는 각도 인자로 `double`을 받는다.
- 제어 흐름은 기존과 동일하다(괄호 없는 `if`, `for i in a..b`).
- 제거된 `let`, `fn`, `mut` 키워드를 사용하면 새 형식을 안내하는 도움말과 함께 `Q0110` 오류가 발생한다.

아래는 0.5.0 문법으로 작성한 예제이다.

```java
// .qx 0.5.0
int add(int a, int b) {
    return a + b;
}

void main() {
    final int n = 3;
    double theta = 0.5;
    Qubit q = qubit();
    rx(q, theta);
    Bit m = measure(q);
    println("{} {}", add(n, 4), m);
}
```

`long`을 생략한 이유는 `int`가 이미 64비트(Java의 `long`과 같은 너비)이기 때문이다. 인터프리터와 qxide 라이브러리 모두 64비트 정수를 사용하므로 별도의 정수 타입을 두어도 쓰임새 없이 변환만 늘어난다. 더 좁은 정수 타입이 필요해지면 그때 함께 추가할 수 있다. 현재 `long`을 쓰면 사용 가능한 타입 목록을 안내하는 도움말과 함께 알 수 없는 타입 오류(`Q0108`)로 거부된다.

### 12.2 0.4.x에서의 마이그레이션 안내

아래 표는 0.4.x 문법과 0.5.0 문법의 대응 관계를 정리한 것이다.

| 0.4.x (MVP) | 0.5.0 |
| --- | --- |
| `fn main() { ... }` | `void main() { ... }` |
| `fn add(a: i64, b: i64) -> i64 { a + b }` | `int add(int a, int b) { return a + b; }` |
| `let x = 1;` / `let mut x = 1;` | `final int x = 1;` / `int x = 1;` |
| `let q = qubit();` | `Qubit q = qubit();` |
| `let r = qreg(3);` | `QReg r = qreg(3);` |
| `let m = measure(q);` | `Bit m = measure(q);` |
| `let bits = measure(r);` | `BitReg bits = measure(r);` |
| `i64`, `bool` | `int`, `boolean` |
| `println("{}", bits)` → `011` | `println("{}", bits)` → `[0, 1, 1]` |

- `fn` 함수 선언 헤더를 반환 타입이 앞에 오는 형식으로 바꾼다.
- `let`과 `let mut` 선언을 타입이 명시된 선언으로 바꾼다(일반 선언은 이제 기본 가변이므로 불변을 유지해야 하는 변수에는 `final`을 붙인다).
- 함수 끝의 마지막 표현식 반환을 `return ...;` 문으로 바꾼다.
- `qxide check`를 실행하면 제거된 각 키워드에 대해 새 형식을 안내하는 `Q0110` 오류가 보고된다.
- `qxide run`의 다중 샷 출력이 12.4절의 표 형식으로 바뀌었으므로, 기존의 `== n/N ==` 헤더를 파싱하던 스크립트를 함께 수정해야 한다.
- 자동 마이그레이션 도구는 아직 제공하지 않는다.

### 12.3 `var`를 통한 타입 추론(채택·구현됨)

Java 10의 지역 변수 타입 추론과 마찬가지로 지역 변수에 한해 `var x = expr;`를 허용해 초기화식의 타입을 추론하고, 함수 매개변수와 반환 타입에는 명시적 타입을 계속 요구하는 방안이다. 다만 `.qx`에서는 변수의 타입이 소유권과 실행 시점 규칙을 결정하므로(`Qubit`은 선형 타입이고 `Bit`는 샷 시점 값이다) 신중하게 접근해야 한다. 명시적 타입은 이러한 규칙을 선언 지점에서 바로 드러내지만, `var q = qubit();`처럼 쓰면 `q`를 반드시 소비해야 한다는 사실이 가려진다.

- 후보 규칙 1: 고전 값(`int`, `double`, `boolean`)에만 `var`를 허용하고 `Qubit`, `QReg`, `Bit`, `BitReg`에는 명시적 타입을 요구한다.
- 후보 규칙 2: 모든 지역 변수에 `var`를 허용하되, 진단 메시지에 추론된 타입을 명시한다.
- 결정(2026-11-20): 메인테이너가 후보 규칙 1을 채택해 구현했다(세부 규칙은 13.2절 참고).

### 12.4 측정 결과 출력

아래는 `r[1]`을 중첩 상태에 두고 `r[2]`를 1로 설정한 3큐비트 레지스터 예제 프로그램과 실제 실행 출력이다.

```java
void main() {
    QReg r = qreg(3);
    h(r[1]);
    x(r[2]);
    BitReg m = measure(r);
    println("{}  {}  {}", m, m.to_binary(), m.as_int());
}
```

```text
$ qxide run bits.qx
[0, 1, 1]  0b110  6
$ qxide run bits.qx --shots 1000
[0, 1, 1]  0b110 = 6  ×521
  [0, 1, 1]  0b110  6
[0, 0, 1]  0b100 = 4  ×479
  [0, 0, 1]  0b100  4
```

- `BitReg`에 `{}`를 사용하면 `r[0]`이 먼저 오는 레지스터 순서의 배열로 출력한다(`[0, 1, 1]`).
- `r.to_binary()`는 `0b` 접두사 뒤에 최상위 인덱스부터 `r[0]`까지 레지스터 너비에 맞춰 0으로 채워 출력한다(`0b110`, 빈 레지스터는 `0b0`).
- `r.as_int()`는 `r[0]`을 최하위 비트로 해석하므로 이진 표현과 항상 같은 값을 가진다(`0b110` = 6). 최대 64비트까지 지원하며 초과 시 `Q0410` 오류가 발생한다.
- 두 메서드는 출력 전용 샷 시점 뷰(view)로, 변수에 저장하려 하면 `Q0218` 오류가, 그 외의 메서드를 호출하면 `Q0220` 오류가 발생한다.
- 단일 `Bit`는 `0` 또는 `1`로 출력되며, `--bit-order` 같은 비트 순서 변경 옵션은 의도적으로 두지 않는다.

다중 샷 표에서는 측정된 모든 비트를 순서대로(`c[0]` 우선) 기록한 결과를 배열·이진수·정수와 횟수로 한 행에 표시하고(`[0, 1, 1]  0b110 = 6  ×521`) 그 아래에 해당 결과의 `println` 출력을 공백 두 칸 들여쓰기로 이어 붙이며, 예제의 횟수는 기본 시드로 실제 실행한 한 번의 결과로 `--seed` 값에 따라 달라진다.

### 12.5 포지셔닝

메인테이너가 결정한 언어 포지셔닝은 세 가지 축으로 정리된다. 첫째, 타입 선언, 반환 타입 우선 표기, `final`, `int`/`double`/`boolean` 등 Java와 C 개발자에게 익숙한 문법을 제공한다. 둘째, 선형 큐비트, 측정 후 사용 금지, 게이트 피연산자 중복 금지 같은 양자 자원 소유권 규칙을 실행 전에 검사하는 Rust 수준의 컴파일 시점 안전성을 유지한다. 셋째, 장기 목표로 고전 코드에 대해 컴파일을 통한 네이티브 수준의 실행을 지향한다(12.6절).

현재 언어는 트리 순회 인터프리터로 실행되며, 성능은 아직 측정되지 않았으므로 벤치마크가 마련되기 전까지는 어떤 성능 주장도 하지 않는다. 한편 `Cargo.toml`과 `pyproject.toml`의 패키지 설명에 남아 있던 'Rust-like' 문구는 커밋 `dfe5b78`에서 C 스타일 문법, Rust 소유권과 같은 컴파일 시점 큐비트 안전성, OpenQASM 3 출력을 설명하는 문구로 교체되어 이 항목은 종결되었다.

### 12.6 인터프리터에서 IR, 네이티브 코드 생성까지의 로드맵

현재는 검사를 마친 AST를 트리 순회 인터프리터가 해석하면서 `qxide::Circuit`을 구성한다. 고전 코드는 인터프리터에서 직접 실행되고, 양자 코드는 라이브러리 회로와 OpenQASM 3으로 하향 변환(lowering)된다.

목표 구조는 검사된 AST를 빌드 시점 고전 코드, 측정 결과에 대한 샷 시점 고전 코드, 양자 연산으로 분리된 타입 포함 IR로 하향 변환하는 것이다. 먼저 이 IR을 인터프리터로 실행하고, 이어서 고전 코드 부분에 대한 네이티브 코드를 생성한다. 아래 표는 두 후보 백엔드를 비교한 것으로, 아직 측정된 수치는 없으며 각 프로젝트의 문서화된 범위에 기반한 정성적 비교이다.

| 항목 | Cranelift | LLVM |
| --- | --- | --- |
| 의존성 및 빌드 | Wasmtime/Bytecode Alliance 프로젝트의 순수 Rust 크레이트로, Cargo만으로 추가되며 별도 시스템 툴체인이 필요 없다. | 대규모 C++ 라이브러리로, `inkwell` 같은 Rust 바인딩이 특정 LLVM 버전에 종속되어 설치 또는 번들이 필요하며 cargo-dist 및 PyPI 빌드를 복잡하게 만든다. |
| 컴파일 속도 | 빠른 코드 생성을 목표로 설계되었다(Wasmtime의 JIT 및 rustc 디버그 빌드용 대체 백엔드로 사용된다). | 특히 최적화를 활성화할 경우 코드 생성 속도가 상대적으로 느리다. |
| 생성 코드 최적화 수준 | 최적화 패스가 적어 생성 코드가 일반적으로 LLVM의 최적화 출력보다 느릴 것으로 예상된다(qxide 워크로드에 대한 실측 필요). | 인라이닝, 벡터화, 루프 최적화 등 성숙한 최적화 파이프라인을 제공한다. |
| 지원 타깃 | x86-64, AArch64 등 주요 64비트 타깃과 JIT 및 오브젝트 파일 출력을 지원한다. | 매우 폭넓은 CPU 타깃을 지원하며 NVPTX, AMDGPU 같은 GPU 타깃도 존재한다. |
| 양자 툴체인과의 연계 | 없음. 양자 출력은 라이브러리가 생성하는 OpenQASM 3을 그대로 사용한다. | QIR(Quantum Intermediate Representation)이 LLVM IR 위에 정의되어 있으므로, QIR을 지원하는 하드웨어 툴체인용 출력을 함께 생성할 수 있다. |

1. 타입 포함 IR과 IR 인터프리터를 구현해 현재 결과를 그대로 재현한다. 기존 테스트와 예제가 모두 통과하고 OpenQASM 3 출력이 바이트 단위로 동일해야 한다.
2. 최적화를 시작하기 전에 벤치마크 모음을 먼저 구축한다. 반복문·재귀 등 고전 연산 비중이 높은 프로그램과 대규모 레지스터 회로 구성을 포함해 이후의 판단이 실측에 근거하도록 한다.
3. 첫 번째 네이티브 백엔드로 빌드 시점 고전 코드용 Cranelift JIT을 도입한다. 순수 Rust 구성이므로 설치와 배포를 단순하게 유지할 수 있다.
4. 최적화 수준이 중요한 AOT 빌드와 QIR 출력을 위해 LLVM 백엔드를 추후 평가한다. 무거운 의존성에 대한 기존 원칙에 따라 기본값이 꺼진 Cargo feature 뒤에 둔다.
5. 측정 결과에 대한 샷 시점 고전 연산은 OpenQASM 3 고전 코드(도입 시 QIR 포함)로 하향 변환한다.

권고 방향은 Cranelift로 먼저 시작하고 LLVM은 선택 기능으로 두며, 벤치마크가 확보된 뒤 방향을 재검토하는 것이다.

## 13. 큐비트 매개변수, `var`, 캐스트 및 `PI` (2026-11-20 결정)

이 절은 2026-11-20에 메인테이너가 결정하고 `src/lang/`에 구현한 네 가지 언어 기능을 정리한다. 이 기능들은 `main` 브랜치에 반영되어 있으며 아직 릴리스되지 않았다. 바이너리 전용 모듈로만 유지하고 공개 라이브러리 API를 변경하지 않으며 새 외부 의존성을 추가하지 않는 기존 설계 원칙은 그대로 유지된다.

### 13.1 큐비트 매개변수: 대여와 `consume`

아래 예제는 `examples/qx/functions.qx`로, `bellPair`가 두 큐비트를 대여해 게이트만 적용하고 `measureAll`이 `consume`으로 레지스터의 소유권을 넘겨받아 측정하므로 `main`에서 `r`을 직접 측정하지 않는다. 실행 결과는 `examples/qx/bell.qx`와 동일한 Bell 상관을 보이며, 측정 횟수 분포는 `--seed` 값에 따라 달라진다.

```java
// examples/qx/functions.qx
void bellPair(Qubit a, Qubit b) {
    h(a);
    cx(a, b);
}

void measureAll(consume QReg r) {
    BitReg m = measure(r);
    println("{}", m);
}

void main() {
    QReg r = qreg(2);
    bellPair(r[0], r[1]);
    measureAll(r);
}
```

```text
$ qxide run examples/qx/functions.qx --shots 1000
[1, 1]  0b11 = 3  ×521
  [1, 1]
[0, 0]  0b00 = 0  ×479
  [0, 0]
```

- **기본 대여**: `Qubit` 또는 `QReg` 매개변수는 기본적으로 대여된다. 함수는 대여받은 값에 게이트와 `reset`을 적용하거나, 다른 대여 매개변수로 넘기거나, 대여받은 `QReg`를 인덱싱할 수 있다. 반대로 이를 측정·폐기하거나 이동(`Qubit p = q;`)하거나 `consume` 매개변수로 넘기면 오류 `Q0313`이 발생하며, 호출자는 여전히 소유권을 가지므로 직접 측정하거나 폐기해야 한다.
- **`consume` 소유권 이동**: 매개변수 타입 앞에 `consume` 키워드를 붙이면(`void measureAll(consume QReg r)`) 소유권이 함수로 이동한다. 호출 이후 호출자는 해당 값을 다시 사용할 수 없으며(`Q0301`), 피호출 함수는 모든 실행 경로에서 그 값을 측정하거나 폐기해야 한다(`Q0302`).
- **인자 형태 제한**: 대여 매개변수에는 `Qubit`/`QReg` 변수나 `r[i]` 같은 레지스터 원소만 넘길 수 있으며 `qubit()` 같은 새 값은 `Q0311` 오류다. `consume` 매개변수에는 변수 전체나 `qreg(2)` 같은 새 값을 넘길 수 있지만 `r[i]` 같은 단일 레지스터 원소는 넘길 수 없다(`Q0306`).
- **중복(별칭) 금지**: 한 번의 함수 호출에 동일한 큐비트가 두 번 이상 나타날 수 없으며, 레지스터 전체는 자신의 각 원소와 겹치는 것으로 간주한다(`Q0303`). 실행 시점에 결정되는 인덱스는 호출이 실행될 때 검사하며 위반 시 동일하게 `Q0303`을 보고한다.
- **반복문 안 소비 금지**: 반복문 바깥에서 선언된 큐비트를 반복문 본문 안에서 `consume` 매개변수로 넘기는 것은 `measure`와 마찬가지로 금지된다(`Q0305`). 반면 반복문 본문 안에서 할당된 큐비트는 넘길 수 있다.
- **고전 매개변수 `consume` 금지**: 고전 타입 매개변수에 `consume`을 붙이면 오류 `Q0221`이 발생한다.
- **기타 제한**: 작성 당시에는 `Qubit`이나 `QReg`를 반환하는 함수(`Q0219`)와 `Bit` 조건의 `if` 블록 안에서의 사용자 함수 호출(`Q0308`)이 제한되었으나, 이후 두 제한 모두 해제되어 `Qubit`/`QReg` 반환 함수(14.1절 참고)와 게이트만 적용하는 함수의 조건부 호출(14.2절 참고, 조건부 실행 불가 함수는 `Q0314`)이 지원된다.

아래 예제는 대여받은 매개변수를 함수 안에서 측정할 때 `Q0313` 오류가 보고되는 경우를 보여 준다.

```java
void f(Qubit q) {
    Bit m = measure(q);
}
```

```text
error[Q0313]: cannot consume borrowed parameter `q`
 --> t.qx:2:21
  |
2 |     Bit m = measure(q);
  |                     ^
note: borrowed here without `consume`
 --> t.qx:1:14
  |
1 | void f(Qubit q) {
  |              ^
help: add `consume` before the parameter type, such as `void f(consume Qubit q)`, to take ownership and become responsible for measuring or discarding it
```

대여를 기본값으로 택한 이유는 게이트 메서드가 `&mut Qubit`을 받고 `measure`가 `Qubit`을 값으로 소비하는 `qxide` 라이브러리 설계와 일치하며, 가장 흔한 게이트 서브루틴 작성 시 별도 키워드를 쓰지 않아도 되기 때문이다. 사용자 함수 호출은 인터프리터가 실행하므로 생성되는 회로는 게이트를 인라인으로 작성한 것과 동일하다. 실제로 대여 기반 `bellPair` 함수로 작성한 Bell 예제의 OpenQASM 3 출력은 인라인 버전과 바이트 단위로 동일함을 확인했다.

### 13.2 `var` 지역 변수 타입 추론

아래 예제는 초기화식의 타입에 따라 `var`가 `int`, `double`, `boolean`을 추론하는 방식을 보여 준다.

```java
var steps = 4;           // int
var angle = PI / steps;  // double
final var big = steps > 2;
var q = qubit();         // error[Q0222]: write `Qubit q = qubit();`
```

- **사용 위치와 초기화식 필수**: Java 10의 지역 변수 타입 추론과 동일하게 초기화식이 있는 지역 변수 선언에서만 사용할 수 있다. 초기화식 없는 `var x;`는 문법 오류 `Q0105`이며, 매개변수나 반환 타입에 `var`를 쓰면 오류 `Q0111`이 발생한다.
- **허용 타입 제한**: 초기화식의 타입이 `int`, `double`, `boolean`일 때만 허용된다(12.3절 후보 규칙 1 채택). `Qubit`, `QReg`, `Bit`, `BitReg`, `to_binary()`/`as_int()` 뷰, `void`에 `var`를 사용하면 오류 `Q0222`가 발생하는데, 선형 소유권이나 샷 시점 값처럼 실행 규칙이 다른 타입은 선언 지점에 명시적으로 드러내야 하기 때문이다.
- **고정된 추론 타입과 `final var`**: 한 번 추론된 타입은 고정되므로 `var n = 1; n = 2.5;`처럼 다른 타입을 대입하면 `Q0204` 오류가 발생한다. 불변 선언인 `final var`도 허용된다.
- **정식 키워드**: `var`는 새로운 키워드로 승격되어 더 이상 변수·매개변수·함수 이름으로 사용할 수 없다.

### 13.3 `int`와 `double` 간 캐스트

아래 예제는 Java식 캐스트 `(int) x`와 `(double) n`의 사용법을 보여 준다.

```java
double x = 2.9;
int a = (int) x;          // 2
int b = (int) -x;         // -2
double half = (double) 7 / 2; // 3.5
int c = (int) x * 2;      // 4: the cast binds tighter than `*`
```

- **연산자 우선순위**: 캐스트는 단항 연산자와 같은 우선순위로 결합한다(`*`보다 강하고 인덱싱·메서드 호출보다 약하다). 따라서 `(int) x * 2`는 `((int) x) * 2`로 해석되고 `(int) -x`는 부정 연산 결과를 캐스트한다.
- **허용되는 변환**: `int`와 `double` 사이의 변환만 허용하며 동일 타입 캐스트도 허용한다. `(boolean) 1`이나 `(int) true`처럼 허용되지 않은 캐스트는 오류 `Q0223`이며, 측정 결과인 `Bit`를 캐스트하면 오류 `Q0218`이 발생한다.
- **절사와 경계값 규칙**: `double`에서 `int`로의 변환은 0 방향으로 절사하며(`(int) 2.9`는 `2`, `(int) -2.9`는 `-2`), `.qx`의 `int`가 64비트 정수이므로 Java의 `long` 캐스트 규칙을 그대로 따른다. `NaN`은 `0`이 되고 범위를 벗어난 값은 `int` 최솟값 또는 최댓값으로 포화되며, 검사 산술(`Q0401`)과 달리 런타임 오류를 발생시키지 않는다.
- **타입 이름의 식별자 사용 금지**: `(int) x`가 괄호로 감싼 변수 표현식과 모호해지지 않도록 타입 이름(`int`, `double`, `boolean`, `void`, `Bit`, `BitReg`, `Qubit`, `QReg`)은 더 이상 변수·매개변수·함수 이름으로 사용할 수 없다(`Q0112`).

### 13.4 `PI` 상수

`PI`는 Rust의 `std::f64::consts::PI`(3.141592653589793)와 같은 값을 갖는 내장 `double` 상수로, `rz(q, PI / 2)` 같은 회전 각도를 포함해 표현식이 올 수 있는 어디에서나 사용할 수 있다. `PI`라는 이름으로 변수·매개변수·`for` 변수·함수를 선언하면 오류 `Q0217`이 발생하고, `PI = 3.0;`처럼 대입하면 지역 변수 사용을 안내하는 도움말과 함께 오류 `Q0207`이 보고된다. 현재 `E`, `TAU` 등 다른 수학 상수는 제공하지 않는다. 아래 `examples/qx/rotation.qx` 예제는 큐비트를 `ry`로 `PI / 8`씩 네 단계에 걸쳐 총 `PI / 2` 회전한 뒤, 총 각도를 도(degree) 단위(90)로 환산해 `double` 값과 `(int)`로 절사한 값을 나란히 출력한다.

```java
// examples/qx/rotation.qx
void main() {
    var steps = 4;
    var angle = PI / 2 / steps;
    Qubit q = qubit();
    for i in 0..steps {
        ry(q, angle);
    }
    Bit m = measure(q);
    var degrees = angle * steps * 180 / PI;
    println("ry total {} degrees ({}), m={}", (int) degrees, degrees, m);
}
```

```text
$ qxide run examples/qx/rotation.qx
ry total 90 degrees (90.0), m=0
```

## 14. 큐비트 반환 함수와 측정 결과 `if` 안의 함수 호출 (2026-11-20)

이 절은 2026-11-20에 메인테이너 요청으로 구현되어 13.6절의 남은 제한 두 가지를 해소한 기능을 기록한다. 현재 `main` 브랜치에만 반영된 미릴리스 상태이며, 바이너리 전용 모듈 변경만으로 구현되어 라이브러리 API 변경이나 새 의존성 추가는 없다.

### 14.1 `Qubit`과 `QReg`를 반환하는 함수

아래 예제의 `ghz` 함수는 레지스터를 할당해 얽힘 상태로 만든 뒤 호출자에게 반환하며, `main`은 반환된 레지스터의 소유권을 받아 측정한다. 실행 결과는 GHZ 상태의 상관관계를 보이며, 세부 관측 횟수는 `--seed` 값에 따라 달라진다.

```java
QReg ghz(int n) {
    QReg r = qreg(n);
    h(r[0]);
    for i in 1..n {
        cx(r[0], r[i]);
    }
    return r;
}

void main() {
    QReg r = ghz(3);
    BitReg m = measure(r);
    println("{}", m);
}
```

```text
$ qxide run ghz_fn.qx --shots 1000
[1, 1, 1]  0b111 = 7  ×521
  [1, 1, 1]
[0, 0, 0]  0b000 = 0  ×479
  [0, 0, 0]
```

- **소유권 반환과 오류**: `Qubit`이나 `QReg`를 반환하는 함수에서 `return e;`는 값의 소유권을 호출자에게 이동한다. `e`에는 함수가 소유한 변수(이 `return` 지점에서 소비됨)나 `qubit()` 같은 새 할당 값을 쓸 수 있으며, 대여 매개변수를 반환하면 `Q0313`, 레지스터의 단일 원소 `r[i]`를 반환하면 `Q0306`, 고전 값을 반환하면 `Q0204`, 반환문이 누락되면 `Q0213`이 보고된다.
- **미반환 큐비트 누수 검사**: `return` 시점이나 함수 끝에 함수가 여전히 소유하고 있는 다른 큐비트가 남아 있으면 기존과 동일하게 `Q0302`로 보고된다.
- **`consume` 매개변수 통과 반환**: `consume` 매개변수는 함수가 소유권을 가지므로 `Qubit hadamard(consume Qubit q) { h(q); return q; }`처럼 게이트를 적용한 뒤 호출자에게 다시 반환해 소유권을 통과시킬 수 있다.
- **호출자의 결과 처리**: 호출자는 반환된 `Qubit`/`QReg`를 새로 할당한 큐비트와 동일하게 취급해 변수에 저장한 뒤 측정하거나 폐기해야 한다. 끝까지 소비하지 않으면 `Q0302`, 소비 후 재사용하면 `Q0301`, `make();`처럼 반환값을 버리면 `Q0312`, `h(make())`처럼 게이트에 직접 넘기면 `Q0311`이 보고되며, `measure(make())`나 `consume` 매개변수에 직접 전달하는 것은 허용된다.
- **인라인과 동일한 회로**: 인터프리터가 호출을 실행하므로 생성되는 회로는 코드를 인라인으로 작성한 경우와 같다. 실제로 `QReg ghz(int n)`으로 구성한 GHZ 회로의 OpenQASM 3 출력은 `examples/qx/ghz.qx`와 바이트 단위로 동일하다.

아래 오류 예제는 함수가 소유한 큐비트 중 하나를 반환하지 않고 남겨 두어 `Q0302`가 발생하는 경우를 보여준다.

```java
Qubit make() {
    Qubit a = qubit();
    Qubit b = qubit();
    h(a);
    return a;
}
```


### 14.2 측정 결과 `if` 안에서의 사용자 함수 호출

아래 발췌는 텔레포테이션의 보정 연산을 대여 큐비트 함수로 분리해 `if m1`과 `if m0` 블록 안에서 호출하는 예와 그 OpenQASM 3 출력이다. 생성된 OpenQASM 3 출력은 `examples/qx/teleport.qx`와 바이트 단위로 동일하다.

```java
// examples/qx/teleport_fn.qx (excerpt)
void correctX(Qubit q) {
    x(q);
}

void correctZ(Qubit q) {
    z(q);
}

    // in main, after measuring msg (m0) and alice (m1)
    if m1 {
        correctX(bob);
    }
    if m0 {
        correctZ(bob);
    }
```

```text
$ qxide qasm examples/qx/teleport_fn.qx
...
c[0] = measure q[0];
c[1] = measure q[1];
if (c[1] == true) {
  x q[2];
}
if (c[0] == true) {
  z q[2];
}
c[2] = measure q[2];
```

- **허용되는 호출 형태**: 대여 큐비트 매개변수를 받아 게이트와 `reset`을 적용하는 사용자 함수는 `Bit` 조건의 `if`와 `else` 블록 안에서 호출할 수 있으며, `Bit` 매개변수에 대한 중첩 `if`, 반복문, 회전 게이트, 재귀 호출, `int`를 반환하는 고전 보조 함수도 함께 사용할 수 있다. 인터프리터가 조건부 블록(`Circuit::if_one`/`if_zero`)을 기록하는 동안 호출을 실행하므로 출력 회로는 게이트를 인라인으로 작성한 경우와 동일하다.
- **조건부 실행 불가 함수**: 다음 중 하나에 해당하는 함수는 조건부 블록 안에서 호출할 수 없다. (1) `consume` 매개변수를 가진 함수(일부 샷에서만 호출자의 큐비트를 소비하게 됨), (2) `Qubit`/`QReg`를 반환하는 함수(조건부 블록 안에서 큐비트를 생성하게 됨), (3) 본문 어디서든 `qubit`, `qreg`, `measure`, `discard`, `println`을 사용하는 함수, (4) 이러한 함수를 호출하는 함수.
- **호출 그래프 기반 고정점 분석**: 검사기는 호출 그래프 전체에 대해 고정점(fixpoint)을 계산하여 재귀 함수까지 포함해 조건부 실행 가능 여부를 판정한다. 이 분석은 보수적으로 동작하므로 빌드 시점에 실행되지 않는 분기 안에 금지 연산이 있어도 조건부 실행 불가로 간주한다.
- **`Q0314` 진단 구성**: 조건부 실행이 불가능한 함수를 `Bit` 조건의 `if` 안에서 호출하면 새 오류 `Q0314`가 보고된다. 진단 메시지에는 구체적 원인(`consume` 매개변수, 반환 타입, 금지 연산 또는 내부 호출)을 가리키는 노트, 조건식을 가리키는 노트, 그리고 도움말 한 줄이 함께 제공된다.
- **직접 사용 규칙 유지**: `if` 본문 안에 직접 작성한 `measure`, `discard`, `qubit()`/`qreg()`, `println`, `return`, 양자 변수 선언은 계속 `Q0308`로 보고되며, 이미 `Q0314`로 보고된 호출로 초기화되는 양자 변수 선언은 중복 보고하지 않는다. 바깥 변수의 재대입 역시 기존대로 `Q0309`이다.
- **검증 예제**: `examples/qx/teleport_fn.qx`는 `examples/qx/teleport.qx`와 OpenQASM 3 출력이 바이트 단위로 동일하며, `else` 분기·중첩 조건문·반복문 안 회전 게이트·고전 보조 함수를 포함한 `examples/qx/conditional_fn.qx` 역시 인라인 버전과 동일한 출력을 생성하고 두 출력 모두 Qiskit 파서로 검증되었다.

아래 오류 예제는 `consume` 매개변수를 가진 함수를 측정 결과 `if` 블록 안에서 호출해 `Q0314`가 발생하는 경우를 보여준다.

```java
void eat(consume Qubit q) {
    discard(q);
}
void main() {
    Qubit a = qubit();
    Bit m = measure(a);
    Qubit t = qubit();
    if m {
        eat(t);
    }
}
```

```text
error[Q0314]: cannot call function `eat` inside an `if` on a measurement result
 --> t.qx:9:9
  |
9 |         eat(t);
  |         ^^^^^^
note: parameter `q` takes ownership via `consume`, which a conditional call cannot do
 --> t.qx:1:24
  |
1 | void eat(consume Qubit q) {
  |                        ^
note: condition is a measurement result
 --> t.qx:8:8
  |
8 |     if m {
  |        ^
help: a function called inside an `if` on a measurement result may only apply gates and `reset` to borrowed qubits, so it cannot allocate, measure, discard, print, take a `consume` parameter, or return a qubit; call it before or after the `if`
```

qxide 라이브러리 자체는 분기 안의 `measure`만 거부해 패닉을 일으키며, 큐비트 할당과 `discard`, `println`을 조건부 블록 밖에 두는 것은 큐비트 소유권과 출력 결과가 샷에 따라 달라지지 않도록 하는 `.qx` 언어 자체의 규칙이다. 어느 쪽도 조건부 측정을 유효한 문법으로 허용하고 일부 하드웨어도 지원하는 OpenQASM 3의 한계가 아니다. 조건부 블록 안에서의 측정을 허용하려면 먼저 라이브러리 수준의 지원이 필요하며, 나머지 규칙의 완화는 추후 언어 차원의 과제로 남긴다.

| 코드 | 의미 |
| --- | --- |
| `Q0314` | `Bit` 조건 `if` 내부에서 조건부로 실행할 수 없는 사용자 함수(측정·할당·폐기·출력, `consume` 매개변수, 큐비트 반환)를 호출함 |

- `Q0219` (폐기): `Qubit`/`QReg` 매개변수(13.1절)와 반환 타입(14.1절)이 모두 지원되면서 폐기되었으며 번호는 재사용하지 않는다.
- `Q0308` (변경): 더 이상 사용자 함수 호출에는 적용되지 않으며, 이미 오류로 보고된 호출로 초기화되는 양자 변수 선언은 중복 보고하지 않는다.
- `Q0302`, `Q0301`, `Q0312`, `Q0311`, `Q0313`, `Q0306` (적용 확대): 14.1절에서 정리한 대로 함수에서 반환되는 큐비트와 그 호출 결과에도 동일하게 적용된다.

### 14.4 남은 제한 사항

- 조건부 블록 안에서의 측정(`measure`), 폐기(`discard`), 큐비트 할당(`qubit()`/`qreg()`), 출력(`println`)은 여전히 지원하지 않으며, 측정은 라이브러리 측 지원이 선행되어야 하고 할당·폐기·출력은 소유권과 출력이 샷에 따라 달라지지 않도록 하는 `.qx` 규칙에 따라 제외된다.
- `consume` 매개변수를 갖거나 `Qubit`/`QReg`를 반환하는 함수는 `Bit` 조건의 `if` 블록 안에서 호출할 수 없다.
- 조건부 실행 가능 여부 분석은 보수적으로 동작하므로 빌드 시점에 실행되지 않는 분기라도 본문에 금지 연산이 있으면 조건부 호출을 허용하지 않는다.
- `println`의 이진 포맷 지정자는 계속 추후 과제로 보류한다.

## 15. CLI 명령 확장: `new`, `fmt`, `repl`, `explain` (2026-11-20)

`0.6.0` 기반 위에 하위 명령 `new`, `fmt`, `repl`, `explain` 네 가지를 추가한다. 기존 명령인 `run`, `check`, `qasm`, `bell`의 동작은 변경하지 않으며, 버전 번호도 아직 올리지 않는다.

### 15.1 `qxide new`

`qxide new <NAME>`은 `qx-packages.md` 규격에 맞는 새 패키지 프로젝트 디렉터리 `NAME`을 생성한다.

- 디렉터리 안에 `qxide.toml`, `src/main.qx`, `README.md`, `.gitignore`를 만든다. `qxide.toml`에는 `[package]`의 패키지 이름, 버전 `0.1.0`, 현재 major.minor 기준 `qxide = ">=X.Y"`와 빈 `[dependencies]` 섹션이 들어가며, `src/main.qx`는 `qxide check`와 `qxide fmt --check`를 이미 통과하는 벨 쌍(Bell pair) 프로그램이다. `README.md`의 제목은 폴더 이름(`NAME` 경로의 마지막 구성 요소)으로 채우고, `.gitignore`에는 `target/`을 기록한다.
- 패키지 이름은 폴더 이름을 소문자로 바꾼 뒤 ASCII 영숫자 외 연속 문자를 하이픈(`-`) 하나로 치환하고 끝의 하이픈을 제거해 최대 64자로 만든다. 남은 문자가 없으면 `app`을 사용하며, 숫자로 시작하면 `app-` 접두사를 붙인다(예: `New Project` → `new-project`, `2fast` → `app-2fast`).
- 생성된 프로젝트 디렉터리 안에서는 파일 인자 없이 `qxide run`, `qxide check`, `qxide qasm`을 실행하면 `src/main.qx`를 대상으로 사용한다.
- `NAME` 경로에 파일이나 디렉터리가 이미 있으면 종료 코드 `1`로 실패하며 아무 파일도 생성하거나 덮어쓰지 않는다. 파일 기록 중 오류가 발생하면 새로 만든 디렉터리를 다시 삭제하고 종료 코드 `1`로 종료한다.
- 상위 디렉터리가 미리 존재해야 하며 디렉터리는 재귀적으로 생성하지 않는다. `-`로 시작하는 인자는 폴더 이름이 아닌 사용법 오류로 처리하며, 사용법 오류는 종료 코드 `2`로 종료한다.
- 생성에 성공하면 만든 파일 목록과 이어서 실행할 명령(`qxide run NAME/src/main.qx`, `qxide fmt NAME/src/main.qx`)을 출력한다.

### 15.2 `qxide fmt`

`qxide fmt <FILE> [--check]`는 소스 파일을 설계 문서와 예제에서 사용하는 스타일에 맞춰 제자리에서 다시 쓴다. `examples/qx`의 예제 프로그램 일곱 개는 모두 이미 이 서식을 따른다.

서식 규칙은 다음과 같다.

- 들여쓰기는 공백 4칸을 사용한다. 여는 중괄호 `{`는 줄 끝에 두고, `} else {`는 한 줄에 작성하며, 한 줄에 한 문장만 둔다.
- 이항 연산자 양옆과 쉼표 뒤에 공백을 두고, 괄호와 대괄호 안쪽에는 공백을 두지 않는다.
- 범위는 `0..n`, 단항 연산자는 공백 없이 `-x`와 `!b`, 형 변환은 `(int) x`, 빈 블록은 `{}` 형태로 쓴다.
- 연속된 빈 줄은 한 줄로 줄이고, `{` 바로 뒤나 `}` 바로 앞의 빈 줄은 제거한다.
- 모든 토큰은 원본에 적힌 형태 그대로 복사한다. 따라서 `1_000`, `1e3` 같은 리터럴 표기나 문자열 이스케이프는 바뀌지 않는다.
- 주석이 줄바꿈을 강제하지 않는 한 문장 내부의 줄바꿈은 유지하지 않고 한 줄로 합치며, 긴 줄을 자동으로 줄바꿈하지 않는다.
- 바이트 순서 표시(BOM)와 CRLF 줄바꿈 형식은 유지한다.

주석 처리와 안전 검사 규칙은 다음과 같다.

- 주석은 모두 보존한다. 단독 줄 주석은 해당 블록 수준에 맞춰 다시 들여쓰고, 문장 끝의 행말 주석은 원래 공백 간격을 유지해 정렬된 주석이 그대로 정렬되도록 둔다. 문장 중간에 들어간 주석은 문장의 나머지 부분을 다음 줄로 옮기고 한 단계 더 들여쓴다.
- 입력 파일은 어휘 분석과 구문 분석을 통과해야 한다. 그렇지 않으면 진단을 출력하고 아무것도 쓰지 않는다. 반면 타입 오류나 소유권 오류는 서식 정리를 막지 않는다.
- 파일을 쓰기 전에 서식 정리 결과의 토큰과 주석 열이 입력과 정확히 일치하는지 검사한다. 일치하지 않으면 내부 오류를 보고하고 아무것도 쓰지 않는다.
- 이미 서식이 맞는 파일은 건드리지 않고 종료 코드 `0`으로 종료한다. `--check` 옵션은 파일을 절대 쓰지 않으며, 변경이 필요하면 메시지를 출력하고 종료 코드 `1`을, 그렇지 않으면 `0`을 반환한다.

### 15.3 `qxide repl`

`qxide repl [--seed S]`는 대화형 세션을 제공한다. 각 입력은 `main` 내부에서 실행되는 문장, 함수 정의, 또는 단독 식 가운데 하나이다. 함수 정의처럼 여러 줄에 걸친 입력은 모든 괄호가 닫힐 때까지 계속 읽고, 단독 식은 `println("{}", expr)`과 같이 값을 출력한다. 빠진 세미콜론 `;`은 자동으로 보충한다.

- 변수, 함수, 큐비트는 입력 사이에서 계속 유지된다.
- 세션 명령으로 `:help`, `:qasm`(지금까지 구성된 OpenQASM 3 회로 출력), `:reset`(누적된 상태 초기화), `:quit`(`:q` 또는 입력 종료로도 종료)을 지원한다.
- 최상위 `return`은 `main`을 종료시켜 이후 입력을 건너뛰게 하므로 거부한다.
- 배너와 `qx> ` / `... ` 프롬프트는 표준 입력이 터미널일 때만 표시하므로, 파일을 `qxide repl`로 파이프해 실행할 수 있다.

내부적으로는 수락된 입력을 소스 텍스트로 보관하고, 새 입력이 들어올 때마다 전체 세션을 하나의 프로그램으로 합쳐 `qxide run`과 동일한 렉서, 파서, 검사기, 인터프리터로 다시 실행한다.

- 동일한 파이프라인을 거치므로 선형성 규칙을 포함한 모든 언어 규칙이 그대로 적용된다. 예를 들어 이미 측정한 큐비트를 다시 사용하면 `Q0301`이 보고된다.
- 실패한 입력은 진단을 보고한 뒤 보관하지 않으며 세션은 이전 상태 그대로 이어진다. 성공한 경우에도 새 입력이 추가로 만들어 낸 출력만 표시한다.
- 진단 메시지의 파일 이름은 `<repl>`로 표시하며, 줄 번호는 수락된 입력을 입력한 순서대로 매긴다.
- 파일 실행과 다른 점은 입력 사이에 큐비트가 살아 있는 상태로 남을 수 있다는 점 하나뿐이다. 세션이 끝날 때까지 측정하거나 폐기하지 않은 큐비트가 남아 있으면 `Q0302`를 보고하고 종료 코드 `1`로 종료한다(누수가 없으면 `0`).
- 입력마다 지금까지 입력한 전체를 다시 실행하므로 짧은 실험 용도에 적합하다.

측정은 시드 `S`(기본값 `0`)로 시뮬레이션하며 항상 상태 벡터(state-vector) 백엔드만 사용한다. `Backend::Auto`를 쓰면 첫 비-클리포드(non-Clifford) 게이트가 등장할 때 스태빌라이저 백엔드에서 상태 벡터 백엔드로 전환되는데, 두 백엔드는 같은 시드에서도 서로 다른 측정 결과를 뽑기 때문에 이미 출력된 비트 값이 이후 세션에서 바뀔 수 있다. 상태 벡터 백엔드로 고정하면 이런 불일치를 막는 대신, 1 GiB 메모리 한도에 따라 REPL에서 다룰 수 있는 큐비트 수가 약 26개로 제한된다(초과 시 `Q0406`).

### 15.4 `qxide explain`와 오류 코드 카탈로그

`qxide explain <CODE>`는 오류 코드에 대한 영문 설명을 출력한다. 설명은 오류 발생 조건과 규칙이 존재하는 이유, 오류가 나는 예제, 수정 방법, 수정된 프로그램으로 구성된다. 코드 입력은 대소문자를 구분하지 않으며(`q0302` 허용), 알 수 없는 코드는 종료 코드 `2`로 종료한다.

- 설명 원문은 코드당 하나의 항목을 담은 새 영문 카탈로그 `docs/error-codes.md`를 단일 출처로 삼는다. `qxide explain`은 빌드 시 이 파일을 내장해 해당 항목을 출력한다.
- 폐기된 코드 `Q0219`도 항목을 유지하며, 내부 안전망 코드 `Q0407`은 예제 없이 설명 항목만 둔다.
- 설계 문서의 오류 코드 표에는 짧은 한국어 요약을 그대로 두고, 상세한 영문 설명은 `docs/error-codes.md`에서 관리한다. 표의 누락을 채우기 위해 기존 14.3절 글머리 목록에만 있던 `Q0314`의 행을 추가했다.
- 테스트가 세 목록의 동기화를 강제한다: (1) `docs/error-codes.md` 카탈로그의 코드 목록, (2) 컴파일러가 보고할 수 있는 코드(`Code` 열거형과 함께 매크로로 생성되어 변형을 빠뜨릴 수 없는 `Code::ALL`)에 폐기된 코드를 더한 목록, (3) 설계 문서 오류 코드 표의 코드 목록. 또한 카탈로그의 모든 오류 예제는 실행 시 해당 오류 코드를 보고해야 하며, 모든 수정 예제는 오류 없이 실행되고 이미 서식이 정렬된 상태여야 한다.

### 15.5 검증

`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`를 모두 통과했다. 모든 예제에 대한 `run`, `check`, `qasm`의 출력은 `0.6.0`과 바이트 단위로 동일하다.

- 새 단위 테스트:
  - 포매터: 예제 파일 무변경, 흐트러뜨린 예제의 복원 및 OpenQASM 출력 동일성, 정돈 전후 골든 테스트, 멱등성, BOM/CRLF 보존, 파싱 불가 입력 거부.
  - 카탈로그: 코드 커버리지 및 오류·수정 예제 검증.
  - REPL: 상태 유지, 식 에코, 선형성 오류, 종료 시 누수 보고, 비-클리포드 게이트 이후 비트 값 안정성, 여러 줄 함수 정의, 세션 명령, 런타임 오류.
- 새 CLI 테스트: `new`, `fmt --check`, `explain`, 파이프로 입력한 `repl`.

### 15.6 남은 제한 사항

- `qxide fmt`는 긴 줄을 자동으로 줄바꿈하지 않으며, 주석이 강제하지 않는 한 문장 내부의 줄바꿈을 유지하지 않는다.
- `qxide repl`은 입력마다 세션 전체를 다시 실행하므로 세션이 길어지면 느려진다.
- `qxide repl`은 상태 벡터 백엔드만 사용하므로 약 26큐비트(1 GiB 메모리 한도, 초과 시 `Q0406`)로 제한된다.
- `qxide repl`은 파일 불러오기나 입력 이력 편집 기능을 제공하지 않으며, 진단의 줄 번호는 `<repl>` 기준의 누적 줄 번호로 표시된다.
- `qxide explain`은 원본 Markdown을 그대로 출력한다.

## 15. 모듈, import, 패키지 (2026-11-20)

`.qx` 파일마다 하나의 모듈이 되며, 파일 맨 앞에 Java식 `import pkg.module.function;` 또는 `import pkg.module.*;` 선언을 둔다. 다른 모듈에서 가져올 수 있는 대상은 `public`으로 표시한 함수뿐이며, `import`와 `public`은 새 정식 키워드로 추가된다. 모듈 사이의 순환 import는 금지되고, 큐비트 선형성 규칙은 함수 시그니처(대여, `consume`, 큐비트 반환)를 통해 패키지 경계를 넘어 그대로 유지된다.

매니페스트 `qxide.toml`, 잠금 파일 `qxide.lock`, GitHub 색인 레지스트리, 그리고 `qxide add`/`remove`/`install`/`publish`/`search` 명령을 포함한 패키지 시스템의 전체 설계는 별도 영어 문서 [qx-packages.md](qx-packages.md)에 정리되어 있다.

### 15.1 신규 오류 코드

| 코드 | 의미 |

| `Q0501` | `import` 경로의 첫 이름이 현재 패키지도 선언된 의존 패키지도 아님 |
| `Q0502` | 모듈 파일을 찾거나 읽을 수 없음(모듈 수 4096개 한도 초과 포함) |

| `Q0507` | 두 개 이상의 와일드카드 import가 같은 이름을 제공해 호출이 모호함 |
| `Q0508` | `qxide.toml` 프로젝트 밖의 단독 파일에서 `import`를 사용함 |

## 17. `String` 타입과 표준 라이브러리 (2026-11-21)

데스크톱 앱 프레임워크 작업의 일부로(설계는 영문 문서 [qx-app.md](qx-app.md) 참조), 앱 로직이 텍스트 처리와 OS 접근을 필요로 하므로 `.qx` 언어에 `String` 타입과 표준 라이브러리 `std`가 추가된다. `std`의 각 모듈은 호스트가 권한 정책에 따라 제공한다.

### 17.1 `String` 타입

`String`은 `int`와 마찬가지로 빌드 타임 불변 텍스트 값이다. 기존 이스케이프를 포함하는 `"..."` 리터럴이 이제 값으로 평가된다.

- 양변 중 하나가 `String`이면 `+` 연산자는 텍스트를 연결한다. 다른 한쪽은 `int`, `double`, `boolean` 또는 `String`일 수 있으며, 숫자는 `println`이 출력하는 표기 그대로 변환된다.
- `==`와 `!=`는 텍스트를 비교한다.
- `len(s)`는 유니코드 문자 수를 센다.
- `println("{}", s)`로 출력할 수 있다.
- 매개변수, 반환 타입, `final` 선언 및 `var` 타입 추론에 사용할 수 있다.
- 값으로 사용되는 리터럴에는 `{}` 플레이스홀더를 포함할 수 없으며(`Q0214`, 플레이스홀더는 `println`의 형식 문자열에서만 허용된다는 내용으로 메시지가 변경되었다), 중괄호 자체는 `{{`와 `}}`로 표기한다.
- `String`은 이제 예약 타입명이므로 변수명이나 함수명으로 사용할 수 없다(소규모 호환성 변경).
- 이에 따라 `int s = "hi";`는 `Q0214` 대신 타입 불일치 오류인 `Q0204`를 발생시킨다.

### 17.2 표준 모듈과 import

`import std.fs;` 형식으로 모듈 별칭을 가져오면 `fs.write_text("a.txt", s);`처럼 한정 호출한다. 기존의 `import std.fs.write_text;`와 `import std.fs.*;` 형식도 동일하게 동작한다. `std` import는 프로젝트 외부에서도 사용할 수 있다. 모듈 별칭은 현재 `std`에 대해서만 허용되며, `std`는 예약 패키지명이다.

MVP 단계의 표준 모듈은 다음과 같다.

- `std.log`: `info`, `warn`, `error`
- `std.time`: `now_millis`, `now_iso`, `sleep_millis`
- `std.fs`: `read_text`, `write_text`, `append_text`, `exists`, `remove`
- `std.app`: `set_title`, `set_size`, `close`, `emit` (데스크톱 앱 전용)
- `std.qxide`: `check`, `run`, `qasm`, `format` (`qxide` 권한이 있는 앱 전용, 즉 Qxide Studio)

각 모듈은 컴파일러 내부에 `.qx` 스텁으로 선언되어 있으며(진단 메시지에는 `std/fs.qx`와 같이 표시된다), 일반 검사기가 호출을 그대로 검증한다.

### 17.3 효과가 실행되는 시점

`std` 호출은 빌드 타임 효과로, 함수가 전개(elaboration)되는 동안 `--shots`와 무관하게 실행당 한 번, 프로그램 순서대로, 모든 샷이 시뮬레이션되기 전에 실행된다. `std` 함수는 빌드 타임 값만 인수로 받고 반환한다. `Bit`와 `BitReg`는 `println` 또는 커맨드의 반환값을 통해서만 외부로 전달된다. 측정 결과에 대한 `if` 내부에서는 `std` 호출을 허용하지 않는다(`Q0314`).

### 17.4 호스트별 허용 범위

| 호스트 | 허용 범위 |
| --- | --- |
| `qxide run` / `qxide check` | `std.log`(stderr 출력)와 `std.time`은 항상 허용된다. `std.fs`는 `--allow fs` 지정 시에만 허용되며 `qxide.toml` 옆의 `data/` 또는 `./data`를 루트로 한다. `std.app`과 `std.qxide`는 사용할 수 없다(`Q0702`). |
| `qxide qasm` | `std.log`는 폐기되며 `std.time`은 동작한다. 내보내기에 부수 효과가 없도록 `std.fs`와 `std.app` 호출은 `Q0702`로 거부된다. |
| `qxide repl` 및 플레이그라운드 | 둘 다 `std.log`만 허용된다. 플레이그라운드는 stderr에 `info: ...` 형식으로 출력하지만, REPL은 매 입력마다 전체 세션을 다시 실행하므로 호출은 허용하되 출력하지 않는다. |
| 데스크톱 앱 | `std.log`는 항상 허용되며, 그 외 모듈은 `[app] permissions`에 나열된 경우에만 허용된다. 의존성은 `std.log`만 사용할 수 있다. |

### 17.5 신규 오류 코드

| 코드 | 의미 |
| --- | --- |
| `Q0701` | 알 수 없는 `std` 모듈 또는 함수 |
| `Q0702` | 현재 호스트에서 사용할 수 없는 모듈 |
| `Q0703` | 허용되지 않은 모듈(`--allow` 또는 `[app] permissions` 미지정, 또는 의존성이 `std.log` 외의 모듈을 import함) |
| `Q0704` | 파일 작업 실패(파일 없음, 16 MiB 초과, UTF-8 아님, I/O 오류) |
| `Q0705` | 허용되지 않은 경로(절대 경로, 드라이브/UNC 경로, `..`, 예약 장치명, 심볼릭 링크 탈출) |
| `Q0706` | `std` 인수 범위 초과(`sleep_millis`는 `0..60000`) |
| `Q0707` | HTTP 요청 실패(네트워크 오류, 2xx 외 상태 코드, 16 MiB 초과, UTF-8 아님) |
| `Q0708` | 허용되지 않은 URL(https 아님 또는 `[app] http_hosts`에 없는 호스트) |
| `Q0711` | 알 수 없는 앱 커맨드 |
| `Q0712` | 잘못된 커맨드 인수 또는 샷 수 |
| `Q0713` | 호출 취소 |
| `Q0714` | 잘못된 커맨드 시그니처(없음, 공개 함수가 아님, 빌드 타임이 아닌 매개변수) |
| `Q0715` | 잘못된 `[app]` 섹션 |
| `Q0716` | 호출 결과가 너무 큼(페이지로 넘기는 결과는 32 MiB까지) |

각 오류 코드의 상세 내용은 `docs/error-codes.md`와 `qxide explain`에서 확인할 수 있다.
