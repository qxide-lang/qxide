# 얽힘 추적(Entanglement Tracking) 설계 검토

> **상태**: 설계 검토 문서(미구현) — 구현 착수 전 메인테이너 승인 필요

## 1. 배경 및 목표

`qxide`는 `.qx` 파일 기반의 Rust 유사 양자 프로그래밍 언어를 목표로 하는 프로젝트의 Stage 0 Rust 크레이트이다. 현재 `qxide`의 핵심 모델은 다음과 같다.

- `Qubit`: `Clone` 및 `Copy`가 구현되지 않은(non-Clone, non-Copy) 유일 소유권 핸들
- 게이트 연산: `&mut Qubit`을 인자로 받음 (예: `cx(&mut a, &mut b)`는 Rust 대여 검사기(borrow checker)를 통해 앨리어싱을 원천 차단)
- 측정 및 초기화: `measure(q: Qubit) -> Bit`은 `Qubit` 핸들을 소비(consume)하며, `reset` 연산을 지원함
- 레지스터 및 고전 제어 흐름: `QReg` 레지스터 및 `if_one`/`if_zero(bit, |c| ...)` 형태의 고전 분기 지원
- 백엔드: 상태 벡터(state-vector) 시뮬레이터 및 안정자(stabilizer) 백엔드 제공

본 문서는 **"Rust 타입 시스템만을 사용하여 `cx` 등의 2큐비트 게이트로 형성되는 큐비트 간 얽힘(entanglement) 그룹을 타입 수준에서 표현할 수 있는가?"**에 대한 설계 분석을 정리한다.

얽힘 추적 기능이 확보되면 다음 세 가지 영역에 직접적인 이점을 제공한다.

1. **안전한 큐비트 폐기(`drop`) 검증**: 얽힌 큐비트를 그대로 폐기하면 얽힘 파트너 상태가 결어긋남(decoherence)을 겪는다. 큐비트가 비얽힘 상태임을 알면 안전한 `drop`을 보장할 수 있으며, 이는 자동 역연산(automatic uncomputation) 연구와 직접 연결된다.
2. **시뮬레이터 분할(Simulator Partitioning)**: 서로 독립된 얽힘 그룹을 별도의 작은 상태 벡터로 분리해 시뮬레이션할 수 있다(메모리 사용량 $2^{a+b}$ 대신 $2^a + 2^b$).
3. **진단 및 오류 메시지 개선**: 의도치 않은 얽힘 잔존이나 잘못된 상태 사용에 대해 더 명확한 오류 메시지를 제공할 수 있다.

## 2. 설계 제약 조건

Rust 타입 시스템 기반의 정적 얽힘 추적은 다음 두 가지 근본적인 제약에 의해 경계가 정해진다.

1. **얽힘은 구문(syntax)이 아니라 런타임 상태의 속성이다.**
   - 제어 큐비트가 $|0\rangle$ 상태일 때 `cx`를 적용해도 얽힘은 발생하지 않는다.
   - Bell 쌍의 한 큐비트를 측정(`measure`)하면 얽힘이 해소된다.
   - `reset`은 해당 큐비트의 모든 상관관계를 끊는다.
   - `rx(θ)` 이후 `cx`가 얽힘을 만드는지는 각도 `θ`에 따라 달라진다.
   - 따라서 어떠한 정적(타입 수준) 추적도 **"얽혀 있을 수 있음(may be entangled with)"**을 판별하는 건전한 **과대근사(sound over-approximation)**만 가능하며, 일반적인 경우 정확한 정적 추적은 불가능하다.

2. **Rust 변수는 제자리에서(in place) 타입을 바꿀 수 없다.**
   - 타입 상태로 얽힘 그룹이나 큐비트 상태를 반영하려면 `c.cx(&mut a, &mut b)` 대신 `let (a, b) = c.cx(a, b);`처럼 핸들을 소비하고 새 타입으로 반환(consume-and-return)해야 한다.
   - 이는 현재의 `&mut` 기반 API에 대한 중대한 호환성 깨짐(breaking change)이며 사용성 비용이 크다.

## 3. 설계 대안 비교

| 대안 | 접근 방식 | 안정 Rust 지원 | 루프 / `QReg` 호환 | 평가 및 판정 |
| :--- | :--- | :---: | :---: | :--- |
| **A** | 타입 수준 그룹 집합 (`Qubit<G>`) | X (특수화/동등성 부재) | X | **기각** (장난감 수준 외 비실용적) |
| **B** | Const 제네릭 그룹 ID (`Qubit<const G: u32>`) | X (`generic_const_exprs` 필요) | X | **기각** (안정 Rust 불가) |
| **C** | 생성적 브랜딩 (`GhostCell`식 불변 라이프타임) | O | 제한적 | **기각** (과도한 클로저 중첩, 빌더 스타일 부적합) |
| **D** | 거친 단위의 Typestate (`Fresh`/`Classical`/`Any`) | O | 제한적 | **opt-in 정적 계층으로 고려** |
| **E** | 런타임 추적 (`Circuit` 내부 Union-Find + 선택적 Stabilizer) | O | O | **1차 구현 권장 (동적 계층)** |
| **F** | `.qx` 컴파일러(Stage 1–2)로 이관 | N/A | O | **장기 목표 (정밀 흐름 민감 분석)** |

### 대안 A: 타입 수준 그룹 집합 기반 Typestate
- **구조**: `Qubit<G>`에서 `G`를 타입 수준 집합으로 두고, `cx(Qubit<G1>, Qubit<G2>) -> (Qubit<Union<G1, G2>>, Qubit<Union<G1, G2>>)` 형태로 합집합을 계산한다.
- **장점**: 이론적으로 순수 타입 수준에서 그룹 병합을 표현할 수 있다.
- **단점**: 안정 Rust에는 타입 수준 동등성 비교나 특수화(specialization)가 없다. `HList`나 `typenum` 스타일의 트레이트 기법으로 흉내 낼 수 있으나, 난해한 컴파일 오류와 컴파일 속도 저하를 유발한다. 또한 루프 본문은 반복마다 변수의 타입을 바꿀 수 없고, 동적 크기의 `QReg` 레지스터에서도 동작하지 않는다.
- **판정**: 토이 예제를 넘어서면 실용성이 없다.

### 대안 B: Const 제네릭 그룹 ID
- **구조**: `Qubit<const G: u32>`로 그룹 ID를 부여하고, 병합 시 `const` 제네릭 위치에서 `min(G1, G2)` 등을 계산한다.
- **장점**: 트레이트 기반 타입 집합보다 표현이 단순하다.
- **단점**: 제네릭 위치의 연산을 위해 불안정 기능인 `generic_const_exprs`가 필수적이다. 루프 및 동적 크기 레지스터 문제 역시 대안 A와 동일하게 해결되지 않는다.
- **판정**: 안정 Rust에서 구현 불가능하다.

### 대안 C: 생성적 브랜딩 (Generative Branding)
- **구조**: `GhostCell`과 유사하게 불변 라이프타임(invariant lifetime) `'g`를 도입해 각 그룹을 클로저 스코프로 표현하고, 두 그룹을 병합할 때는 두 그룹을 인자로 받는 새로운 중첩 스코프를 연다.
- **장점**: 타입 건전성(soundness)이 보장되며 안정 Rust에서 동작한다.
- **단점**: 모든 `cx` 호출마다 깊게 중첩된 클로저를 강제하므로, 현재 `qxide`의 명령형 빌더 스타일(`&mut Circuit`)과 양립하기 어렵다.
- **판정**: 작고 구조화된 커널(structured kernels)에는 흥미로우나 범용 API로는 부적합하다.

### 대안 D: 거친 단위의 Typestate (Coarse Typestate) — 정적 계층 권장안
- **구조**: 임의의 얽힘 그룹 대신, 정적으로 판별 가능한 소수의 상태만 타입으로 추적한다.
  - `Qubit<Fresh>`: `qubit()` 또는 `fresh()`가 반환하는 초기 상태로, $|0\rangle$임이 보장되며 아직 게이트가 적용되지 않음.
  - `Qubit<Classical>`: `X` 게이트만 적용되어 알려진 기저 상태(basis state)에 있음.
  - `Qubit<Any>`: 기본 일반 상태.
  - `Fresh`나 `Classical`에 일반 게이트를 적용하면 더 일반적인 상태 타입을 반환한다.
- **장점**: 불필요한 `reset`을 생략할 수 있고, `Classical` 큐비트에 대한 저비용 `measure` 경로를 제공하며, 반드시 `Fresh`여야 하는 보조 큐비트(ancilla)에 비초기화 큐비트가 전달되는 오류를 컴파일 타임에 차단할 수 있다.
- **단점**: 상태 전이를 위해 여전히 소유권 소비 및 반환(consume-and-return) 패턴이 필요하다. 따라서 기존 `&mut` API를 대체하기보다 **선택적(opt-in) 상위 계층**으로 제공하는 것이 적합하다.

### 대안 E: 런타임 추적 (Union-Find + 선택적 Stabilizer 정제) — 동적 계층 권장안
- **구조**: `Circuit` 내부에서 큐비트 슬롯을 대상으로 union-find 자료구조를 유지한다.
  - 2큐비트 게이트 적용 시 두 큐비트 슬롯을 `union`한다.
  - 측정(`measure`)이나 `reset` 시 해당 큐비트를 기존 그룹에서 분리(split)한다.
  - 고전 분기(`if_one`/`if_zero`)에서는 양쪽 분기 경로의 결과를 모두 합쳐(union) 건전한 과대근사를 유지한다.
  - 회로가 클리포드(Clifford) 회로인 경우, 선택적으로 안정자 태블로(stabilizer tableau)를 활용해 얽힘 여부를 정확하게 정제(refinement)할 수 있다.
- **인터페이스**: `c.may_be_entangled(&a, &b) -> bool`, `c.group_of(&a)` 등의 질의 API를 노출한다.
- **장점**: 런타임 비용이 낮고, 기존 `&mut` API를 깨뜨리지 않으며, 루프·동적 크기 `QReg`·고전 분기와 자연스럽게 호환된다.

### 대안 F: `.qx` 컴파일러(Stage 1–2)로 이관
- **구조**: 향후 도입할 `.qx` 전용 타입 시스템에서는 문장(statement) 단위로 변수의 타입이 변하는 흐름 민감 분석(flow-sensitive analysis)을 수행할 수 있다.
- **역할**: Stage 0 Rust 라이브러리에서의 런타임/타입 실험 결과는 `.qx` 컴파일러의 참조 의미론(reference semantics) 역할을 한다.

## 4. 권장 접근 방식

1. **1단계 — 대안 E(런타임 Union-Find 추적) 우선 구현**: 구현 규모가 작고 테스트가 용이하며, 시뮬레이터 상태 벡터 분할($2^a + 2^b$) 및 안전한 `drop` 검증, 진단 메시지 개선에 즉시 활용할 수 있다.
2. **2단계 — 대안 D(Coarse Typestate)의 opt-in 계층 검토**: 기존 `&mut` 기반 API 위에 선택적으로 사용할 수 있는 타입 안전 계층으로 제공하여, `Fresh` ancilla 검증 등 정적 보장이 필요한 사용자에게 제공한다.
3. **문서화 유지**: 대안 A, B, C는 검토 후 기각된 설계 대안으로 기록만 남긴다.
4. **장기 방향 — 대안 F**: 정밀한 정적 얽힘 추적은 `.qx` 컴파일러 타입 시스템(Stage 1–2)에서 다룬다.

## 5. 사용 예시

### 런타임 Union-Find 추적 (대안 E)

```rust
let mut c = Circuit::new();
let mut a = c.qubit();
let mut b = c.qubit();
let mut d = c.qubit();
c.h(&mut a);
c.cx(&mut a, &mut b);
assert!(c.may_be_entangled(&a, &b));   // 런타임 union-find (대안 E)
assert!(!c.may_be_entangled(&a, &d));
let ma = c.measure(a);                 // b는 다시 그룹에서 분리됨
```

### Opt-in Coarse Typestate 스케치 (대안 D)

```rust
let f: Qubit<Fresh> = c.fresh();
let f: Qubit<Any> = c.h_owned(f);      // 소유권 소비 및 반환으로 타입이 변경됨
```

## 6. 한계 및 예외 처리

- **과대근사(Over-approximation) 한계**: 정적 추적은 물론 union-find 기반 동적 추적 역시 보수적 과대근사다. 예를 들어 $|0\rangle$ 제어 큐비트에 대한 `cx`나 `θ` 값에 따라 얽히지 않는 `rx(θ)` + `cx` 조합에서도 `may_be_entangled`가 `true`를 반환할 수 있다(클리포드 회로의 안정자 정제를 적용하지 않는 한 거짓 양성이 존재함).
- **고전 분기 (`if_one` / `if_zero`)**: 정적·동적 추적 모두 양쪽 경로의 그룹 합병을 취해야 하므로 보수성이 증가한다.
- **루프 및 동적 레지스터 (`QReg`)**: Rust 타입은 루프 반복마다 변할 수 없어 정적 추적은 고정점(`Any`)으로 수렴할 수밖에 없으며, 동적 크기의 `QReg`는 원소별 정적 타입 부여가 어렵다.
- **트레이트 기반 기법의 비용**: 대안 A와 같은 타입 수준 트릭은 컴파일 시간 증가와 판독 불가능한 오류 메시지를 초래한다.
- **실패 및 예외 상황 처리**:
  - `drop` 시점에 큐비트가 여전히 다른 큐비트와 얽힘 그룹에 속해 있다면 비정상 폐기(결어긋남 위험)로 간주해 경고/검증 오류를 내거나 안전 폐기 검사에서 거부할 수 있다.
  - 대안 D에서는 `Fresh`가 요구되는 자리에 `Any`나 `Classical` 큐비트를 넘길 경우 컴파일 에러로 즉시 실패 처리된다.

## 7. 메인테이너 검토 요청 사항 (Open Questions)

1. **Opt-in 소비-반환(consume-and-return) API 수용 여부**: 대안 D를 기존 `&mut` API 위의 선택적 계층으로 추가할 때, `h_owned`와 같은 consume-and-return 형태의 API 형태를 허용할 것인가?
2. **클리포드 회로 대상 안정자 태블로 정제 여부**: `may_be_entangled` 질의 시 회로가 클리포드 연산으로만 구성된 경우, 안정자 태블로를 참조해 과대근사가 아닌 정확한 얽힘 판별 결과를 반환하도록 할 것인가?
