# 메모리 모델: 쉬운 소유권과 가변 값 의미론 (제안, 미승인, 실험 구현 있음)

## 1. 상태

- **작성 및 승인 상태**: 2026-11-24 작성. 사용자가 정한 방향(Mojo·Hylo식 가변 값 의미론)을 구체화한 제안이다. 언어 의미가 바뀌는 되돌리기 어려운 결정이라 기본 동작은 바꾸지 않았다.
- **실험 구현(2026-11-24, `worktree-mm` 브랜치)**: 사용자 지시("되돌릴 수 있게 진행")에 따라 `--experimental value-semantics` 플래그(또는 `QXIDE_EXPERIMENTAL=value-semantics`) 뒤에 M0, M1, M3, M4를 앞단에서 구현했다. 플래그를 끄면 문법, 진단, 실행 결과, 스텝 수가 그대로다. 11절의 남은 질문은 임시로 정했고, 각 항목에 "임시 결정(사용자 확인 필요)"과 바꿀 때의 비용을 적었다. 구현 방식은 12절에 있다.
- **기존 결정과의 관계**: 현재 언어는 2026-11-23 결정 D5(배열)·D6(구조체)에 따라 Java식 참조 의미론을 쓴다. 이 문서는 D5·D6을 다시 검토 대상으로 올린다(아직 바꾸지 않았다).
- **목표(사용자 비전 2026-11-24)**: C·Java 기반의 쉬운 문법을 유지하면서 같은 알고리즘에서 Rust 대비 95% 성능을 내고 Rust와 양방향으로 연동하는 것이다. 메모리 모델은 이 목표의 바탕이다.

## 2. 핵심 규칙 (사용자 결정 방향)

1. **값 의미론**: 배열, 구조체, `String`, `List`/`Map`은 값이다. 대입·초기화·`consume` 인자 전달은 별개의 값을 만들며(구현은 복사 또는 이동), 기본 매개변수나 `inout` 매개변수로 전달할 때는 빌림이므로 새 값을 만들지 않는다. 열거형은 지금도 불변 값이다.
2. **참조는 매개변수로만**: 빌림은 함수 매개변수(와 메서드의 `this`)에만 존재하고 변수·필드·배열 원소에 저장하거나 반환할 수 없다. 따라서 수명(lifetime) 표기가 필요 없다.
3. **단어로 쓰는 매개변수 규칙**: 기본은 읽기 전용 빌림, `inout`은 수정 가능한 빌림(호출자의 값을 고친다), `consume`은 이동(소유권을 넘김)이다. `&`/`&mut` 기호는 쓰지 않는다.
4. **마지막 사용에서 자동 이동, 작은 값은 자동 복사**: 변수의 마지막 사용은 복사 없이 이동하며, 힙을 쓰지 않는 작은 값(`int`, `double`, `boolean`, 그런 필드만 가진 작은 구조체)은 언제나 암묵적으로 복사된다. 큰 값(배열, 문자열, 컬렉션, 힙을 가진 구조체)을 마지막 사용이 아닌 곳에서 값으로 넘기면 비용이 보이게 하기 위해 명시적 `.copy()`를 요구하는 오류를 내고 고치는 방법(빠른 수정)을 제시한다(대안인 Swift식 암묵 복사+COW는 9절, 큰 값 기준은 11절 참고).
5. **명시적 공유**: 공유가 꼭 필요하면 참조 카운팅 타입을 명시적으로 쓴다. 이름은 미정이며 내장 제네릭 타입 `Shared<T>`(기존 `List`/`Map`처럼 프로그램이 같은 이름을 선언하면 사용자 타입 우선) 또는 문맥적 단어 `shared`를 후보로 둔다.
6. **고치는 방법과 빠른 수정**: 모든 오류는 고치는 방법을 알려 주고, 언어 서버에서 바로 고칠 수 있게 한다.
7. **문맥적 단어**: 새 단어 `inout`, `shared`는 `new`처럼 문맥적 단어로 두어 이 이름을 식별자로 쓰는 기존 프로그램을 깨지 않는다. `consume`은 이미 키워드다.

## 3. 문법 예시

```qx
struct Particle {
    double x;
    double v;
}

// 기본: 읽기 전용 빌림. p를 고치려 하면 오류(빠른 수정: inout 추가)
double energy(Particle p) {
    return 0.5 * p.v * p.v;
}

// inout: 호출자의 값을 고친다
void step(inout Particle p, double dt) {
    p.x += p.v * dt;
}

// consume: 소유권을 받아 새 값을 돌려준다
Particle[] grow(consume Particle[] ps, Particle extra) {
    ps = append(ps, extra);   // 표기는 미정, 예시
    return ps;
}

void main() {
    Particle[] ps = new Particle[2];
    step(inout ps[0], 0.1);       // 호출 위치에도 inout을 쓸지는 남은 질문(11절)
    Particle a = ps[0];           // 복사: 작은 구조체
    a.x = 9.0;                    // ps[0]은 바뀌지 않는다 (지금은 바뀐다)
    Particle[] qs = ps.copy();    // 큰 값의 복사는 명시
    Particle[] rs = grow(ps, a);  // ps의 마지막 사용: 이동
}
```

메서드에서 `this`를 고치는 예시:

```qx
struct Counter {
    int n;

    inout void bump() {      // this를 고치는 메서드 표기(미정, 11절)
        this.n += 1;
    }
}
```

명시적 공유 예시(이름은 `Shared<T>`와 `shared` 중 미정):

```qx
Shared<Node> head = new Shared<Node>(new Node(1));
```

위 예시의 `append`와 호출 위치의 `inout` 표기는 설명용이며 아직 결정하지 않았다.

## 4. 검사 규칙

실험 구현은 라벨마다 오류 번호를 붙였다(`docs/error-codes.md`, 플래그를 켰을 때만 나온다): `M-빌림수정` `Q0320`, `M-이동후사용` `Q0321`, `M-큰값복사`와 `M-참조저장` `Q0322`, `M-빌림중복` `Q0323`, `M-반복안이동` `Q0324`, `inout` 표기 오류 `Q0325`, 복사할 수 없는 타입 `Q0326`, 전환 경고 `M-별칭쓰기` `Q0803`. 오류마다 도움말이 있고, 고칠 수 있는 오류에는 언어 서버 빠른 수정이 붙는다.

- **`M-빌림수정`**: 기본(읽기 전용) 매개변수나 그 필드·원소에 쓰거나 변경 메서드(`add`, `put` 등)를 호출할 때 발생한다. 빠른 수정으로 매개변수에 `inout` 추가를 제시한다.
- **`M-이동후사용`**: 명시적으로 이동된(`consume` 매개변수에 넘긴) 값을 다시 사용할 때 발생한다. 변수의 마지막 사용에서 일어나는 이동은 이후 사용이 없으므로 이 진단을 유발할 수 없다. 기존 큐비트 오류 `Q0301`(소비된 큐비트 사용)을 고전 값으로 일반화한 규칙이며, 빠른 수정으로 `.copy()`를 대신 넘기는 변경을 제시한다.
- **`M-큰값복사`**: 큰 값을 마지막 사용이 아닌 곳에서 값으로 넘길 때 발생한다. 빠른 수정으로 `.copy()` 추가 또는 빌림 매개변수로 바꾸기를 제시한다.
- **`M-빌림중복`**: 같은 값을 한 호출에 `inout`으로 두 번 넘기거나 `inout`과 읽기 빌림으로 동시에 넘길 때 발생한다. 기존 큐비트 인자 별칭 검사(`Q0303`)를 일반화한 규칙이다.
- **`M-참조저장`**: 빌림을 변수·필드·원소에 저장하거나 반환하려 할 때 발생한다. 구조상 문법에서 표현할 수 없게 하며, 시도하면 값으로 복사하라는 도움말을 제시한다.
- **`M-반복안이동`**: 반복문 밖의 값을 반복문 안에서 이동할 때 발생한다. 기존 `Q0305`(반복문 안 큐비트 소비)의 일반화다.
- **측정 비트 `if` 규칙 유지**: 측정 비트 `if` 규칙(`Q0308`, `Q0314`)은 그대로 유지한다. `inout` 매개변수를 가진 함수 호출은 지금의 "저장 함수" 규칙처럼 보수적으로 다룬다.
- **전환 경고 `M-별칭쓰기`**: 원소나 필드에서 꺼낸 지역 변수에 쓰는 코드(`Particle p = ps[i]; p.v = ...;`)는 새 의미에서 조용히 동작이 바뀐다. 전환 기간 동안 경고로 알리고 빠른 수정(`ps[i].v = ...`로 바로 쓰기, 또는 끝에서 되써 넣기)을 제시한다.

## 5. 지금의 참조 의미와 큐비트 선형 규칙을 합치는 방법

현재 언어(확인된 규칙)에서 `Qubit`/`QReg` 매개변수는 기본이 빌림이며, 빌린 큐비트에는 게이트와 `reset`을 적용할 수 있지만 측정·폐기·이동하거나 `consume`에 넘길 수는 없다(`Q0313`). `consume`은 소유권을 이동하고 호출된 함수는 모든 경로에서 측정하거나 폐기해야 하며(`Q0302`), 고전 매개변수에 `consume`을 쓰면 `Q0221` 오류다. 또한 큐비트는 배열이나 구조체에 저장할 수 없고(D3), 반복문 안의 바깥 큐비트 소비는 `Q0305`, 같은 큐비트 중복 전달은 `Q0303`, 소비 후 사용은 `Q0301`이다.

새 메모리 모델에서는 이 규칙을 고전 값과 다음과 같이 합친다.

- **선형(큐비트)과 아핀(고전 값)**: 큐비트는 선형 그대로 반드시 소비(측정·폐기)해야 한다(`Q0302`). 고전 값은 버려도 되며(아핀), 범위 끝에서 자동 해제된다.
- **기본 빌림의 비대칭**: 기본 빌림은 둘 다 같은 단어 규칙을 쓰지만 의미가 다르다. 큐비트의 양자 상태는 값이 아니라 장치 자원이므로 기본 빌림에서도 게이트와 `reset`을 적용할 수 있다(지금과 같음). 고전 값의 기본 빌림은 읽기 전용이다. 이 비대칭을 문서와 도움말에 명시한다.
- **`consume` 확장과 `Q0221` 은퇴**: `consume`은 큐비트에서 쓰던 그대로 고전 값에도 허용한다. 따라서 `Q0221`은 은퇴시키며 오류 번호는 재사용하지 않는다.
- **소유권 분석 공유**: 큐비트 오류 `Q0301`, `Q0303`, `Q0305`, `Q0313`의 검사기는 고전 값용 규칙과 같은 소유권 분석을 공유하도록 일반화한다. 오류 코드 번호를 어떻게 나눌지는 구현 단계에서 정한다.
- **D3 유지**: D3(배열·구조체에 큐비트 없음)는 유지한다. 값 의미론이 되면 나중에 큐비트를 담은 구조체를 허용하는 길이 열리지만 이번 범위가 아니다.
- **`inout Qubit` 불필요**: 큐비트는 기본 빌림이 이미 게이트 적용을 허용하므로 `inout Qubit`은 필요 없다.

## 6. 기존 코드와 예제를 옮기는 계획

가장 위험한 변경은 오류 없이 결과만 달라지는 조용한 동작 변화이며, 그다음이 컴파일 오류로 드러나는 변경이다. 아래 표는 2026-11-24 기준 `examples/`, `bench/`, `apps/studio/ui/examples`의 `.qx` 파일 54개를 grep으로 확인한 현황이다(`apps/studio/ui/examples`에는 `examples/qx` 파일의 사본이 여럿 들어 있다). Rust 테스트 소스(`src/lang/*tests.rs`)에는 이보다 훨씬 많은 프로그램이 들어 있으며, 검사기 기반 스캔이 필요해 이 집계에는 포함하지 않았다.

| 패턴 | 새 의미에서 | 위치·개수 |
| --- | --- | --- |
| 원소·필드를 지역 변수로 꺼내 쓰기 (`Particle p = ps[i]; p.v = ...`) | 조용히 바뀜(복사본만 바뀜) | `bench/qx/arrays.qx` 33–34행, `bench/compare/qx/nbody.qx` 51–56행 |
| for-each 변수에 쓰기 (`for b in bs { b.x += ... }`, 내부적으로 `var b = bs[i]`) | 조용히 바뀜; 대신 인덱스 반복문(`for i in 0..len(bs) { bs[i].x += ... }`)으로 쓰거나 11절의 for-each 바인딩 결정을 따른다 | `bench/compare/qx/nbody.qx` 60–62행 |
| 매개변수의 필드에 쓰기 (`void step(Particle p)` 안의 `p.vel.y -= ...`) | 오류(빠른 수정: `inout`) | `examples/qx/structs.qx`와 Studio 사본 |
| 매개변수인 배열·컬렉션 수정 (`tally(String text, int[] totals, Map<String, int> counts)`) | 오류(빠른 수정: `inout`) | `examples/cli/wc.qx` |
| 메서드에서 `this` 필드 쓰기 (`Rect.scale`) | 오류(빠른 수정: 메서드 표기) | `examples/qx/interfaces.qx` 포함 4곳(2파일, 하나는 Studio 사본) |
| 전체 쓰기 현황 | — | 필드 쓰기 20줄(6파일), 원소 쓰기 25줄, 변경 메서드 호출 18줄(7파일) |

이전은 다음 단계로 진행한다.

- **1단계(경고만, 의미 변화 없음)**: 다음 릴리스에서 `inout`과 고전 `consume`을 문법으로 받아들이고 지금처럼 참조로 동작시키되, 새 의미에서 오류나 변화가 될 곳에 경고(`M-빌림수정` 예고, `M-별칭쓰기`)와 빠른 수정을 낸다. `qxide fix`(가칭)가 빠른 수정을 일괄 적용한다.
- **2단계(새 의미 선택)**: `qxide.toml`의 언어 판(edition) 설정 같은 선택 스위치로 새 의미를 켠다. 단일 파일은 명령줄 플래그(가칭)로 켠다. 저장소 예제와 Studio 예제를 먼저 옮긴다.
- **3단계(기본값 전환)**: 한 릴리스 뒤 새 의미가 기본이 되고 옛 의미는 경고와 함께 한 릴리스 더 남는다. 그 뒤 제거한다. 의미가 바뀌는 변경이므로 사용 중단 기간은 최소 두 릴리스로 둔다(camelCase 전환 때 한 릴리스였던 것보다 길다).
- **엔진 일관성**: 세 엔진(`ast`, `ir`, `jit`)과 플레이그라운드가 같은 의미를 쓰도록 엔진별 전환을 따로 두지 않는다.

## 7. 성능 근거 (가설, 아직 측정하지 않음)

아직 측정하지 않았으며, 아래 효과는 모두 가설이다. 각 가설은 `bench/compare`(기준선은 `docs/perf/RUST_COMPARISON.md`)로 검증한다.

현재 런타임에서 배열은 `Rc<RefCell<ArrayData>>`, 구조체와 `List`/`Map`은 `Rc`다. 네이티브 코드는 참조를 읽고 쓸 때마다 참조 카운트를 증가·감소(retain/release)하고, 원소는 헬퍼 호출(`qx_heap`, 원소·필드 읽기의 빠른 경로 포함)로 읽는다. 또한 컴파일된 모든 함수는 스텝 예산을 과금한다.

- **H1 참조 카운팅·`RefCell` 검사 제거**: 고유 소유 값은 참조 카운트가 필요 없다 → `binarytrees`, `nbody`.
- **H2 평탄한 메모리 배치**: 기본형 원소 배열(`matmul`의 `double[]`)은 안정적인 메모리 배치(`repr(C)` 저장소)만 있으면 네이티브 코드에서 원소에 직접 접근할 수 있으며 값 의미론이 필수는 아니다. 값 의미론은 여기에 더해 구조체 값을 배열 안에 포인터 없이 인라인으로 두고 별칭(aliasing)을 없애 주는데, 이는 `nbody`에서 중요하다 → `matmul`, `nbody`.
- **H3 별칭 없음**: `inout`이 아닌 빌림은 읽기 전용이고 `inout`은 겹치지 않으므로 최적화기가 별칭을 가정하지 않아도 된다(나중의 LLVM 백엔드에서 특히 효과적이다) → 모든 벤치마크.
- **H4 제자리 변경**: 마지막 사용 이동으로 `s = s + x` 같은 갱신을 새 할당 없이 할 수 있다 → `strings`.
- **H5 병렬화**: 고유 소유 값은 다른 스레드로 그대로 보낼 수 있어 `Arc`로 바꿀 필요가 줄어든다(`docs/design/qx-parallel.md`의 `Rc`→`Arc` 질문이 이 결정에 달려 있다).
- **실행 예산 분리**: 실행 예산(스텝 과금)은 메모리 모델과 별개의 비용이며 장기 계획 1단계의 "컴파일된 프로그램의 실행 예산 제거"로 따로 다룬다.

## 8. 구현 단계 나눔

각 단계는 로드맵의 공통 테스트 기준(세 엔진 결과·스텝 일치, wasm 동작)을 지킨다.

- **M0 분석 도구**: 검사기에 소유권 분석(마지막 사용, 쓰기 위치)을 넣고 경고만 낸다. 언어 서버에 `codeActionProvider` 기능을 추가해 빠른 수정을 제공한다(지금 서버는 이 기능을 알리지 않는다). 완료 기준: 기존 실행 의미를 바꾸지 않고 경고와 빠른 수정이 LSP에서 동작한다.
- **M1 매개변수 규칙**: `inout`(문맥적 단어)과 고전 `consume` 문법, 4절의 검사 규칙을 추가하되 아직 참조 의미로 실행한다. 완료 기준: 새 문법과 4절 검사가 세 엔진 앞단에서 일관되게 동작한다.
- **M2 자동 이전과 전환 경고**: `qxide fix`(가칭)를 만들고 전환 경고로 저장소 예제와 테스트를 옮긴다. 완료 기준: 예제와 테스트가 전환 경고 없이 통과한다.
- **M3 새 의미 실행**: 새 의미 선택 스위치와 세 엔진의 값 의미 실행을 구현한다(처음엔 단순 복사로 정확성을 먼저 맞춘다). 완료 기준: 세 엔진 동등성·스텝 동등성 테스트와 wasm 동작을 통과한다.
- **M4 명시적 공유 타입**: `Shared<T>`(가칭) 명시적 공유 타입을 도입한다. 완료 기준: 명시적 공유 타입이 세 엔진과 wasm에서 동일하게 동작한다.
- **M5 런타임 표현 교체**: 고유 소유 값에서 `Rc`/`RefCell`을 제거하고 `repr(C)` 배열과 JIT 인라인 접근을 적용한다. 완료 기준: 공통 테스트 기준을 통과하고 `bench/compare` 재측정으로 7절 가설을 확인한다.
- **M6 기본값 전환과 옛 의미 제거**: 6절 일정에 따라 새 의미를 기본값으로 전환하고 옛 의미를 제거한다. 완료 기준: 옛 의미가 제거되고 모든 테스트와 예제가 새 의미로 통과한다.

## 9. 대안

- **(A) 지금의 Java식 참조 의미 유지 + 최적화만**: 구현과 학습이 쉽지만, 별칭 때문에 Rust 대비 95% 성능 목표가 어렵다는 가설이다.
- **(B) Rust식 빌림 검사와 수명 표기 노출**: 성능은 좋지만 입문이 어렵다.
- **(C) Swift식 값 의미 + 암묵 복사·COW**: 쓰기는 쉽지만 복사 비용이 보이지 않고 참조 카운트가 남는다.
- **(D) 이 문서의 안(Mojo·Hylo식 가변 값 의미론 + 매개변수 전용 빌림)**: 수명 표기 없이 별칭을 막고 큰 값의 복사 비용을 드러낸다.

## 10. 위험

- **조용한 의미 변화**: 원소·필드를 지역 변수로 꺼내 쓰거나 for-each 변수에 쓰는 코드(6절 표)가 오류 없이 다른 동작을 할 수 있다.
- **학습 비용**: `inout`, `consume`, `Shared<T>`(또는 `shared`) 세 단어를 새로 익혀야 한다.
- **큐비트와 고전 값의 비대칭**: 기본 빌림이 큐비트에서는 게이트를 허용하고 고전 값에서는 읽기 전용이므로 혼동이 생길 수 있다.
- **구현 규모**: 세 엔진(`ast`, `ir`, `jit`), JIT, 플레이그라운드(wasm), 언어 서버(LSP)를 함께 바꿔야 한다.
- **이미 공개된 0.8.0 프로그램**: 배열 참조 공유에 기대는 기존 0.8.0 코드가 영향을 받는다.

## 11. 남은 질문

아래 항목은 실험 구현을 위해 임시로 정했다. "바꾸는 비용"은 다른 안으로 바꿀 때 고칠 곳이다.

- **호출 위치의 `inout` 표기**: 임시 결정(사용자 확인 필요). 문서에 권장안이 없어 보수적인 쪽을 골랐다. 호출 위치에도 `step(inout ps[0], 0.1)`처럼 써야 하고, 빠지면 `Q0325`와 빠른 수정이 나온다. 바꾸는 비용: 작다. `values.rs`의 `call_args`에서 표기 검사를 빼고 `parser::call_args`의 표기 해석을 지우면 된다. 이미 쓴 `inout` 표기는 그때 경고로 돌리면 된다.
- **`this`를 고치는 메서드 표기**: 임시 결정(사용자 확인 필요). 3절 예시대로 반환 타입 앞에 `inout`을 쓴다(`inout void bump() { ... }`). 바꾸는 비용: 작다. 문법은 `parser::inout_word` 호출 한 곳(구조체·열거형 멤버)이고, 검사기는 `this` 매개변수의 `inout` 여부만 본다. 인터페이스 메서드를 `inout` 메서드로 구현하는 것은 아직 막았다(`Q0325`).
- **큰 값의 복사 방식과 기준**: 임시 결정(사용자 확인 필요). 이 문서의 제안대로 큰 값은 마지막 사용에서 이동하고, 그 밖의 곳에서는 명시적 `.copy()`를 요구한다. 기준은 힙 사용 여부다. 숫자, `boolean`, 그런 값만 가진 구조체·열거형, `Shared<T>` 핸들은 암묵적으로 복사하고, `String`을 포함한 나머지는 큰 값이다. `String`, `Json`, 바뀌지 않는 열거형의 `.copy()`는 값을 공유한다(바뀌지 않으므로 복사와 구별되지 않는다). 바꾸는 비용: 기준은 `values::Decls::implicit_copy` 한 함수다. 예를 들어 `String`을 작은 값으로 돌리는 것은 한 줄이다. Swift식 암묵 복사로 바꾸려면 `Q0321`/`Q0322`를 끄고 `values::lower`가 모든 보관 위치에 복사를 넣게 하면 되므로 중간 정도다.
- **공유 타입 이름**: 임시 결정(사용자 확인 필요). 내장 제네릭 구조체 `Shared<T>`(필드 `value` 하나)로 정했다. 프로그램이 `Shared`를 직접 선언하면 그쪽이 우선하고 보통 구조체로 다룬다. 바꾸는 비용: 이름만 바꾸는 것은 작다(`values::SHARED`, `stdlib::SHARED_PRELUDE`). 문맥적 단어 `shared`로 바꾸려면 파서와 검사기 작업이 들어 중간 정도다.
- **지역 범위 `inout` 바인딩**: 임시 결정(사용자 확인 필요). 보수적으로 허용하지 않는다. 반복문 안에서 원소를 고치려면 `ps[i].x += ...`처럼 직접 쓴다. 바꾸는 비용: 중간이다. 파서 한 곳, 규칙 한 곳(새 `Kind`), 낮추기 한 곳이 필요하다.
- **for-each 변수의 의미**: 임시 결정(사용자 확인 필요). 읽기 전용 빌림으로 정했다. 변수에 쓰면 `Q0320`이 나므로 조용한 의미 변화가 없다. 원소를 보관하려면 큰 값은 `.copy()`가 필요하다. 바꾸는 비용: 작다. 규칙은 `values.rs`의 `Kind::ForEach` 한 곳이고, 복사본으로 바꾸면 낮추기에서 복사를 넣으면 된다. `for inout x in xs`를 추가하는 것은 중간 정도다.
- **배열 원소 추가 API**: 임시 결정(사용자 확인 필요). 이번에는 추가하지 않았다. 배열 길이는 지금처럼 고정이고, 늘어나는 목록은 `List`를 쓴다. 바꾸는 비용: 새 기능 추가라 기존 결정과 충돌하지 않는다.
- **외부 경계 값 전달**: 임시 결정(사용자 확인 필요). 플래그는 CLI(`run`, `check`, `qasm`, `test`, `bench`, `repl`, `lsp`)에만 있다. `qxide build`와 `qxide app`은 만든 프로그램이 나중에 플래그 없이 실행되므로, 플래그를 켜면 실행을 거부한다. 플레이그라운드(wasm), 번들 실행 파일, 데스크톱 앱 런타임, Rust 연동(`unstable-lang`) API는 플래그도 환경 변수 `QXIDE_EXPERIMENTAL`도 읽지 않으므로 지금 의미 그대로다(환경 변수는 CLI의 `main`만 읽는다). 바꾸는 비용: 번들 형식에 플래그를 기록하면 `build`를 열 수 있다(작음). 앱 명령 경계는 앱 런타임 크레이트까지 바꿔야 해서 중간 정도다.
- **사용 중단 기간의 길이**: 임시 결정(사용자 확인 필요). 기본값 전환(6절 2·3단계)을 구현하지 않았으므로 정하지 않았다. 6절의 최소 두 릴리스 기준을 그대로 둔다.

실험 구현에서 생긴 추가 임시 결정:

- **`inout` 인자를 되돌려 쓰는 방식**: 임시 결정(사용자 확인 필요). 숫자, `boolean`, `String`, 열거형 매개변수와 함수가 통째로 다시 대입하는 매개변수는 낮추기에서 한 필드짜리 구조체(`#RefN`)로 감싸고, 호출 문장 앞에서 감싸고 뒤에서 되써 넣는다. 그래서 `inout` 인자의 인덱스식은 두 번 계산된다(부작용이 있는 인덱스는 결과가 달라질 수 있다). 바꾸는 비용: 엔진이 참조 전달을 직접 지원하면 낮추기의 이 부분만 지우면 된다(M5와 함께 하는 것이 맞다).
- **셀로 바뀌는 `inout` 인자의 제한**: 셀은 문장 앞에서 채우므로 `&&`/`||`의 오른쪽에서는 쓸 수 없고(`Q0325`), `final` 지역 변수 전체는 `inout`으로 넘길 수 없다(`Q0325`). 셀 매개변수와 같은 이름의 지역 변수·반복 변수·`match` 바인딩은 그 블록 안에서 보통 변수로 다룬다. 바꾸는 비용: 엔진이 참조 전달을 지원하면(M5) 모두 없어진다.
- **빠른 수정이 없는 오류**: `Q0323`(겹치는 인자), `Q0326`(복사할 수 없는 타입), for-each 변수·`match` 바인딩에 쓰는 `Q0320`, 변수·필드·원소가 아닌 `inout` 인자의 `Q0325`, `.copy()`로 복사할 수 없는 값의 `Q0322`에는 도움말만 있고 빠른 수정이 없다. 고치는 방법이 여러 가지라 하나를 고르기 어렵기 때문이다. 나머지 오류의 빠른 수정은 `values_tests.rs`의 `every_offered_fix_removes_its_error`가 적용해 보고 오류가 사라지는지 확인한다.
- **인터페이스 메서드의 `inout` 매개변수**: 임시 결정(사용자 확인 필요). 아직 막았다(`Q0325`). 동적 호출이 되돌려 쓰기를 모르기 때문이다.
- **전환 경고 `Q0803`**: 임시 결정(사용자 확인 필요). 플래그를 켰을 때만, 원소나 필드에서 복사한 작은 구조체를 처음 바꾸는 곳에서 경고한다(4절 `M-별칭쓰기`). 플래그를 끈 기존 프로그램에는 경고하지 않는다(6절 1단계는 구현하지 않았다).

## 12. 실험 구현 (2026-11-24)

켜는 방법: `qxide run --experimental value-semantics a.qx` 또는 환경 변수 `QXIDE_EXPERIMENTAL=value-semantics`. 언어 서버(`qxide lsp`)는 환경 변수로 켜며, 켜면 `codeActionProvider`를 알리고 빠른 수정을 준다. 끄면 서버 기능 목록도 그대로다.

구조는 다음과 같다. 문법은 `src/lang/parser.rs`의 `inout_word`와 `call_args` 두 곳에만 있고, 규칙은 `src/lang/values.rs`에만 있다. 검사기(`check.rs`)는 플래그가 켜졌을 때 식과 변수의 타입을 기록하고, `.copy()`의 타입을 정하고, 고전 값의 `consume`에 `Q0221`을 내지 않는 일만 한다. 큐비트 규칙(`Q0301`~`Q0315`)은 손대지 않았고, 플래그를 켜도 오류 카탈로그의 큐비트 예제가 같은 결과를 낸다(`values_tests.rs`).

실행은 엔진을 고치지 않고 단형화가 끝난 프로그램을 `src/lang/values/lower.rs`가 보통 프로그램으로 바꿔서 한다.

- `.copy()`는 타입마다 생성한 복사 함수(`#copyN`) 호출이 된다. 구조체는 필드를, 배열·`List`는 원소를, `Map`은 `keys()`와 `values()`로 항목을 차례로 복사한다.
- 필드나 원소에서 읽어 보관하는 작은 구조체는 같은 복사 함수로 복사한다.
- 엔진이 값으로 넘기는 `inout` 매개변수는 위의 `#RefN` 셀로 바꾼다.
- `inout` 표기와 고전 값의 `consume`은 지운다. 디버그 빌드는 낮춘 프로그램이 플래그 없이 검사를 통과하는지 확인한다.

엔진은 지금처럼 공유 참조로 실행하지만 결과는 값 의미론과 같다. 규칙이 다음을 보장하기 때문이다. 큰 값이 두 번째 이름을 얻는 길은 이동(원래 변수는 쓸 수 없게 된다)과 명시적 `.copy()`뿐이다. 빌린 매개변수는 바뀌지 않는다. 한 호출의 `inout` 인자는 서로 겹치지 않는다. 작은 구조체는 낮추기가 복사한다. 공유가 남는 곳은 `Shared<T>`가 공유하는 값뿐이다. 세 엔진이 같은 낮춘 프로그램을 받으므로 결과와 스텝 수가 같다. `ir/tests.rs`의 `value_semantics_agrees_at_every_step_limit`이 모든 스텝 한도에서 이를 확인한다.

이 방식은 정확성을 먼저 맞추는 단계(M3의 "단순 복사")이고 빠르게 하려는 것이 아니다. 참조 카운팅과 헬퍼 호출은 그대로 남는다. 복사 함수와 셀은 스텝과 할당을 더 쓴다. 성능은 `docs/perf/RUST_COMPARISON.md`의 "Measured changes"에 기록했다. 플래그를 켠 `bench/compare/qx-values`는 끈 쪽과 같거나 느렸다(`69ad055`, JIT 기준 Rust 대비 `nbody` 0.26% 대 0.39%, `binarytrees` 13.83% 대 13.44%, `matmul` 0.30% 대 0.30%, `strings` 5.56% 대 5.72%, 다른 작업이 도는 중 Windows에서 측정). 7절의 가설 H1~H4는 런타임 표현을 바꾸는 M5에서만 검증할 수 있고, M5는 아직 하지 않았다.
