# 자동 역연산(Automatic Uncomputation) 설계 검토

> **상태**: 설계 검토 문서(미구현) — 구현 착수 전 메인테이너 승인 필요

## 1. 배경 및 목표

현재 `qxide` Rust 크레이트는 다음 API 모델을 기반으로 한다.

- `Qubit`: `Clone`이 구현되지 않은(non-Clone) 소유권 핸들
- 게이트 연산: `h`, `x`, `z`, `cx`, `s`, `t`, `rx`/`ry`/`rz(θ)` 등이 `&mut Qubit`을 인자로 받음
- 측정 및 제어 흐름: `measure`는 `Qubit`을 소비(consume)하며, `if_one`/`if_zero` 분기와 `reset`을 지원함
- 슬롯 관리: 측정으로 해제된 큐비트 슬롯은 이후 할당에서 재사용됨

양자 연산에서 중간 값을 저장한 임시(보조, ancilla) 큐비트는 데이터 큐비트와 얽힌(entangled) 쓰레기(garbage) 상태를 남길 수 있다. 이러한 보조 큐비트를 단순히 폐기(discard)하는 것은 부분 대각합(partial trace)에 해당하며, 데이터 상태의 결어긋남(decoherence)을 일으켜 양자 간섭(interference)을 파괴한다. 따라서 보조 큐비트를 안전하게 `drop`하거나 슬롯을 재사용하려면, 계산에 적용했던 연산의 역연산(inverse)을 적용해 보조 큐비트를 $|0\rangle$ 상태로 되돌리는 **역연산(uncomputation)**이 필요하다.

관련 언어의 접근 방식은 다음과 같다.

- **Silq** (`silq.ethz.ch` 공식 사이트/문서 기준): "안전한 자동 역연산(safe automatic uncomputation)"을 표방한다. `qfree`로 주석된 함수가 자동 역연산을 가능하게 하며, 양자 `if`의 조건은 암묵적으로 역연산되고 양자 `if` 분기 본문은 `mfree`(measurement-free, 측정 없음)여야 한다.
- **Q#**: `within { U } apply { V }` 구문을 제공하며, 공식 문서에 따르면 역연산($U^\dagger$ 적용)이 자동으로 수행된다. 이는 임시 변수를 암묵적으로 폐기하는 방식이 아니라, 프로그래머가 스코프로 켤레화(conjugation)를 구조화하는 방식이다.

본 문서의 목표는 **`qxide`에서 임시 보조 큐비트가 스코프를 벗어날 때 계산 연산의 역연산을 자동으로 적용해 $|0\rangle$으로 되돌릴 수 있는지**, Rust의 `Drop` 기반 접근과 스코프 클로저 기반 접근 중 무엇이 적합한지, 그리고 **측정과의 상호작용 및 실패 처리 정책**을 어떻게 정의할지 검토하는 것이다.

## 2. 설계 제약 조건

1. **소유권과 가변 대여의 충돌**: `qxide`의 게이트는 `&mut Qubit`을 통해 `Circuit`을 변경한다. 스코프를 벗어나는 시점에 역연산 게이트를 회로에 추가하려면 해당 시점에 회로(`&mut Circuit`)에 접근할 수 있어야 한다.
2. **Rust `Drop`의 실행 비보장**: Rust에서 `std::mem::forget`이나 `Rc` 순환 참조는 안전(safe) 코드로 허용된다("leaks are safe"). 따라서 역연산의 정확성이 `Drop` 실행 여부에 의존해서는 안 된다.
3. **패닉 언와인딩(Unwinding) 안전성**: `Drop`은 패닉으로 인한 스택 언와인딩 중에도 호출된다. 언와인딩 중에 회로에 게이트를 방출하는 것은 잘못된 동작이며, `Drop`은 `Error`를 반환할 수도 없고 언와인딩 중 `Drop` 내부에서 다시 패닉이 발생하면 프로세스가 즉시 중단(abort)된다.
4. **역연산 가능성 및 측정 배제**: 모든 계산 연산 $U$가 역연산 $U^\dagger$를 가지려면 계산 단계가 가역적(unitary)이고 측정이 없어야 하며, 보조 큐비트를 사용하는 동안 그 계산 기저(computational basis) 값이 변경되지 않아야 한다.

## 3. 설계 대안 비교

### 대안 1: 순수 `Drop` 가드 (`Ancilla`)

`let anc = c.ancilla();`가 자신에게 적용된 연산을 기록하는 `Ancilla` 가드를 반환하고, `impl Drop for Ancilla`에서 기록된 연산의 역연산을 회로에 추가하는 방식이다.

- **장점**:
  - 별도의 스코프 중첩 없이 일반적인 지역 변수 수명(lexical scope)에 맞춰 사용할 수 있다.
- **단점**:
  - **회로 대여 차단 또는 API 전면 변경**: `Drop::drop(&mut self)`는 가드가 회로 대여를 보유하지 않는 한 `&mut Circuit`에 접근할 수 없다. 대여를 보유하면 가드가 살아 있는 동안 `Circuit`의 다른 모든 사용이 차단된다. 이를 우회하려고 `Rc<RefCell<CircuitInner>>` 기반 공유 소유권을 도입하면 전체 API가 바뀌고 런타임 대여 패닉 위험이 추가된다.
  - **누수 시 역연산 누락**: `std::mem::forget`이나 순환 참조로 `Drop`이 호출되지 않으면 역연산이 실행되지 않는다.
  - **언와인딩 및 오류 보고 한계**: `Drop` 내부에서는 `std::thread::panicking()`을 확인해 언와인딩 중 게이트 방출을 막아야 하며, 실패를 호출자에게 `Result`로 반환할 수 없다.
- **판정**: 주된 역연산 메커니즘으로는 **부적합**하다. 디버그 시점의 누수 탐지 안전망(safety net) 용도로만 수용 가능하다.

### 대안 2: 스코프 클로저 (Q# `within`/`apply` 유사 구조, 권장)

계산(`compute`) 단계와 사용(`use`) 단계를 두 개의 클로저로 분리해 받고, `use` 클로저가 종료된 뒤 `compute`의 역연산을 자동으로 추가하는 방식이다.

```rust
c.with_ancilla(
    |u, anc, inputs| { /* compute: u는 UnitaryCircuit이며 가역 게이트만 제공 */ },
    |c, anc| { /* use: anc는 &Qubit(제어 전용)으로만 제공 */ },
);   // compute의 역연산이 여기서 자동으로 추가됨
```

- **장점**:
  - **컴파일 타임 역량 제한**: `compute` 클로저에 `UnitaryCircuit` 핸들을 전달해 `measure`, `reset`, `if_one`/`if_zero` 호출을 컴파일 타임에 원천 차단한다(취지상 Silq의 `qfree`/`mfree`와 유사하나 일반 Rust 타입으로 강제).
  - **대여 검사기를 통한 제어 전용 사용 강제**: `use` 클로저에서 보조 큐비트는 공유 참조 `&Qubit`으로만 제공된다. 상태를 변경하는 게이트는 `&mut Qubit`을 요구하므로 대여 검사기가 이를 거부하고, 제어(control) 위치만 `&Qubit`을 받도록 제한해 `use` 단계가 보조 큐비트의 계산 기저 값을 바꾸지 않음을 보장한다.
  - **API 호환성 및 확정적 역연산**: `Rc<RefCell<_>>` 전환 없이 기존 `&mut Circuit` 모델을 유지한다. 클로저 종료 시점에 `&mut Circuit`이 확실히 가용하므로 `Drop` 누수에 의존하지 않는다.
- **단점**:
  - 클로저 기반 API이므로 여러 중첩 스코프를 사용할 때 코드 들여쓰기가 깊어질 수 있다.
  - `use` 단계에서 제어 전용으로 쓰기 위한 전용 게이트 API(`cx_ctrl(&Qubit, &mut Qubit)` 등)와 추가 역게이트(`sdg`, `tdg`) 구현이 선행되어야 한다.
- **판정**: Rust 타입 시스템과 대여 검사기의 보장을 가장 잘 활용하므로 **권장 방식**으로 채택한다.

## 4. 권장 접근 방식 및 Rust 수준 보장

대안 2(스코프 클로저 + `UnitaryCircuit` 역량 타입 + `&Qubit` 제어 전용 사용)를 1차 구현 대상으로 권장한다.

### Rust 네이티브 보장 요소

1. **`UnitaryCircuit` 역량 제한 빌더**:
   - 가역 게이트 메서드만 노출하며 `measure`, `reset`, `if_one`/`if_zero`를 제공하지 않는다.
   - `UnitaryCircuit`에 허용되는 모든 게이트는 역연산을 가져야 하며, 이는 타입 구성상 보장된다:
     - 자기 역원(self-inverse): `h`, `x`, `z`, `cx`
     - 위상 게이트 역원: `s` $\leftrightarrow$ `sdg`, `t` $\leftrightarrow$ `tdg` (선행 추가 필요)
     - 회전 게이트 역원: `rx`/`ry`/`rz(θ)` $\rightarrow$ 각도 `-θ`
2. **제어 전용(`&Qubit`) 참조**:
   - `use` 단계에서 보조 큐비트는 `&Qubit`으로만 전달된다.
   - `cx_ctrl(&Qubit, &mut Qubit)` 형태의 제어 전용 게이트만 `&Qubit`을 허용하므로, `use` 단계에서 보조 큐비트를 표적으로 쓰거나 측정·초기화하는 실수가 컴파일 오류로 차단된다.
3. **신규 $|0\rangle$ 슬롯 할당 보장**:
   - `Circuit`이 슬롯 할당을 직접 관리하므로, 보조 큐비트는 반드시 알려진 $|0\rangle$ 상태의 새 슬롯에서 할당된다.
4. **디버그 안전망**:
   - `Drop` 기반 가드는 역연산 실행 주체가 아니라 디버그 시점 누수 감지기(leak detector)로만 유지한다.

### 구현 전제 조건 (기존 API 깨짐 없음)

- `sdg`, `tdg` 게이트 추가
- `&Qubit`을 제어 인자로 받는 게이트(`cx_ctrl(&Qubit, &mut Qubit)` 스타일) 추가
- `UnitaryCircuit` 빌더 및 `with_ancilla` 스코프 API 추가

## 5. 사용 예시

현재 `qxide`에는 `ccx`(Toffoli)가 없으므로 두 큐비트의 AND를 보조 큐비트에 계산하는 구성은 아직 표현할 수 없다. 대신 두 입력 큐비트 `a`, `b`의 패리티(parity)를 보조 큐비트 `anc`에 계산한 뒤, 이를 제어로 사용해 `target`을 반전하고 자동 역연산하는 예시는 다음과 같다.

```rust
// a, b의 패리티를 anc에 계산한 뒤 target을 제어 반전하고 anc를 자동 역연산한다.
c.with_ancilla(
    |u, anc, (a, b)| {
        // compute: UnitaryCircuit에서 가역 게이트만 허용
        u.cx(a, anc);
        u.cx(b, anc);
    },
    |c, anc| {
        // use: anc는 &Qubit(제어 전용)으로만 접근 가능
        c.cx_ctrl(anc, &mut target);
    },
);
// 스코프 종료 시 역연산 cx(b, anc); cx(a, anc); 가 자동 추가된다.
// 이후 anc는 |0⟩ 상태로 복귀하며 해당 슬롯은 재사용된다.
```

## 6. 측정 상호작용 및 설계 한계

### 측정(Measurement)과의 상호작용

- **`compute` 내부 측정**: `UnitaryCircuit`에 `measure` 메서드가 없으므로 구조적으로 불가능하다.
- **`use` 내부에서 보조 큐비트 자체 측정**: 보조 큐비트는 `&Qubit`으로만 전달되고 `measure`는 소유권을 소비하므로 불가능하다.
- **`use` 단계 또는 `compute`와 역연산 사이에서 입력/데이터 큐비트 측정**: 일반적으로 데이터 큐비트를 측정(특히 회전된 기저에서의 측정)하면 $U^\dagger$가 보조 큐비트를 $|0\rangle$로 복원한다는 가정이 깨진다. 따라서 보수적 규칙으로 `compute` 단계가 읽은 데이터 큐비트 역시 `use` 단계에서 `&Qubit`으로만 제공하거나, 스코프 내부에서 해당 큐비트의 측정을 거부한다.
- **`use` 단계의 고전 분기(`if_one`)**: 보조 큐비트를 제어 전용(`&Qubit`)으로만 사용하는 한 허용된다. 반면 `compute` 단계의 분기는 `mfree` 조건을 위반하므로 허용하지 않는다.

### 현재 한계

- `ccx` 등 다중 제어 게이트가 아직 없어 AND 계산과 같은 비클리퍼드(non-Clifford) 보조 큐비트 패턴은 선행 게이트 확장 전까지 간접 분해가 필요하다.
- 데이터 큐비트 측정에 대한 보수적 제한으로 인해, 고전 오라클(classical oracle)처럼 계산 기저 측정이 역연산 유효성을 유지하는 경우까지 일률적으로 제한될 수 있다.

## 7. 실패 처리 정책

1. **컴파일 타임 실패 (우선)**: 잘못된 역량 사용(`compute` 내 `measure`/`reset`/분기 호출, `use` 내 `&mut Qubit` 요구 게이트 적용 등)은 Rust 타입 및 대여 검사 오류로 컴파일 단계에서 차단한다.
2. **런타임 실패 기록 및 보고**: 가드 누수(디버그 안전망) 또는 동적 검사 실패가 발생할 경우 `Drop` 내부에서 패닉을 일으키지 않고 실패 상태를 `Circuit`에 기록한다. 이후 `simulate_with` 또는 `to_qasm` 호출 시 오류(예: 새로운 `SimError` 배리언트)로 반환·보고한다. 패닉 언와인딩 중에는 절대 게이트를 방출하지 않는다.
3. **테스트 검증(선택 사항)**: 상태 벡터 백엔드에서 회로를 실행해 보조 큐비트가 확률 1로 $|0\rangle$에 복귀하는지 검증할 수 있으며, Clifford `compute`에 한해서는 안정자(stabilizer) 백엔드에서도 검증할 수 있다.

## 8. 미결 과제 (Open Questions)

구현 승인 전 다음 항목에 대한 결정이 필요하다.

1. **API 네이밍**: 스코프 진입 메서드 이름을 `with_ancilla`로 할지, Q# 스타일에 맞춰 `within`으로 할지 여부.
2. **다중 보조 큐비트 지원**: 단일 보조 큐비트 외에 `[Qubit; N]` 또는 `QReg` 단위의 다중 보조 큐비트 스코프를 함께 지원할지 여부.
3. **고전 오라클 측정 규칙 완화**: 제어 전용 입력에 대한 계산 기저 측정은 역연산 유효성을 유지하므로, 향후 고전 오라클 사례에 한해 `use` 단계에서의 데이터 큐비트 측정 제한을 완화할지 여부.
